# Python Setup
## 000 — Scope
Define the Python environment procedure for TDS and preserve Project009’s setup summary in the appendix. Proposed baseline: `uv`, Python 3.11 and a repo-local `.venv`, following Project009’s approach.[1]
## 001 — Procedure for this repository
**Status checked 2026-11-08:** `uv 0.12.7` is available. TDS has no `pyproject.toml`, `.python-version`, `uv.lock` or `.venv` yet; `.gitignore` already excludes `.venv/`. The procedure below is proposed and has not been executed.
### 001.a — Enter TDS and verify uv
```zsh
cd /Users/coder/Public/EngineGit/TDS
uv --version
```
On another Mac, install `uv` with `brew install uv` if needed.[1]
### 001.b — Define the environment recipe
Create root `pyproject.toml` with this proposed initial configuration. Runtime dependencies are empty until implementation requires them; `pytest` and `ruff` are development tools.[2]
```toml
[project]
name = "tds"
version = "0.0.0"
requires-python = ">=3.11"
dependencies = []

[dependency-groups]
dev = ["pytest", "ruff"]
```
### 001.c — Create and synchronize the local environment
```zsh
uv python install 3.11
uv python pin 3.11
uv venv --python 3.11 --prompt tds
uv sync --group dev
```
`.python-version` selects Python 3.11; `.venv` holds this machine’s interpreter and packages; `uv.lock` records resolved dependencies. On subsequent checkouts, use `uv sync --locked --group dev` with the committed lockfile.[2]
### 001.d — Verify and use it
```zsh
uv run python -c "import sys; print(sys.executable); print(sys.version)"
uv run pytest --version
uv run ruff --version
```
Verify Python is 3.11 and its executable is inside TDS’s `.venv`. Tool versions confirm installation; they do not establish that tests pass. Record actual execution results here when setup is performed.
Use `uv run python ...` for project commands. In VS Code, use `Python: Select Interpreter` to choose `.venv/bin/python`; manual terminal activation is unnecessary with `uv run`.[1][2]
### 001.e — Keep the recipe portable
Track `pyproject.toml`, `.python-version` and `uv.lock`; keep `.venv`, caches and machine-specific interpreter settings local. Windows and macOS create their own environments from the same recipe.[1][2]
