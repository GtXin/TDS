## 001 — Install procedure
1. Start Codex from the TDS root. Record the installation goal, allowed paths and checks in a task under `mas/tasks/` before execution.[4]
2. Submit this prompt to Codex. The installer normally uses a personal skill directory; explicitly choose the repository destination for this trial.[5]
```text
$skill-installer
Install only python-pro from:
https://github.com/Jeffallan/claude-skills/tree/main/skills/python-pro
Use the installer's --dest mas/skills so the result is
mas/skills/python-pro/SKILL.md. Include all supporting references.
Preserve .agents/skills -> ../mas/skills.
Record the upstream URL, resolved commit, skill version and MIT license
in the installation task; retain the applicable license with the skill.
Preserve upstream instructions and identify any project-specific overrides.
Do not install Python dependencies or change the environment configuration.
Record actual file/discovery checks and update logXW.md.
```
3. From the repository root, verify the installed files and shared path:
```zsh
test -f mas/skills/python-pro/SKILL.md
test -f mas/skills/python-pro/references/type-system.md
test .agents/skills/python-pro -ef mas/skills/python-pro
```
4. In Codex, run `/skills` and confirm `python-pro` appears. If discovery does not refresh, restart Codex from TDS. Codex supports symlinked skill folders and explicit `$skill-name` invocation.[5]

## 003 — Sample use
Use this isolated exercise to evaluate the skill before applying it to the Chan classes in memo009. The example does not change that design.
```text
$python-pro
Create a task record for a Python3.11 OOP trial.
Write trial code/tests only in artifacts/mas/python-pro-trial/.
Implement:
- An immutable PriceBar with a timezone-aware UTC timestamp and finite
  open/high/low/close values. Require low <= open/close <= high.
- A PriceSeries that contains PriceBar objects by composition,
  retains their supplied order and rejects duplicate or decreasing timestamps.
- Type hints and pytest tests for valid data, invalid price bounds,
  nonfinite prices, naive timestamps, duplicates and reversed ordering.
Explain the class responsibilities before coding.
Use the existing uv/pytest/Ruff tools; add no dependencies or configuration.
Run the checks below and record their actual results in the task record.
Keep TDS source classes and design memos unchanged. Update logXW.md.
```
After files are generated, run from the TDS root:
```zsh
uv run --locked pytest artifacts/mas/python-pro-trial/ -q
uv run --locked ruff check artifacts/mas/python-pro-trial/
```
Accept the trial when the requested valid/invalid cases pass, Ruff reports no issues and review confirms clear responsibilities, composition and Python3.11 compatibility. Record the skill commit and task evidence for later comparison. Installation and these checks have not yet been executed.
