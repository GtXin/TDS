## 001 — Install procedure

1. **Open Codex in TDS.** In a terminal, run:

   ```zsh
   cd /Users/coder/Public/EngineGit/TDS
   codex
   ```

2. **Ask Codex to install one skill.** Paste the following into Codex. It includes the task record required by TDS.[4] `--dest mas/skills` selects this repository instead of the installer's usual personal location.[5]

   ```text
   $skill-installer
   Create an installation task under mas/tasks/, then install only:
   https://github.com/Jeffallan/claude-skills/tree/main/skills/python-pro
   Use --dest mas/skills; keep the complete skill and its reference files.
   Resolve main to an exact Git commit and install it with --ref.
   Record the source URL, commit and skill version; retain the MIT license.
   Preserve the upstream instructions and existing .agents/skills link.
   Keep the Python environment and project configuration unchanged.
   Check the installed files, record the result and update logXW.md.
   ```

3. **Check the installed folder.** It should contain `mas/skills/python-pro/SKILL.md` and `references/`. The existing `.agents/skills` link lets Codex read this shared folder.[2]
4. **Check Codex can find it.** Enter `/skills` and look for `python-pro`. If it is missing, restart Codex in TDS and check again.[5]
## 002 — Usage instruction

1. **Select the skill.** Start your Codex request with `$python-pro`.[5]
2. **Describe the job.** State what to build, which design to follow, where files may be written and what must pass.
3. **State the TDS constraints.** Use Python 3.11, uv, pytest and Ruff. Follow approved class definitions; keep algorithm code independent of the API and website.[2][3]
4. **Keep extra tools optional.** The skill also asks for Black, strict mypy and coverage above 90%.[1] These are not part of this trial's required setup; tell Codex to add no dependencies or configuration.
5. **Review the evidence.** Ask for the changed files, checks actually run and any unresolved issues. A skill appearing in `/skills` shows Codex can find it; the coding trial still needs to pass.
## 003 — Sample use
Use a small exercise before changing the Chan classes in memo009.

1. **Paste this request into Codex:**

   ```text
   $python-pro
   Create a task record for a Python 3.11 OOP trial.
   Write code and tests only in artifacts/mas/python-pro-trial/.
   Build two classes:
   - PriceBar: an immutable bar with a timezone-aware UTC timestamp and
     finite OHLC prices. Require low <= open/close <= high.
   - PriceSeries: contains PriceBar objects, preserves their order and
     rejects duplicate or decreasing timestamps.
   Explain each class's responsibility and add type hints.
   Write pytest tests for valid input, invalid price bounds, nonfinite prices,
   naive timestamps, duplicate timestamps and reversed ordering.
   Use the existing uv/pytest/Ruff tools; add no dependencies or configuration.
   Run pytest and Ruff on the trial folder and record their actual results.
   Keep TDS source classes and design memos unchanged. Update logXW.md.
   ```

2. **Check the result.** Codex should run these commands from TDS; you can also run them in a terminal:

   ```zsh
   uv run --locked pytest artifacts/mas/python-pro-trial/ -q
   uv run --locked ruff check artifacts/mas/python-pro-trial/
   ```

3. **Decide whether the trial succeeded.** The requested tests should pass, Ruff should report no issues and each class should have a clear responsibility. Save the result and skill commit in the task record for comparison later. These checks are still pending.
