## 001 — Definition (What)

**包含 （辅助定义）**：相邻两根K线中，若其中一根的最高价不低于另一根的最高价，且最低价不高于另一根的最低价，则两根K线存在包含关系。既可以前一根包含后一根，也可以后一根包含前一根，边界相等也算。

**向上、向下趋势**（此处指K线区间的局部方向）：按时间先后，若后一根K线的最高价和最低价均严格高于前一根，则称为向上；若均严格低于前一根，则称为向下。若两根存在包含关系，包括边界相等，则不能仅凭这两根K线确定方向。

**MergedKline（合并K线）**：用于结构分析的价格区间单元，代表一根原始K线，或由逐次包含关系归并形成的多根连续原始K线，以一个最高点和一个最低点表示其价格区间，并记录其在原始K线序列中的起止位置，以便追溯全部原始成员。合并方向向上时，高、低点分别取成员高、低点的最大值，形成偏上的“乐观”区间表示；方向向下时，分别取最小值，形成偏下的“悲观”区间表示。

**MergedKlineSeries（合并K线序列）**：由同一原始K线序列按顺序处理包含关系后形成、按原始来源先后排列的非空MergedKline序列。各单元的原始来源范围连续、互不重叠，并覆盖本次完整输入；处理完成后，任意相邻两个单元均不存在包含关系，包括边界相等的包含。非相邻单元仍可能包含。

**初始化小注（可选）**

起始时若相邻K线存在包含关系，且尚无方向依据，可考虑以下初始化选项，暂不选定默认方案：

1. 默认向上。
2. 默认向下。
3. 同时按向上、向下两种方向评估。输出向上，若差距太大给warning
4. 取包含区间的外边界：高点取较大值，低点取较小值，即“上大下小”。

## 002 — Algorithm (How)

### 002.a — Algorithm Tree

本树从001的定义出发，按原始K线顺序形成合并单元。原始输入为不可变的 `KlineTSeries`；合并工作单元独立保存高低点和来源位置，不修改原始K线。以下为算法讨论稿，相关特征类尚未实现，初始化默认方案尚未选定。

**变量与位置**

| 变量 | 含义与约定 |
|---|---|
| `raw` | 本次计算使用的原始 `KlineTSeries` 对象；结果保留对这个确切快照的引用。 |
| `N` | 原始K线数量，即 `len(raw)`；序列校验通过后至少为1。 |
| `i` | 下一根待处理原始K线的零基下标；读取 `raw.klines[i]`。首根初始化后为1，等于N时输入耗尽。 |
| `n` | 当前合并工作单元的顺序编号，从1开始；与原始下标i分开，不自动等于特征ID。 |
| `R` | 已保存的不可变MergedKline记录，按来源顺序排列；不包含尚在处理的当前单元。 |
| `Kₙ` | 当前末端合并工作单元，可代表一根或多根原始K线；不能理解为 `raw[n]`。 |
| `Kₙ₊₁` | 本轮由 `raw[i]` 建立的临时候选，尚未成为独立的第n＋1个合并单元；若被吸收，下轮仍可使用这个候选编号。 |
| `Hₙ、Lₙ` | 当前Kₙ的高点、低点。 |
| `Hₙ₊₁、Lₙ₊₁` | 本轮候选Kₙ₊₁的高点、低点，取自 `raw[i]`。 |
| `direction` | 当前Kₙ的合并方向：向上、向下或未定；不由候选的阴阳线决定。 |
| `source_start` | 当前单元第一个原始成员在raw中的零基下标，包含此位置。 |
| `source_stop` | 当前单元最后一个原始成员下标＋1，不包含此位置；完整来源为 `raw.klines[source_start:source_stop]`。 |
| `id` | 保存记录时分配的、本次结果内唯一的整数ID；不把原始下标i当作ID。 |

在每次进入2.2时，当前单元的 `source_stop=i`，表示原始下标i尚未处理；在正常单路径中，`R`已有n−1个单元，Kₙ是尚未保存的第n个单元。每轮先用本轮i完成计算和来源范围更新，再推进下标。

**判断树：判断结果 → 行动 → 下一步**

```text
2.1 原始序列检查
├── 2.1.a raw校验失败 → 报错，停止
└── 2.1.b raw校验通过
    → N=len(raw)；结果R为空；n=1；
      用raw[0]建立K₁，方向未定，来源范围[0,1)；i=1
    └── 2.2 下一根原始K线检查
        ├── 2.2.a i=N，数据耗尽
        │   → 保存Kₙ；检查来源范围连续、完整且不重叠；
        │     检查相邻合并单元无包含；
        │     返回引用原始raw的MergedKlineSeries
        └── 2.2.b i<N，仍有原始K线
            → 用raw[i]建立候选Kₙ₊₁，来源范围[i,i+1)
            └── 2.3 Kₙ与候选Kₙ₊₁的包含关系检查
                ├── 2.3.a 不存在包含
                │   └── 2.4 高低点方向检查
                │       ├── 2.4.a Hₙ₊₁>Hₙ 且 Lₙ₊₁>Lₙ
                │       │   → 保存旧Kₙ；候选另立为当前单元，方向向上；
                │       │     保留候选来源范围[i,i+1)；
                │       │     n=n+1，i=i+1；回2.2
                │       └── 2.4.b Hₙ₊₁<Hₙ 且 Lₙ₊₁<Lₙ
                │           → 保存旧Kₙ；候选另立为当前单元，方向向下；
                │             保留候选来源范围[i,i+1)；
                │             n=n+1，i=i+1；回2.2
                └── 2.3.b 存在包含，包括完全相等
                    └── 2.5 当前Kₙ的合并方向检查
                        ├── 2.5.a 向上
                        │   → Kₙ.high=max(Hₙ,Hₙ₊₁)；
                        │     Kₙ.low=max(Lₙ,Lₙ₊₁)；
                        │     source_start不变，source_stop=i+1；
                        │     候选被吸收，n不变；i=i+1，回2.2
                        ├── 2.5.b 向下
                        │   → Kₙ.high=min(Hₙ,Hₙ₊₁)；
                        │     Kₙ.low=min(Lₙ,Lₙ₊₁)；
                        │     source_start不变，source_stop=i+1；
                        │     候选被吸收，n不变；i=i+1，回2.2
                        └── 2.5.c 方向未定
                            └── 2.6 初始化选项［默认方案尚未选定］
                                ├── 2.6.a 默认向上
                                │   → 设置Kₙ方向向上；n、i均不变，转2.5.a
                                ├── 2.6.b 默认向下
                                │   → 设置Kₙ方向向下；n、i均不变，转2.5.b
                                ├── 2.6.c 同时评估
                                │   → 复制当前工作状态，建立两条独立路径；
                                │     向上路径：设置Kₙ.direction=向上，转2.5.a；
                                │     向下路径：设置Kₙ.direction=向下，转2.5.b；
                                │     分路时n、i均不变，各路合并后按2.2继续；
                                │     两路均在2.2.a返回后，输出向上初始化路径的结果；
                                │     差距过大时warning，差距度量与阈值待定
                                └── 2.6.d 上大下小
                                    → Kₙ.high=max(Hₙ,Hₙ₊₁)；
                                      Kₙ.low=min(Lₙ,Lₙ₊₁)；
                                      Kₙ.direction=未定（None）；
                                      source_start不变，source_stop=i+1；
                                      候选被吸收，n不变；i=i+1，回2.2
```

2.6按明确指定的初始化选项进入对应分支；未指定时保留待定，不自动采用2.6.a。

2.6.c的两路分别保留R、n、i、Kₙ及候选的独立工作状态，共享同一不可变raw；后续方向仍按各路的2.4变化。2.6.d只取外边界，不能由此推出向上或向下；方向未定时若再次包含，继续按已选定的2.6.d处理，遇到非包含则转2.4为新单元定向，首段保留未定方向。

2.3.b包含前包后、后包前和完全相同。2.4只有向上、向下两支，是因为有效价格区间在排除包含后，高低点必然共同严格升高或共同严格降低。

**递增与保存规则**

| 情况 | 原始下标i | 合并编号n | 来源范围与动作 |
|---|---|---|---|
| 首根初始化 | 设为1 | 设为1 | K₁来自 `raw[0]`，范围 `[0,1)`。 |
| 候选另立单元：2.4.a／2.4.b | 增加1 | 增加1 | 先保存旧Kₙ，再把来源为 `[i,i+1)` 的候选作为新末端；推进后重新记作Kₙ。 |
| 候选被吸收：2.5.a／2.5.b | 增加1 | 不变 | 先保持source_start、设置 `source_stop=i+1`，再推进i；不新增独立单元。 |
| 选定初始方向：2.6.a／2.6.b | 不变 | 不变 | 只设置方向，仍处理同一根 `raw[i]`，转入2.5完成合并后才推进。 |
| 双路初始化：2.6.c | 分路时不变；各路在2.5合并后增加1 | 分路与合并时均不变 | 两路各自设置初始方向并处理同一根raw[i]，独立更新来源范围和结果；后续按各路正常规则推进。 |
| 外边界合并：2.6.d | 增加1 | 不变 | 高点取max、低点取min，方向仍未定；先保持source_start、设置source_stop=i+1，再推进i。 |
| 未指定初始化选项 | 不变 | 不变 | 保留raw、R、n、i、Kₙ及当前候选，等待明确选项，不跳过候选。 |
| 输入耗尽：2.2.a | 不变，保持N | 不变 | 保存最后单元后，R共有n个单元；不再读取 `raw[N]`。 |

“保存Kₙ”指为当前工作单元分配本次结果内唯一的整数ID，将高低点、方向和来源起止位置复制为不可变MergedKline记录，追加到R。输入耗尽或保存记录不自动表示已经确认；状态、确认时间与完整决策trace另行定义。

完整结果的来源范围应从0开始，相邻记录的前一source_stop等于后一source_start，最后source_stop等于N。未来映射ChanTable时，成员ID覆盖 `[source_start,source_stop)` 内全部原始行，起始标记在source_start，结束标记在 `source_stop−1`，方向按已有设计只标在起始行。该映射需对应同一原始快照及行序；现有ChanTable仍只接受特征列为NA，此处不表示特征投影已经实现。

### 002.b — Detailed Implementation logic and Numerical Examples

本节展开002.a的处理逻辑；数值均为教学构造，不代表行情。价格区间统一写作 `[low,high]`，两端都包含；原始来源范围写作 `[source_start,source_stop)`，右端不包含。图中原始K线的开收盘仅用于画蜡烛，算法只比较高低点；合并结果只画价格区间，不另造开收盘。

#### 处理逻辑

1. **准备输入与工作状态（2.1）。** 校验原始 `KlineTSeries`，保留对同一不可变快照的引用。用 `raw[0]` 建立K₁，方向为None、来源为 `[0,1)`；设 `n=1、i=1`，已保存结果R为空。合并过程只修改独立工作单元，不修改原始OHLCV。
2. **每轮比较当前合并单元与下一根原始K线（2.2–2.3）。** 候选Kₙ₊₁始终来自 `raw[i]`。包含条件为 `Hₙ≥Hₙ₊₁ 且 Lₙ≤Lₙ₊₁`，或 `Hₙ₊₁≥Hₙ 且 Lₙ₊₁≤Lₙ`。判断对象是已经更新过的Kₙ，不能换成上一根原始K线 `raw[i−1]`。
3. **不包含时结束旧单元，建立新单元（2.4）。** 候选高低点都严格较高，则新单元向上；都严格较低，则向下。先把旧Kₙ连同其方向、来源范围保存，再提升候选为新的当前单元；来源是 `[i,i+1)`，随后n、i各增加1。新方向只赋给新单元，不回填旧单元的None。
4. **包含且方向已知时吸收候选（2.5.a／2.5.b）。** 向上取高点max、低点max；向下取高点min、低点min。前包后、后包前采用同一方向规则，谁的区间较大不决定方向。保持source_start，用本轮旧i设置 `source_stop=i+1`，再将i增加1；n不变，候选不另占一个合并编号。
5. **包含且方向未定时执行指定的初始化选项（2.6）。** 向上或向下选项先赋方向，再处理同一候选；双路选项复制完整工作状态，各路分别合并、推进和保存；外边界选项取高max、低min，方向保留None后继续。未指定选项时保留待定状态，不能跳过候选，也不能宣称已得到完整结果。
6. **输入耗尽时保存末单元（2.2.a）。** 当 `i=N`，不再读取 `raw[N]`，保存仍在工作的Kₙ。最终来源范围应连续、不重叠，并恰好覆盖 `[0,N)`，还须检查相邻合并单元不存在包含关系；EOF只结束这份输入的计算，不代表理论上的确认。

#### 主例：从10根原始K线形成3个合并单元

本例的 `raw[0]=[1,3]` 与 `raw[1]=[2,4]` 不包含，直接建立向上新单元，因此不需要选择初始化方案。表中i是本轮读入的原始下标；“下一轮(i,n)”是处理完成后的状态。K₁、K₂、K₃只表示顺序位置，不是已分配的特征ID。

| 本轮i | 比较前Kₙ | 候选区间 | 分支与动作 | 处理后Kₙ及方向 | 来源范围 | 下一轮(i,n) |
|---|---|---|---|---|---|---|
| 初始化0 | — | `[1,3]` | 2.1.b：建立首根 | K₁ `[1,3]`，None | `[0,1)` | (1,1) |
| 1 | K₁ `[1,3]` | `[2,4]` | 2.4.a：保存K₁，另立 | K₂ `[2,4]`，向上 | `[1,2)` | (2,2) |
| 2 | K₂ `[2,4]` | `[1,5]` | 2.5.a：后包前，吸收 | K₂ `[2,5]`，向上 | `[1,3)` | (3,2) |
| 3 | K₂ `[2,5]` | `[3,4]` | 2.5.a：前包后，吸收 | K₂ `[3,5]`，向上 | `[1,4)` | (4,2) |
| 4 | K₂ `[3,5]` | `[2,6]` | 2.5.a：后包前，吸收 | K₂ `[3,6]`，向上 | `[1,5)` | (5,2) |
| 5 | K₂ `[3,6]` | `[1,5]` | 2.4.b：保存K₂，另立 | K₃ `[1,5]`，向下 | `[5,6)` | (6,3) |
| 6 | K₃ `[1,5]` | `[2,4]` | 2.5.b：前包后，吸收 | K₃ `[1,4]`，向下 | `[5,7)` | (7,3) |
| 7 | K₃ `[1,4]` | `[0,6]` | 2.5.b：后包前，吸收 | K₃ `[0,4]`，向下 | `[5,8)` | (8,3) |
| 8 | K₃ `[0,4]` | `[0,4]` | 2.5.b：完全相等，吸收 | K₃ `[0,4]`，向下 | `[5,9)` | (9,3) |
| 9 | K₃ `[0,4]` | `[0,5]` | 2.5.b：低点相等，吸收 | K₃ `[0,4]`，向下 | `[5,10)` | (10,3) |

例如i=2时，候选 `[1,5]` 包含当前 `[2,4]`，但当前方向已经向上，所以结果为 `[max(2,1),max(4,5)]=[2,5]`。i=7时同样是后包前，当前方向却向下，结果为 `[min(1,0),min(4,6)]=[0,4]`。包含的前后次序不改变既有合并方向。

图中上半是原始蜡烛，下半是合并区间；两图共用原始下标轴。合并区间的横向跨度表示它覆盖哪些原始成员，蓝、橙、灰分别表示向上、向下、未定；原始蜡烛的红绿只表示构造的开收盘关系。

此时 `i=N=10`，R中已有K₁、K₂，再按2.2.a保存末单元K₃，得到：

| 顺序单元 | 最终价格区间 | 方向 | 原始来源范围 | 全部原始成员 |
|---|---|---|---|---|
| K₁ | `[1,3]` | None | `[0,1)` | raw[0] |
| K₂ | `[3,6]` | 向上 | `[1,5)` | raw[1]、raw[2]、raw[3]、raw[4] |
| K₃ | `[0,4]` | 向下 | `[5,10)` | raw[5]至raw[9]，共5根 |

三个来源范围连续覆盖全部10根原始K线。K₂的结果低点为3，并不要求每根原始成员的最低价都不低于3；合并区间是方向性表示，完整原始成员仍由来源范围保留。

#### 顺序反例：下一根要与合并结果比较

另取一段独立输入：`raw[0]=[0,2]、raw[1]=[1,4]、raw[2]=[2,3]、raw[3]=[0,3.5]`。

1. 前两根不包含，建立向上的K₂ `[1,4]`，来源 `[1,2)`。
2. raw[2]被K₂包含，向上处理后K₂为 `[2,4]`，来源扩展到 `[1,3)`。
3. raw[3]虽然包含最后一根原始K线raw[2]的 `[2,3]`，但它与当前K₂ `[2,4]` 不包含：高点3.5小于4，低点0小于2。因此必须保存K₂，另立向下的K₃ `[0,3.5]`，来源 `[3,4)`。

这里raw[1]与raw[2]包含、raw[2]与raw[3]也包含，raw[1]与raw[3]却不包含。不能凭相邻原始K线的包含链一次圈定整组；每次吸收后都要用新的合并区间与下一根比较。

#### 起始包含：同一输入的四种初始化

另取四根原始K线：`[2,5] → [3,4] → [2.5,4.5] → [3,6]`。首两根包含，且首根没有既有方向；下面分别演示001列出的选项，不选定项目默认值。

1. **2.6.a，向上初始化。** 首两根合为 `[max(2,3),max(5,4)]=[3,5]`，方向向上、来源 `[0,2)`。raw[2]的 `[2.5,4.5]` 比它的高低点都低，另立向下单元；raw[3]再另立向上单元。向上初始化不表示整条路径以后只能向上。
2. **2.6.b，向下初始化。** 首两根合为 `[min(2,3),min(5,4)]=[2,4]`，方向向下、来源 `[0,2)`。raw[2]相对它的高低点都高，另立向上单元；raw[3]再另立向上单元。
3. **2.6.c，同时评估。** 在尚未吸收raw[1]时复制工作状态，分别赋向上、向下方向，得到前两项各自的完整结果；各路独立维护i、n、R与来源范围。主输出取向上初始化路径，向下路径用于比较；差距度量和warning阈值仍待定义，本例不据此触发或取消warning。
4. **2.6.d，取外边界。** 首两根合为 `[min(2,3),max(5,4)]=[2,5]`，方向仍为None、来源 `[0,2)`。raw[2]继续被它包含，仍为 `[2,5]`，来源扩展到 `[0,3)`；raw[3]才与它形成非包含的严格向上关系，另立向上单元。首段仍保留None，不回填方向。

各路径在EOF保存末单元后，完整结果如下。双路选项保留前两条路径，主输出等于向上初始化路径；来源与ID上下文按路径分别保存。

| 向上初始化 | K₁ | `[3,5]` | 向上 | `[0,2)` |
| 向上初始化 | K₂ | `[2.5,4.5]` | 向下 | `[2,3)` |
| 向上初始化 | K₃ | `[3,6]` | 向上 | `[3,4)` |
| 向下初始化 | K₁ | `[2,4]` | 向下 | `[0,2)` |
| 向下初始化 | K₂ | `[2.5,4.5]` | 向上 | `[2,3)` |

| 外边界初始化 | K₁ | `[2,5]` | None | `[0,3)` |
| 外边界初始化 | K₂ | `[3,6]` | 向上 | `[3,4)` |

### 002.c — Helper Functions

建议保留以下6个辅助函数，供002.a的主循环调用。这里定义的是接口与约束，尚未实现；工作单元只保存高低点、方向和原始来源范围，不修改原始Kline。原始输入校验直接复用已有的 `raw.validate()`。区间参数均须高低点有限且有序；主循环保证调用方属于同一路径和同一raw上下文，函数不凭数字下标猜测来源快照。

**定位约定：** 合并K线放在原始来源组的第一根，即 `source_start`；显示时间取 `raw[source_start].timestamp`。吸收后续成员时这个位置不变，完整来源仍是 `[source_start,source_stop)`，最后成员位于 `source_stop−1`。显示位置不代表高低点分别发生的位置，也不表示在首根时已经知道后续成员或已经确认；002.b图中的居中竖线只用于示意高低区间。

#### 建立工作单元：work_from_raw

**接口：** `work_from_raw(raw, i, direction=None)`。

输入同一原始快照raw、零基原始下标i及方向。要求 `0≤i<len(raw)`，方向只能是向上、向下或None；不接受Python序列允许的负下标。返回新的独立工作单元：高低点取自 `raw[i]`，来源为 `[i,i+1)`，方向保留输入值。

用于2.1.b建立首根，以及2.2.b建立候选。首根与尚未提升的候选都传None；新单元的方向由2.4另行赋值。函数不分配ID，不推进i或n。

#### 判断包含：has_inclusion

**接口：** `has_inclusion(a, b)`。

输入两个有效价格区间，要求高低点有限且 `low≤high`；输出布尔值。当 `a.high≥b.high 且 a.low≤b.low`，或 `b.high≥a.high 且 b.low≤a.low` 时返回True，否则返回False。等高、等低、完全相等及一字区间均按同一条件处理，交换a、b不改变结果。

用于2.3。它只判断这两个区间的几何关系，不判断方向，也不证明多根可以整组归并；主循环保证比较对象是当前Kₙ与来源紧接其后的候选Kₙ₊₁。

#### 判断非包含方向：direction_between

**接口：** `direction_between(a, b)`；a在前、b在后。

输入有效区间，必须先满足 `has_inclusion(a,b)=False`。若b的高低点都严格高于a，返回向上；若都严格低于a，返回向下。若存在包含，包括边界相等，必须报错，不能推测方向或套用上一方向。

用于2.4，返回值赋给新单元。函数不回填旧单元的方向，也不把K线实体的阴阳当作区间方向。

#### 按已知方向合并：merge_included

**接口：** `merge_included(current, candidate)`。

current为Kₙ，candidate为本轮Kₙ₊₁。两者必须属于同一路径、同一raw，存在包含，且 `current.source_stop=candidate.source_start`；候选必须只代表一根原始K线，即 `candidate.source_stop=candidate.source_start+1`。current.direction必须已经是向上或向下；为None时拒绝调用。

返回新的合并工作单元：向上时高低点分别取max；向下时分别取min。方向和source_start保持current的值，source_stop取candidate.source_stop，也就是本轮旧i＋1。输入工作单元保持不变，由主循环用返回值替换当前Kₙ。

用于2.5.a／2.5.b。2.6.a／2.6.b及双路初始化也先给各自current赋方向，再调用本函数；函数不另接一个可覆盖既有方向的参数，不更新i、n或R。

#### 按外边界合并：merge_outer_boundary

**接口：** `merge_outer_boundary(current, candidate)`。

包含、同一raw、连续来源及单根候选的前提与上一函数相同；另外要求调用方已明确选择2.6.d且current.direction为None；函数不自行选择初始化策略。返回新的工作单元：高点取max、低点取min，方向仍为None；source_start保持不变，source_stop取candidate.source_stop。

函数不修改输入、不推导方向、不推进计数器。主循环接收结果后才执行 `i=i+1`，n不变，回2.2。不能用它替代已经向上或向下的正常包含处理。

#### 校验完整结果：validate_merged_result

**接口：** `validate_merged_result(raw, result)`。

输入原始快照及拟定的MergedKlineSeries结果，要求 `result.source_series` 引用同一个raw对象。检查结果非空；每项高低点有限且有序、方向取值有效、ID为本次结果内唯一的整数；来源下标为整数且满足 `0≤source_start<source_stop≤len(raw)`。

再检查首项从0开始、末项到N结束、前项source_stop等于后项source_start，确保完整覆盖、没有空缺或重叠。逐对检查相邻记录，要求 `has_inclusion(result.klines[j],result.klines[j+1])=False`，其中j从0到M−2，M为结果单元数。含等高、等低或完全相等在内的相邻包含都应报错，并指出两个位置及来源范围；M=1时没有相邻对，此项自然通过。非相邻记录不参加这项检查。

只看相邻价格检查，`[1,5] → [3,7] → [2,4]` 可以通过，即使第一根包含第三根；`[1,5] → [3,5]` 则因等高的包含而失败。成功时返回None，失败时报错，不修补来源、不重排结果，也不把待定的部分结果包装成完整结果。

用于2.2.a保存末单元以后；可作为memo009所拟 `MergedKlineSeries.validate()` 的校验核心。它校验结构与来源，不代替逐步规则复算或一般正确性论证；status、confirmed_at及完整trace规则仍需另行定义，不能由EOF自动填成已确认。

#### 与主循环的分工

辅助函数不改原始raw，不读写文件或ChanTable，也不推进i、n或追加R。合并函数只通过返回值扩展source_stop；主循环先接收这个结果，再推进i，避免把同一根候选消费两次。

初始化选项的选择、双路状态复制、给新单元赋方向、分配结果ID、冻结并追加旧单元，以及EOF保存末单元，都留在主循环。冻结时必须复制当前字段，不能把以后还会变化的工作对象直接放入R；实际MergedKline构造仍要衔接memo009中尚未定下规则的状态与确认字段。

双路之间只共享不可变raw和不可变的已保存内容；可变工作单元、候选及结果列表必须独立。暂不定义自动选择初始化、两路差异评分或warning函数，以免在辅助函数中暗设尚未约定的规则。

#### 与002.b对应的小检查

价格区间仍按 `[low,high]` 表示；下列为接口应满足的结果，不表示这些函数已经实现或通过代码测试。

| 调用情形 | 应有结果 |

| `direction_between([1,3],[2,4])` | 向上。 |

### 002.d — Pseudocode

只有遇到方向未定的包含时才执行初始化；单根输入或起始非包含不强行赋初始方向，也不无故分路。以下伪代码对应002.a的主过程，调用002.c的6个辅助函数；不是现有Python接口或可直接执行的实现。`Kₙ`在程序状态中记为current，临时候选Kₙ₊₁记为candidate；n仍是从1开始的合并工作单元编号，i仍是从0开始的下一原始下标。

**输入与输出约定**

- raw是同一个不可变KlineTSeries快照；initialization必须明确为 `UP、DOWN、BOTH、OUTER、UNSET` 之一，分别对应2.6.a–d及尚未选择；UNSET不是向上或向下的默认值。rule_tree_ref标识使用的规则版本。
- 每条路径独立保存 `raw、N、current、R、n、i、initialization、rule_tree_ref`；raw可以共享，current和R的可变部分必须独立。吸收时只推进i，另立时i、n都推进。
- “保存current”是主过程的动作缩写：分配本路径结果内尚未使用的整数ID，复制current的高低点、方向和来源范围为不可变记录，再追加到R；不增加n或i。吸收候选时不分配新ID。不同路径的相同整数ID不表示同一结果记录。
- “组装结果”表示保留同一raw引用、不可变记录及规则配置的逻辑结果。memo009中的status、confirmed_at和完整trace如何落地仍待定义，此处不擅自赋状态、确认时间或补造trace。

#### 建立起始状态

```text
主过程(raw, initialization, rule_tree_ref):
    raw.validate()
    若initialization不在允许的五个值中：报错

    S.raw ← raw                         # 保留原始对象引用
    S.N ← len(raw)
    S.current ← work_from_raw(raw, 0, None)
    S.R ← 空列表
    S.n ← 1
    S.i ← 1
    S.initialization ← initialization
    S.rule_tree_ref ← rule_tree_ref

    返回 推进路径(S)
```

#### 推进一条路径，必要时分为两路

“推进路径”是同一主算法的分段，不是新增的几何辅助函数。双路分开后，各自在未推进的同一i建立候选；重新读取这个位置不等于已经消费了它。

```text
推进路径(S):
    当 S.i < S.N 时重复：
        断言 S.current.source_stop = S.i
        断言 len(S.R) = S.n − 1
        candidate ← work_from_raw(S.raw, S.i, None)

        若 has_inclusion(S.current, candidate) = False：
            new_direction ← direction_between(S.current, candidate)
            保存 S.current 到 S.R
            candidate.direction ← new_direction
            S.current ← candidate
            S.n ← S.n + 1
            S.i ← S.i + 1
            继续下一轮

        # 到这里，current与candidate一定存在包含
        若 S.current.direction = None：
            若 S.initialization = UNSET：
                返回 待定状态(S及candidate的独立状态副本)
                # 保留同一raw、R、n、i和当前候选，不推进，不作为完整序列返回

            若 S.initialization = BOTH：
                U ← 复制S，保留同一raw引用，独立复制可变工作状态
                D ← 复制S，保留同一raw引用，独立复制可变工作状态
                U.initialization ← UP
                D.initialization ← DOWN
                U.current.direction ← 向上
                D.current.direction ← 向下
                # 两路n、i均保持分路前的值，候选尚未吸收
                up_result ← 推进路径(U)
                down_result ← 推进路径(D)
                # 两路都完成各自的EOF检查后，保留两个完整结果
                返回 双路结果：
                    主输出 = up_result
                    比较路径 = down_result
                    原始初始化请求 = BOTH
                    warning评估 = 待定（差距度量和阈值尚未定义）

            若 S.initialization = OUTER：
                S.current ← merge_outer_boundary(S.current, candidate)
                S.i ← S.i + 1           # 合并已先扩展source_stop
                继续下一轮               # n不变，方向仍为None

            若 S.initialization = UP：
                S.current.direction ← 向上
            否则若 S.initialization = DOWN：
                S.current.direction ← 向下
            否则：报错                   # 拒绝遗漏的初始化分支
            # 只设置方向，n、i仍不变；下面吸收同一candidate

        S.current ← merge_included(S.current, candidate)
        S.i ← S.i + 1                   # n不变，source_start不变

    # S.i = S.N：没有raw[N]可读取
    保存 S.current 到 S.R
    断言 len(S.R) = S.n
    result ← 组装逻辑结果：
        source_series = S.raw
        klines = S.R的不可变记录序列
        config = 含本路径initialization的不可变配置
        rule_tree_ref = S.rule_tree_ref
    validate_merged_result(S.raw, result)
    返回 result
```

已知方向的路径始终使用merge_included，只有方向None且明确选OUTER时才取外边界。BOTH的向上初始化路径后续仍可转为向下；比较路径独立保留。warning未评估不能等同于“没有差异”或“不需要warning”，也不能只按相同n比较来源不同的单元。

#### 返回完整结果前的相邻检查

以下是validate_merged_result在来源、价格和ID检查之外必须执行的步骤。M是本路径最终合并单元数量；j是结果数组的零基下标，不是原始下标i。

```text
M ← len(result.klines)
对 j = 0 到 M − 2 逐个检查：
    若 has_inclusion(result.klines[j], result.klines[j+1])：
        报错：相邻合并K线仍有包含，给出j、j+1及各自来源范围
# M=1时没有相邻对，此项检查自然通过
```

检查失败就不返回有效的完整序列；校验函数不偷偷重做合并。非相邻单元不参加这项检查。每个单元的显示位置始终取source_start及其原始时间；完整来源、价格极值位置与确认时间分别保留各自含义。

### B.2 — 开头还没有方向，怎么办？

第一根K线先放入缓冲。后面每加入一根，只比较缓冲里最后两根原始K线：高点和低点都严格升高，方向为上；都严格降低，方向为下；只要不能这样判定，就继续等待。相等边界不能建立方向，也不根据开盘、收盘或阴阳线决定方向。

首次得到方向后，CC用这个方向处理此前全部缓冲成员：向上分别取最高的高点和最高的低点，向下分别取最低的高点和最低的低点，形成首单元。刚刚触发方向的最新K线则单独成为第二单元，随后开始常规追加。

这个次序有实际含义：早期包含链借用了后来才出现的方向。初始化中，程序直接建立上述两个单元，没有再让最新K线与聚合后的首单元重走一次包含判断。如果整个窗口始终没有严格方向，程序保留缓冲，合并输出为空。这些是CC的初始化选择，不能直接当成原文已经完整规定的内容。[8：`_direction()`、`_try_establish()`、`_merge_blob()`]

### B.3 — 已有方向后，怎样判断和处理包含？

判断包含时看完整高低区间，而不是仅看两根K线有没有重叠。旧单元包住新K线，或者新K线包住旧单元，均进入包含分支；上下边界允许相等。

一旦属于包含，就沿用末单元原来的方向，不重新定向。向上时，高点、低点分别取较高者；向下时分别取较低者。新K线加入该单元的来源成员，单元数量不增加。下一根到来时，比较的是这些更新后的高低点。

![已有方向决定包含合并取值](memoWX_015_Chan_mergedkline/cc-merge-values.svg)

图B2：两次独立的教学计算，均以旧区间 `[5,10]` 和新区间 `[6,9]` 为输入；分别假设已有向上、向下方向，说明为何会得到不同结果。[8：`_contains()`、`_append_established()`]

若两者不包含，才由末单元与新K线的高低点确定方向，并给新K线建立新单元。新方向可以延续，也可以反转。代码使用直接数值比较，没有设置“差不多相等”的容差。[8]

### B.4 — 同一根末端K线被修订，怎样恢复？

已有末根被更新时，调用方先撤回旧末根，再追加新值。若还在前导缓冲阶段，撤回就是移除缓冲的最后一根；若已经定向，则从末单元移除该成员。单元还有成员，就按原方向重算高低点；成员清空，则删除该单元。

如果撤回的恰好是最初建立方向的那根K线，程序会把此前首单元的成员重新放回前导缓冲，取消已定向状态。新值到来后，要重新判断方向，不能只修正价格。时间顺序由调用方保证，`append()` 本身没有按时间戳自动识别“替换”。[8：`pop_last_kline()`、`_recompute_unit()`]

### B.5 — 合并结果还保留什么？

除了合并区间和方向，每个结果还保留来源原始K线的起止索引、首尾时间及规则标记，便于回查合并依据。原始K线没有被写成合并后的高低点；该输出对象也没有在这里合成open、close或volume。

规则标记根据单元当前状态生成：初始组保留初始化标记，普通多成员组标记为包含合并，普通单成员组保留形成方向。撤回成员后，标记可随状态恢复。

正常追加时，最后一个单元仍可能吸收新K线；程序以倒数第二单元的结束位置作为稳定边界。不足两个单元时返回 `-1`。这并不保证显式向后撤回时更早状态永远不变。[8：`to_merged_klines()`、`_derive_rule_id()`、`stable_index()`]
