## 001 — Definition (What)

(版本一) 笔是由相邻异性分型构成，各笔首位相连、方向交替，每笔的顶、底分别为其范围内的最高、最低点，两分型之间至少有一根不属于二者的K线，且顶分型最高K线与底分型最低K线区间分别至少部分高于、低于对方区间。

（版本二）笔是在包含处理后的K线序列上，由一顶一底的端点分型连接而成，具有以下六个要素。设顶、底分型中间K线的区间分别为 `[L_T, H_T]`、`[L_B, H_B]`；“笔内”指两端中间K线之间的连续合并K线，包含两端。

1. **连续性**：相邻两笔首尾相接，共享连接端点分型；前一笔的终点就是后一笔的起点。
2. **交替性**：相邻两笔方向相反，向上笔与向下笔交替连接。
3. **异型分型连接**：每笔两端必须是一顶一底；先底后顶为向上笔，先顶后底为向下笔。
4. **端点极值**：顶、底端点分别为该笔的最高、最低点；笔内每根合并K线均满足 `high ≤ H_T`、`low ≥ L_B`。
5. **端点区间关系**：顶分型最高K线与底分型最低K线的区间，分别至少有一部分高于、低于对方区间，即 `H_T > H_B` 且 `L_B < L_T`。
6. **距离**：顶、底分型之间至少有一根不属于二者的合并K线，按包含处理后的序列计数；即两端分型中心的索引之差至少为4。

### A.2 — 第65课：一顶一底与同型分型的取舍

正文47–53行。[2] 原文先区分同型分型之间有没有其他顶底，后说明交替连接；不可只摘“忽略第一个”便改写为无条件删除任意较早分型。53行`娇注`为整理者注。

> **从分型到笔，必须是一顶一底。**那么，两个顶或底能构成一笔吗？这里，有两种情况:
>
> 第一种，在两个顶或底中间有其他的顶和底；这种情况，只是把好几笔当成了一笔，所以只要继续用一顶一底的原则，自然可以解决；
>
> 第二种，在两个顶或底中间没有其他的顶和底；这种情况，意味着第一个顶或底后的转折级别太小，不足以构成值得考察的对象，这种情况下，第一个的顶或底就可以忽略其存在了，可以忽略不算了。
>
> 所以，根据上面的分析，对第二种情况进行相应处理（娇注：类似对分型中包含关系的处理），就可以严格地说，先顶后底，构成向下一笔；先底后顶，构成向上一笔。而所有的图形，都可以唯一地分解为上下交替的笔的连接。显然，除了第二种情况中的第一个顶或底类似的分型，其他类型的分型，都唯一地分别属于相邻的上下两笔，是这两笔间的连接。用一个最简单的比喻，膝盖就是分型，而大腿和小腿就是连接的两笔。

### B.2 — 首笔候选、标准三道门与同型延伸

**首笔不是随便连接最早两分型。** 内部保存`_bis`和`_candidates`。尚无笔时，每来一个分型，按候选保存顺序扫描所有异型候选；首个通过标准三门的配对成为首笔并清空候选。都不通过便把当前分型也存入候选（155–163行）。首笔只尝试标准，未调用强势补救或repair。

**已有笔时的分支优先级。** 若新分型与末笔终点同型，直接尝试更极值延伸并返回；否则先尝试标准成反向笔，失败才试强势模式，再失败才在开关开启时试修正（136–153行）。同型顶只在更高时替换，底只在更低时替换；相等不替换，不重跑距离／端点门，也不回查修正（202–212行）。这说明“看到相反分型”与“已形成有效反向笔”不同。

标准三道门按顺序短路（277–288行）；下列前两项是距离门的两种模式，之后才是端点门与极值门：

1. **类型／距离。** 同型直接失败。`merged_center`用`end.index-start.index`；不足阈值且允许缺口折算，才遍历中心之间的相邻合并单元。缺口按每个单元对应的原始成员高低外包络算，严格满足`max(a_lo,b_lo)>min(a_hi,b_hi)`才加1，不按跳空金额加根数（291–329行）。
2. **新笔原始极值计数。** `raw_extreme`先要求`start.index+1 < end.index-1`（三根窗口不共用），再在起终中心单元的原始成员中找极值下标，相同极值取最早成员，检查原始下标差至少阈值（309–338行）。它不是简单把中心合并下标差改成3，也不在此路叠加缺口。
3. **端点有效性。** `none`跳过；`loss/half/strict/totally`选择不同的分型窗口部分。以向上`half`为例：起点中心low必须小于终点前根／中心low之min，终点中心high必须大于起点中心／后根high之max；向下用对应反向条件。`totally`要求相应价区完全分离（341–372行）。这些参数细节不是分型识别本身。
4. **端点极值。** 若`bi_require_peak`开启，向上要求起终中心之间所有high不超过终点顶；向下要求所有low不低于终点底，比较允许相等（374–379行）。实现没有在此额外检查起点是否也是整段最极值，不能扩大为“两端所有极值都已检验”。

### B.3 — 强势、修正、依赖水位与输出

**强势补救（166–197行）。** 幅度为两端选定顶底价的绝对差。先比当前候选幅度是否至少ratio×前一笔幅度；成功便追加。否则沿后方分型有界查找首条从当前终点起可标准成笔的反向笔，再比该后笔幅度；不会递归用强势笔验证后笔。依赖下标分别记当前终点或实际查到的后方端点，这一look-ahead不能伪装成候选当时已知的信息。

**项目修正（214–269行）。** 要至少已有两笔；先检查当前反向分型是否击穿反弹笔起点、反弹终点是否未反越前笔起点，以及前笔起点到该新极值的peak条件。通过后仍需向后扫描确认：若先越过反弹终点的极值，才视作假反弹并吸收；若先从反弹终点形成标准反向笔，或扫到末尾仍不充分，则保留旧结构。实际处理是弹出末笔并延伸前笔；若延伸没有改变端点，就把弹出的笔放回。最终依赖水位包含后方确认位置。不能只根据docstring“修正”二字就宣称能即时稳定回退所有历史。

**confirmed与provisional（57–79行）。** `bi_confirmed_flags`以每笔trace依赖水位、合并单元总数和末两笔位置计算：末笔恒provisional；缺依赖或`dep >= n_merged-2`者provisional；若末笔依赖仍不稳定，倒数第二笔也provisional。这是CC工程稳定性判据，不是作者对完成一笔的原文定义，也不是单看终点时间。

**finish与追溯（389–419行）。** 工作状态转为不可变Bi：由终点分型定方向；向上价为起底→终顶，向下起顶→终底；trace记录实际成笔rule ID、profile、config hash、中心合并下标闭区间和dep。来源时间包络扩大到`merged[start.index-1].start_ts…merged[end.index+1].end_ts`，包含两端分型的侧翼；几何端点时间仍是中心分型timestamp。Bi显示ID为`bi-{start_ts}-{end_ts}`（models.py:164–184），和TDS拟议整数ID不同。[9][11]

### B.6 — 补查实际生效配置、强势绕过、修正取等与追溯限制

**生效配置。** `build_bis()`首先调用`cfg.normalize()`；`config.py:203–222`对named profile从完整预设取笔参数，只有`CUSTOM`保留调用者自由组合。因此“给bi_5k对象另填一个ratio／min_span”不保证该值进入执行分支；原B.1表列的是归一化后的值。`profile_id`／`config_hash`仍是调用者传给`finish()`的字符串，`build_bis()`没有用实际生效配置重算这两个实参；正常引擎怎样生成它们与helper本身是否校验匹配须分开。[9][10] 本入口也没有重新核对分型index是否属于这份确切merged／raw来源、列表时序和全部价格是否合法；正常调用链的前提不能自动算成helper自身的验证。

**强势的实际豁免。** 标准三门失败后，`_try_strong()`只比较候选幅度与相邻反向笔幅度；满足前笔或后笔条件便直接`_append()`，没有再把失败的距离、端点或peak门重新要求一遍。前笔优先，只有前笔不够才查后笔。`_lookahead_next_std_bi()`从当前位置扫描到当前分型数组末尾，取首个异型且标准成笔的反向候选；所谓“有界”是当前有限数组边界，没有额外固定K数／时间的前看上限。不能把它说成固定时间的实时操作。[9]

**修正首关与取等。** `_repair_sub_peak()`的起点破坏检查用`<`／`>`作失败条件，因此“刚好到达旧起点”并不在首关立即排除；但最后延伸仍要求严格新极值，若对象没变就恢复弹出的笔。`_confirm_reverse_break()`确认越过反弹端点也用严格`>`／`<`，取等不确认；候选／后方证据的先后顺序不可交换。repair中的`_is_peak()`始终执行，不因自定义配置关闭普通`bi_require_peak`而跳过。[9]

**来源与原因记录。** `source_to_ts`只扩到几何终点分型的右侧翼；strong_next／repair读到更晚证据时，额外水位由`dep_to_index`保存，并不自动把时间包络一直扩到该证据。`_extend_same_fx()`只改终点和dep，没有重写原`rule_kind`；所以被修正／同型延伸的笔仍可保留最初standard或strong规则ID。这个ID不能单独重建后来修正的完整原因链。`finish()`的high/low直接取起终几何价格，不重新遍历所有来源成员求生命周期外包络；也总构造trace，未读取`cfg.trace_enabled`，关闭观测配置不等于本helper不再产生这些字段。[9]

### B.7 — 从同一来源底稿补足强势与修正的完整条件链

以下四种是**彼此独立的教学输入场景**，都从B.4原始范围表出发，未导入或运行CC。所有合并单元均只含对应原始成员`Mi=Ri`，相邻无包含，时间依次为`t_i`；未列出的下标保持B.4原值，给定终点后的右邻包含在各自输入前缀中。算术脚本独立核对所有原始分型、零缺口、距离、half与peak前提，不把人为预置的内部状态冒充完整行情输出。

| 场景 | 与B.4底稿不同的原始范围；当前最后下标 | 形成的分型（序号／极值价） |
|---|---|---|
| strong_prev | M15=[5.5,14]；输入到M16 | B1=6、T4=16、B8=5、T12=17、B15=5.5 |
| strong_next | M15=[7,12]，M16=[9,13]，M17=[10,14]，M18=[11,15]，M19=[12,16]，M20=[9,12]；到M20 | B1=6、T4=16、B8=5、T12=17、B15=7、T19=16 |
| repair接受 | M12=[14,15.5]，M15=[4,14]；到M17 | B1=6、T4=16、B8=5、T12=15.5、B15=4、T16=18 |
| repair拒绝 | M12=[14,15.5]，M15=[4,14]，M16=[12,15]，M17=[8,12]，M18=[3,9]，M19=[6,11]；到M19 | B1=6、T4=16、B8=5、T12=15.5、B15=4、T16=15、B18=3 |

**强势前笔。** 固定归一化named `bi_strong`，ratio=0.95。开始仍由标准门建立T4→B8和B8→T12；T12→B15中心差3且零缺口，标准失败。候选幅度`17−5.5=11.5`，前笔幅度`17−5=12`，`11.5>=0.95×12=11.4`成立，立即追加17→5.5，rule=`strong_prev`、dep=15，不再查后笔。原始底分型B15要到M16出现才具备右侧信息，dep下标15不是最早可知的原始时间。

**强势后笔。** 同样使用named `bi_strong`。到B15时，候选17→7的幅度10不够11.4，标准距离3仍失败；look-ahead找到首个从B15标准成笔的T19：中心差4，half为`7<min(11,12)`且`16>max(12,13)`，中间high不超过16，后笔幅度9。`10>=0.95×9=8.55`成立，追加17→7，rule=`strong_next`、dep=19；正常扫描随后到T19再按标准追加7→16。若输入只到M16而没有T19候选，strong_prev、strong_next与repair均不通过，这条17→7尚不能输出。完整M20快照中的几何终点`t15`、时间包络到右侧翼`t16`、依赖19、及T19要等右邻M20才可识别是四件事，不能都标成t15时已确认。

![强势前笔／后笔两个独立输入：同价格轴与来源轴，后笔条件明确依赖19](memoWX_020_Chan_bi/cc-stroke-strong-recheck.png)

**repair接受。** 固定默认named `bi_5k`（standard且repair开启），先得到16→5和5→15.5。B15=4到来时，15−12=3且零缺口，标准失败；`4<=5`、反弹终点`15.5<=16`，前笔起点T4到B15之间所有low≥4，修正前提成立。未来先见T16=18严格超过反弹顶15.5，守卫返回确认下标16；弹出5→15.5，原向下笔终点从B8的5延伸到B15的4，最后得到16→4、dep=max(8,15,16)=16。来源中心范围[4,15]、侧翼时间`t3…t16`，而T16候选依赖原始M17；原standard规则ID被保留，不能据它看出这次吸收动作。

**repair拒绝。** 保持相同历史到B15，后续先见T16=15，没有严格超过15.5；然后B18=3使T12→B18标准成笔：中心差6，half为`15.5>max(12,9)`及`3<min(14,12)`，中间low≥3。守卫在这条标准反向笔先成立时返回None，保留16→5和5→15.5；扫描到B18后追加15.5→3。相同的B15破起点动作，因后续证据顺序不同而结果不同，不能只看“破了5”就直接吞掉反弹。
