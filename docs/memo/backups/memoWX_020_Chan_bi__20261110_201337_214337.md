## 001 — Definition (What)

(版本一) 笔是由相邻异性分型构成，各笔首位相连、方向交替，每笔的顶、底分别为其范围内的最高、最低点，两分型之间至少有一根不属于二者的K线，且顶分型最高K线与底分型最低K线区间分别至少部分高于、低于对方区间。

（版本二）笔是在包含处理后的K线序列上，由一顶一底的端点分型连接而成，具有以下六个要素。设顶、底分型中间K线的区间分别为 `[L_T, H_T]`、`[L_B, H_B]`；“笔内”指两端中间K线之间的连续合并K线，包含两端。

1. **连续性**：相邻两笔首尾相接，共享连接端点分型；前一笔的终点就是后一笔的起点。
2. **交替性**：相邻两笔方向相反，向上笔与向下笔交替连接。
3. **异型分型连接**：每笔两端必须是一顶一底；先底后顶为向上笔，先顶后底为向下笔。
4. **端点极值**：顶、底端点分别为该笔的最高、最低点；笔内每根合并K线均满足 `high ≤ H_T`、`low ≥ L_B`。
5. **端点区间关系**：顶分型最高K线与底分型最低K线的区间，分别至少有一部分高于、低于对方区间，即 `H_T > H_B` 且 `L_B < L_T`。
6. **距离**：顶、底分型之间至少有一根不属于二者的合并K线，按包含处理后的序列计数；即两端分型中心的索引之差至少为4。
7. 
**（版本三）** 从分型序列中选取子集，连接成首尾相接上下交替的折线，简洁有效的的描述市场波动。

### 002.a — Algorithm Tree



第一轮只给我最小主流程和一个完整例子，先不写代码或修改 memo。

本树将001版本二的成笔条件与“暂定端点延伸、缓存备选、恢复重查”合为一个有限输入算法。按时间接受当前工作状态下首个合格反向C；同价B的合法选择分路考察；备选按最近未执行者优先恢复，全部考察后返回合法路线，不暗选唯一结果。此为可执行的候选算法方案，不表示已证明等同于作者的唯一划笔结果。

**起点规则（本轮修订）**：从左往右选首个能与右侧分型合格成笔的分型为初始A；“合格”使用下述完整配对条件，不只判断分型形态。A一旦确定，不因其路线后续阻塞而改用更晚初始A；仍保留该A下的B替代和后续缓存恢复。若该A全部路线阻塞，返回无可行路线及依据。早期多起点实验仅作历史证据，不是现行起点规范。

**输入、工作状态与缓存**

- 输入为已完成包含处理的K线及全部完整分型；分型按中心位置严格递增且无重复。完整仅指三根窗口齐备，不表示走势确认；本次计算使用同一不可变输入。
- A为当前笔起点，B为暂定终点，F为本轮新读分型；C表示通过反向检查的F。找到B后仍保留A，直到工作对推进或恢复备选。
- 缓存保留原始候选及失败依据，并保存尚未执行的选择：已有路径、A/B、所处阶段、对应输入和下一未读位置。备选明确“换走哪一支”；恢复后不重复生成同一个选择。
- 顶、底中心K线区间分别为 `[L顶,H顶]`、`[L底,H底]`。“合格(X,Y)”同时要求：X早于Y且一顶一底；合并中心距离至少4；`H顶>H底`且`L底<L顶`；两中心之间（含两端）每根合并K线均有`high≤H顶`、`low≥L底`。

**判断树：判断结果 → 行动 → 下一步**

```text
2.1 输入与初始起点检查
├── 2.1.a 完整分型少于两个
│   → 返回“暂无完整笔”和未决范围，结束
└── 2.1.b 至少两个
    → 从左往右依次检查初始起点候选X；对每个X，从其右侧按时间查找合格(X,Y)；
      首个存在合格Y的X确定为A，B未定，已有笔为空；只初始化这个A，转2.2；
      若所有X均无合格Y，返回“暂无合格起始笔”和未决范围，结束

2.2 下一分型检查
├── 2.2.a 仍有下一完整分型F
│   → 读取F，把检查位置移到F之后；转2.3
└── 2.2.b 完整分型已耗尽
    → 本分支以“输入耗尽”进入2.8

2.3 当前工作阶段检查
├── 2.3.a B未定：正在寻找当前笔的终点
│   └── 2.4 A→F成笔条件检查
│       ├── 2.4.a 不合格
│       │   → 保留F及本次失败原因；A不变，回2.2
│       └── 2.4.b 合格
│           → 缓存“本次不选F、保留A、从下一位置继续找B”的备选；
│             当前取B=F，保留A，进入等待反向C阶段；回2.2
│             ［此时不固定B，也不立即输出完成笔］
└── 2.3.b B已暂定：正在等待合格反向C
    └── 2.5 F与B的类型检查
        ├── 2.5.a 同型 → 转2.6
        └── 2.5.b 异型 → 转2.7

2.6 同型端点延伸检查
├── 2.6.a F比B更极端：顶更高，或底更低
│   → 重新检查完整的A→F
│   ├── 2.6.a.1 合格
│   │   → 记录旧B的历史，以F更新B；A不变；回2.2
│   │     ［当前路线必须延伸，不保留“跳过更优F仍沿用旧B”的分支］
│   └── 2.6.a.2 不合格
│       → 记录F、失败原因和历史有效片段；
│         当前路线不能沿旧B继续覆盖后续，标记阻塞；转2.8
├── 2.6.b F与B端点价格相等
│   → 检查A→F
│   ├── 2.6.b.1 合格
│   │   → 缓存“改取B=F、从下一位置继续”的备选；
│   │     当前保留旧B，回2.2；两支独立考察
│   └── 2.6.b.2 不合格
│       → 保留F及失败原因；当前B不变，回2.2
└── 2.6.c F不如B极端
    → 保留F供其他路线重查；当前B不变，回2.2

2.7 反向笔检查
├── 2.7.a B→F不合格
│   → 缓存F及相对B的失败原因；A、B均不变，回2.2
└── 2.7.b B→F合格
    → F成为本工作状态下首个合格反向C；
      将A→B暂存为本分支已有笔，记录路径检查点；
      以旧B作为新A，以C作为新B，继续等待下一反向端点；回2.2
      ［B→C仍是可延伸的工作笔，此前路径也允许经备选恢复而重选］

2.8 当前分支收尾与备选恢复
→ 先按进入原因处理
├── 2.8.a 输入耗尽
│   ├── B已暂定
│   │   → 保留“已有笔＋当前A→B”为一条候选路线；
│   │     当前工作笔标为暂定；头尾未覆盖范围单独保留
│   └── B仍未定
│       → 孤立起点不计作笔，保留未决范围
└── 2.8.b 延伸失败，当前路线阻塞
    → 仅保存历史有效片段和阻塞依据；
      不把该片段冒充已处理后续行情的可行路线
→ 再检查备选缓存
├── 2.8.c 还有未执行的备选
│   → 取最近的未执行备选；恢复其完整路径、A/B、阶段及下一检查位置；
│     执行该备选已经指定的不同选择，复核工作对及已有连接；
│     通过后回2.2；恢复状态不一致则报错，停止
│     ［恢复后从该位置按时间重查，不重开同一个选择］
└── 2.8.d 所有备选均已执行
    → 转2.9

2.9 最终结果检查
├── 2.9.a 没有可行候选路线
│   → 返回“暂无可保留的候选路线”，附历史片段、阻塞依据及未决范围；结束
└── 2.9.b 存在可行候选路线
    → 复核每根笔及共享端点、方向交替；不合格则报错，停止；
      合格则合并端点序列完全相同的重复结果，按相同起终点分组；
      组内一条标记唯一，多条全部保留并标记多解；
      返回候选路线、暂定工作笔和各自未决范围，结束

```

**必要约定**

1. 合法A→B只覆盖两中心之间的历史范围。等待C时，B之后的波动属于未决尾部；不把尚缺右邻K线的极值制造成新分型，也不自动确认笔。
2. 更极端F使A→F不合法时，旧B不能继续充当覆盖后续的有效端点：向下的新低F会破坏未来B→C的最低约束，向上对称。旧片段仍可合法，但只能作为阻塞历史保存，必须恢复其他选择。
3. 备选恢复时重新校验受影响连接，分型原时间次序不变。早于新B的缓存分型不能倒接为其后的C；从更早恢复点重放时可以成为新的起点或端点候选。
4. 当前分支每次读取都前进一位；缓存只保存尚未执行的不同选择，恢复从其下一位置继续。有限输入和有限端点选择保证终止；禁止仅凭表面相同的A/B就跳过其他未试备选。输入改变须重新核验，不沿用旧结果。
5. 输出含暂定工作笔和未决头尾，不宣称永久稳定或必能覆盖全部输入。搜索可呈指数增长；此处先确定完整纯算法，效率优化另行处理。[缓存算法与独立核验](../../artifacts/mas/bi-algorithm-study/cached-reference.md)

### 002.b — Detailed Implementation logic and Numerical Examples

本节直接使用已处理好的合并K线和全部完整分型，不重复上游包含处理。区间为 `[low,high]`；合并位置与分型位置均从0开始。数值是教学构造，只提供高低价，不编造原始OHLC或原始锚点。

#### 处理逻辑

1. **准备候选起点（2.1）。** 从左往右依次检查分型X；对每个X，从其右侧向右检查是否存在合格(X,Y)。首个有合格配对的X确定为唯一初始A；不为更晚起点缓存分支。已有端点路径起初只有A，B未定，随后从A右侧重新按时间找B。所有X均不合格则返回空候选与未决范围。
2. **寻找B（2.2–2.4）。** 顺序读取F，先将游标移至下一分型，再检查A→F。失败只记录本次配对原因；成功则缓存“不选F”的独立备选，当前令B=F。A→B仍为工作笔，不立即固定B。
3. **延伸B（2.5–2.6）。** 同型F更极端时，完整检查A→F，通过才更新B；失败则阻塞当前路线，保存历史片段并恢复备选。同价F通过检查时保留旧B与改取F两支；较弱F不替换B。
4. **等待反向C（2.7）。** 异型F须与当前B重新配对；不合格者保留，首个合格者成为C。将A→B局部暂存，工作对推进为B→C；新终点C仍可延伸，先前路线也允许随备选恢复而重选。
5. **恢复备选（2.8）。** 恢复的是另一种选择已经指定好的路径、A/B及下一未读位置，不重新进入同一选择点再次分叉。阻塞历史不混入可行结果；数据耗尽时的最后工作笔保持暂定，头尾未覆盖范围单独记录。
6. **汇总候选（2.9）。** 完成全部分支后复核连接，按分型位置序列去重，再按相同起终点分组。组内唯一不等于整个输入只有一种划笔；本树不另选最多笔、最早或最晚的一条。

#### 主例：21根合并K线中的阻塞与恢复

依次给定最低价：

```text

low：  8  9  6  4  2  0  2  4  6  7  3 -1  1  3  5  8  5  2  0 -2 -1
```

每根的 `high=low+1`。相邻low均不相等，所以相邻high、low始终共同严格上移或下移，没有相邻包含。逐窗识别得到以下全部分型：

| 分型位置 | 类型 | 合并中心 | 中心区间 | 分型价格 | 合并窗口 |
|---|---|---:|---|---:|---|
| FX0 | 顶 | 1 | `[9,10]` | 10 | `[0,3)` |
| FX1 | 底 | 5 | `[0,1]` | 0 | `[4,7)` |
| FX2 | 顶 | 9 | `[7,8]` | 8 | `[8,11)` |
| FX3 | 底 | 11 | `[-1,0]` | −1 | `[10,13)` |
| FX4 | 顶 | 15 | `[8,9]` | 9 | `[14,17)` |

**第一次尝试。** 初始A为顶1，已有端点路径为 `(FX0,)`，B未定。

| 读到的分型 | 检查与结果 | 当前已有路径／工作对 | 缓存或下一步 |
|---|---|---|---|
| 底5 | 1→5中心距4；范围最低0、最高10，合格 | 已有路径仍为`(1,)`；工作对`1→5` | 缓存“不选底5”；当前B=底5 |
| 顶9 | 5→9中心距4；范围最低0、最高8，合格反向 | 局部暂存`1→5`；工作对`5→9` | A=底5、B=顶9，继续等下一反向 |
| 底11 | 9→11中心距2，不合格 | 保留工作对`5→9` | 记录底11及距离失败依据，不删除它 |
| 顶15 | 顶15的9高于暂定顶9的8，须尝试延伸；但5→15范围最低为−1，低于底5的0 | `5→15`不合格，当前路线阻塞 | 保存历史`1→5→9`与失败依据，恢复备选 |

顶15出现时，当前工作笔的A已经是**底5**，B是**顶9**，因此复查的是 `5→15`。初始顶1已经在此前路径中，不能误用 `1→15` 替代本轮检查。新顶更高并不足以保证延伸合法；完整范围内的底11使底5失去最低端点资格。

**恢复的选择。** 底5第一次合格时保存的备选，表示“本次不选底5”；它的状态已经位于该选择之后：

```text
已有端点路径 = (FX0,)
A = FX0（顶1）
B = 未定
下一分型位置 = 2（FX2，顶9）
```

恢复后既不重读底5并重新生成相同备选，也不沿用阻塞分支已经前进到中心19的游标。

| 恢复后读取 | 判断 | 行动 |
|---|---|---|
| 顶9 | 与初始A顶1同型 | 本对不能成笔，继续 |
| 底11 | 1→11中心距10；范围最低−1、最高10，合格 | 当前B=底11，另缓存“不选底11” |
| 顶15 | 11→15中心距4；范围最低−1、最高9，合格反向 | 局部暂存`1→11`，工作对变为`11→15` |
| 底19 | 15→19中心距4；范围最低−2、最高9，合格反向 | 局部暂存`11→15`，工作对变为`15→19` |
| 输入耗尽 | 最后工作对仍满足全部条件 | 保留路线`1→11→15→19`；`15→19`仍为暂定工作笔 |

**全部分支的输出。** 从左往右确定首个可合格成笔的A为中心1；只恢复该A的剩余备选，得到两条去重后的可行路线：

| 合并中心路线 | 源分型位置序列 | 最后暂定工作对 |
|---|---|---|
| `1→11→15→19` | `(0,3,4,5)` | FX4→FX5 |
| `1→19` | `(0,5)` | FX0→FX5 |

这两条属于同一起终点组，仍有多解；更晚初始起点的路线不再单独输出。阻塞的历史`1→5→9`另列诊断，不作为可行路线返回。

例如第一条路线对应的Bi端点位置将是 `(0,3)`、`(3,4)`、`(4,5)`，方向依次向下、向上、向下；不是把合并中心1、11、15、19直接填入 `start_fenxing_index/end_fenxing_index`。本节不为合成区间编造 `anchor_raw_index`；实际显示复用源Fenxing已有的原始锚点。

#### 补例：B成功延伸后才找到反向C

另给15根合并K线，low依次为 `1,0,3,6,9,12,10,8,12,16,13,10,7,4,5`，每根 `high=low+2`。全部分型为底1、顶5、底7、顶9、底13。

| 事件 | 数值检查 | 工作状态 |
|---|---|---|
| 顶5出现 | 底1→顶5中心距4，范围`[0,14]`，合格 | A=底1、暂定B=顶5，不固定B |
| 底7出现 | 顶5→底7中心距2 | 反向不合格，缓存底7 |
| 顶9出现 | 18>14，且底1→顶9中心距8、范围`[0,18]`，完整复检通过 | 必须更新B=顶9，旧顶5进入历史 |
| 底13出现 | 顶9→底13中心距4、范围`[4,18]`，合格 | 首次局部收下`1→9`；`9→13`成为新工作笔 |

![暂定B从顶5延伸至顶9，再推进为反向工作笔](memoWX_020_Chan_bi/algorithm-endpoint-extension.png)

因此这一分支首次局部收下的是 `1→9`，而不是提前固定的 `1→5`。向下笔完全对称：在合格反向顶出现前，后来的更低底只有通过A→新底完整复检后才能替换B。

**其余边界。** 同价B按2.6.b保留两种合法选择，与一个合并中心内部原始锚点的FIRST／LAST无关。最后合并K线已经越过B、但尚未形成完整新分型时，只标注方向性尾部越界和未决范围，不制造新端点。原始输入或合并尾部修订后，应使用新快照重新计算，不把本次恢复点当成跨版本增量协议。

### 002.c — Helper Functions

以下6个拟议私有辅助函数服务于002.a的候选搜索，不新增领域类，不修改上游数据。入口复用确切`FenxingSeries.validate()`；主过程负责读入位置、备选栈、依据记录与报告组装。多条候选路线不能平铺为同一条`BiSeries.items`；本阶段返回普通研究报告，尚不定义正式`BiSeries.derive_from()`的多解返回接口。

**位置与工作状态。** `source`是本次确切FenxingSeries，`fx=source.items`，`merged=source.source_series`，`M=len(fx)`。A、B、F和路线中的端点均为`fx`的零基位置，不是特征ID、合并K线位置或原始锚点；`c(p)=fx[p].source_start+1`才是合并中心。`prefix`为已有连接的端点元组，其最后一项恒为A；当前工作笔A→B尚未追加到prefix。`cursor`为下一未读分型位置，可等于M表示耗尽。分支保存确切source引用、prefix、A/B、阶段和cursor；这些仅是算法工作数据。

#### 检查完整配对：_check_pair

**接口：** `_check_pair(source, a, b) → (ok, reasons)`。

端点必须是当前source中的整数序列位置；非法类型或越界报错，不做ID解析。数值恰好落在位置范围内的ID误用，不能仅凭整数检查识别，调用方必须按源序列位置传参。按002.a的“合格”定义，依次检查时间／类型、`c(b)-c(a)≥4`、两中心区间关系，以及闭区间`[c(a),c(b)]`内全部合并K线的高低界。返回布尔结果及本次实际失败依据；同型或逆序先返回不合格，不能用无意义的方向继续判断。函数不选端点、不推进cursor、不修改分型，也不重跑合并。

#### 比较同型终点：_compare_end

**接口：** `_compare_end(source, b, f) → MORE／EQUAL／LESS`。

要求F晚于B且两者同型。顶比较端点price，较高为MORE；底较低为MORE；严格相等为EQUAL，其余LESS。输入先由source校验保证price与中心高／低一致；不使用原始锚点时间先后代替价格，不设容差。这只决定进入哪条分支，不代替A→F的完整检查。

#### 冻结备选状态：_freeze_branch

**接口：** `_freeze_branch(source, prefix, a, b, cursor) → snapshot`。

保留确切source引用；把路径复制为不可变元组，保存A/B、阶段及下一未读cursor，形成不可变快照，再调用`_validate_branch`。B为空对应SEEK_B，否则WAIT_REVERSE。source本身是不可变输入，保持同一引用，不复制成另一数据版本。调用方随后改变临时列表，不得影响快照；不同分支允许共享不可变值，不共享可变路径。

缓存的是**作出不同选择之后的状态**：首次B备选已经拒绝本次F，故保存B为空及F之后的cursor；同价备选已经改取B=F，也保存F之后的cursor。恢复时不重新生成同一次选择。

#### 校验恢复分支：_validate_branch

**接口：** `_validate_branch(source, snapshot) → None`。

检查snapshot.source与source为同一对象；prefix是非空不可变端点元组且最后一项为A，每项在当前fx范围内，已有各连接重新通过`_check_pair`。SEEK_B时B为空，prefix仅含当前初始A；WAIT_REVERSE时A→B必须合格。cursor为整数，满足`A<cursor≤M`或`B<cursor≤M`，分别对应两阶段；阶段、A/B和路径不一致时报错，不排序、不修补，也不从别的source恢复。

这验证工作状态的结构与几何不变量；时序选择是否符合“必须延伸／首个合格C”，由主过程按输入顺序执行，并用独立递归参考交叉核对，不能声称仅靠几何校验就证明整个协议。

#### 按原因收尾：_finish_branch

**接口：** `_finish_branch(source, snapshot, reason, F=None, reasons=()) → ordinary_data`。

先校验快照，再区分原因。EOF必须有`cursor=M`：B存在时，保存`prefix+(B,)`为候选路线，最后A→B明确标暂定；头部未覆盖范围为`[0,c(first))`，尾部为`[c(B)+1,N)`，均按合并位置计。B不存在时仅保存孤立起点及未决范围，不构造笔。BLOCKED要求F是刚读过的更极端同型分型，且A→F确实不合格；只保存原历史有效连接、原工作对和失败依据，不产生可行路线。

EOF候选可以带有B之后的未决波动，甚至已有合并K线突破B而尚无新完整同型分型；可以记录该事实，但不得据此制造分型或自动确认笔。该报告标记不是对`Bi.status`／`confirmed_at`字段的新定义。

#### 复核候选路线：_validate_candidates

**接口：** `_validate_candidates(source, candidates) → None`。

逐条检查确切来源、至少两个端点、严格时间顺序、全部配对、共享端点和方向交替；最后暂定工作对必须等于路线末两项，未决范围与合并中心一致。候选端点序列完全相同者应已去重，不允许BLOCKED历史混入候选。成功返回None，失败报错；不替用户选定唯一结果，也不改变原Fenxing的状态／锚点。

若后续确定单一路线，其中每个相邻端点对可沿memo009的8字段Bi表达：起止引用仍是该确切FenxingSeries中的位置，价格取对应分型price，方向取一顶一底的先后，ID属于该路线结果；确认字段另按正式规则处理。BiSeries仍保留memo009的6字段，不因当前多解研究报告增加字段或额外类。

### 002.d — Pseudocode

以下为002.a的算法伪代码，不是已实现的生产API。`search(source)`返回普通报告；`记录依据`表示本轮真实比较、来源和选择，不在此新定义DecisionStep字段。全部价格判断使用同一输入精度。

#### 主过程与实际缓存恢复

```text
search(source):
    若source不是完整FenxingSeries：报错
    source.validate()
    fx ← source.items
    merged ← source.source_series
    M ← len(fx)
    N ← len(merged)
    pending、candidates、blocked、unresolved、evidence ← 独立空列表

    若M<2：
        记录“不足两个完整分型”及整个[0,N)为未决范围
        返回同一来源、空候选／分组／阻塞记录、未决范围及本次依据
        # 输入先校验；不构造孤立笔，也不进入分支循环

    initial_A ← None
    对a从0递增到M−2：
        对b从a+1递增到M−1：
            若_check_pair(source,a,b)合格：
                initial_A ← a；结束内层循环
        若initial_A不为空：结束外层循环
    若initial_A为空：
        返回同一来源、空候选／分组及“暂无合格起始笔”的依据和未决范围
    pending.push(_freeze_branch(source,(initial_A,),initial_A,None,initial_A+1))
    # 只确定最早可成笔的A；不固定预查时找到的B，也不缓存更晚A

    当pending不为空时重复：
        snapshot ← pending.pop()             # 最近未执行备选先恢复
        _validate_branch(source, snapshot)
        prefix,A,B,cursor ← snapshot的对应值
        dead ← False
        记录恢复来源、完整路径与下一未读位置

        当cursor<M时重复：
            F ← cursor
            cursor ← cursor+1                # 先移到F之后，再缓存不同选择

            若B为None：
                ok,reasons ← _check_pair(source,A,F)
                若ok：
                    pending.push(_freeze_branch(
                        source,prefix,A,None,cursor))
                        # 此备选已经拒绝本次F；恢复后从下一分型继续找B
                    B ← F
                    记录找到暂定B；保留A，不追加prefix、不确认
                否则：记录F及失败依据

            否则若fx[F].kind=fx[B].kind：
                relation ← _compare_end(source,B,F)
                若relation=MORE：
                    ok,reasons ← _check_pair(source,A,F)
                    若ok：
                        记录旧B与延伸依据
                        B ← F                # 必须更新，不留沿用旧B的备选
                    否则：
                        snapshot ← _freeze_branch(source,prefix,A,B,cursor)
                        blocked.append(_finish_branch(
                            source,snapshot,BLOCKED,F,reasons))
                        dead ← True
                        跳出本分支扫描        # 回到pending恢复更早选择
                否则若relation=EQUAL：
                    ok,reasons ← _check_pair(source,A,F)
                    若ok：
                        pending.push(_freeze_branch(
                            source,prefix,A,F,cursor))
                            # 此备选已经选择同价新B=F
                    记录同价比较；当前保持旧B
                否则：记录较弱F，当前B不变

            否则：
                ok,reasons ← _check_pair(source,B,F)
                若ok：
                    记录本工作状态首个合格反向C=F及路径检查点
                    prefix ← prefix+(B,)
                    A,B ← 旧B,F              # 同时赋值；新B仍可延伸
                否则：记录F及相对B的失败依据

            _freeze_branch(source,prefix,A,B,cursor)
                # 仅核对本轮状态，不另入缓存；构造时已调用_validate_branch

        若dead=False：
            outcome ← _finish_branch(source,
                _freeze_branch(source,prefix,A,B,cursor),EOF)
            若outcome是候选：candidates.append(outcome)
            否则：unresolved.append(outcome)
        # 当前分支已收尾；外层while取最近备选。没有任何裸goto跳过恢复。

    按同一source内的完整端点位置元组去除重复候选
    _validate_candidates(source,candidates)
    按首末端点位置分组：一条标单解，多条全部保留标多解
    # 单解只指同一输入、相同边界、按本树策略得到的一条去重路线
    返回来源、候选／分组、末笔暂定信息、未决范围、blocked及实际依据
    # 无候选时返回相应说明；BLOCKED历史不充当候选路线
```

#### 完整配对与状态校验

```text
_check_pair(source,a,b):
    fx ← source.items；merged ← source.source_series
    检查a,b确为当前fx范围内的整数位置；越界则报错
    i,j ← fx[a].source_start+1, fx[b].source_start+1
    若a≥b或i≥j：返回(False, 时间逆序依据)
    若fx[a]与fx[b]同型：返回(False, 同型依据)
    定位顶中心T与底中心D
    reasons ← 空
    若j−i<4：记录距离失败
    若H_T≤H_D或L_D≥L_T：记录端点区间失败
    对k从i到j（含两端）：
        若merged[k].high>H_T：记录范围最高点失败
        若merged[k].low<L_D：记录范围最低点失败
    返回(reasons为空, reasons的不可变副本)

_compare_end(source,b,f):
    fx ← source.items
    检查f晚于b且同型；否则报错
    若fx[f].price=fx[b].price：返回EQUAL
    若同为顶：较高返回MORE，其余LESS
    若同为底：较低返回MORE，其余LESS

_freeze_branch(source,prefix,a,b,cursor):
    snapshot ← 包含同一source、tuple(prefix)、a、b、阶段及cursor的不可变数据
    _validate_branch(source,snapshot)
    返回snapshot

_validate_branch(source,snapshot):
    fx ← source.items；M ← len(fx)
    prefix,A,B,cursor ← snapshot的对应值
    检查source对象身份、阶段、端点／cursor整数范围
    检查prefix为非空元组且末项=A
    对prefix每个相邻端点对：要求_check_pair通过
    若B为空：要求阶段SEEK_B、prefix=(A,)、A<cursor≤M
    否则：要求阶段WAIT_REVERSE、_check_pair(A,B)通过、B<cursor≤M
    任一不符报错；成功返回None

_finish_branch(source,snapshot,reason,F=None,reasons=()):
    _validate_branch(source,snapshot)
    prefix,A,B,cursor ← snapshot的对应值
    M ← len(source.items)；N ← len(source.source_series)
    若reason=BLOCKED：
        复核F=cursor−1、F较B更极端、A→F失败且依据一致
        返回历史片段及阻塞依据，不返回候选
    要求reason=EOF且cursor=M
    若B为空：返回孤立起点及未决范围
    endpoints ← prefix+(B,)
    返回候选endpoints、末笔(A,B)暂定、头尾未决范围及来源

_validate_candidates(source,candidates):
    fx ← source.items；merged ← source.source_series
    检查每条候选属于同一确切source，且至少含两端点、无重复路线
    对每条路线的相邻端点对：重新要求_check_pair通过
    检查共享端点与交替方向，最后暂定工作对等于末两项
    检查头尾未决范围对应实际合并中心
    任一不符报错；成功返回None
```

每次读取cursor严格前进，备选保存的是F之后的不同选择，恢复不重新创建同一选择；有限分型、唯一初始起点及有限深度选择树保证终止。令N为合并K线数、M为分型数、S为实际检查／恢复步数、R为去重路线数；本参考方案的完整状态与配对复核成本为O((S+R)(N+M))；候选去重、分组和可选排序另计，上游校验亦另计。S与输出数量都可能指数增长，保存候选所需空间至少与全部端点序列总长度成正比，完整依据和阻塞历史另计；本节不暗加剪枝、最大笔数目标或单解优先策略。依据保留原候选及真实失败原因，恢复重放原始时间顺序，不能把早于新B的缓存分型倒接为其后的C。输入版本改变时重新计算。

**核验边界。** 该伪代码的辅助函数分解已用独立可执行模型对照递归参考：1010组输入及1010个价格镜像，包含1000组变宽合并区间；另有12项损坏状态／短输入探针和路径别名检查。对照的是候选端点集合与局部状态不变量，不把它写成全部trace或诊断字段逐字一致的证明。入口的合成适配器仅验证本实验使用的字段，不替代真实FenxingSeries的完整来源校验；生产Bi、确认协议和CC均未在本任务运行。[伪代码模型核验](../../artifacts/mas/memo020-002b-d/pseudocode_model.json)

### A.2 — 第65课：一顶一底与同型分型的取舍

正文47–53行。[2] 原文先区分同型分型之间有没有其他顶底，后说明交替连接；不可只摘“忽略第一个”便改写为无条件删除任意较早分型。53行`娇注`为整理者注。

> **从分型到笔，必须是一顶一底。**那么，两个顶或底能构成一笔吗？这里，有两种情况:
>
> 第一种，在两个顶或底中间有其他的顶和底；这种情况，只是把好几笔当成了一笔，所以只要继续用一顶一底的原则，自然可以解决；
>
> 第二种，在两个顶或底中间没有其他的顶和底；这种情况，意味着第一个顶或底后的转折级别太小，不足以构成值得考察的对象，这种情况下，第一个的顶或底就可以忽略其存在了，可以忽略不算了。
>
> 所以，根据上面的分析，对第二种情况进行相应处理（娇注：类似对分型中包含关系的处理），就可以严格地说，先顶后底，构成向下一笔；先底后顶，构成向上一笔。而所有的图形，都可以唯一地分解为上下交替的笔的连接。显然，除了第二种情况中的第一个顶或底类似的分型，其他类型的分型，都唯一地分别属于相邻的上下两笔，是这两笔间的连接。用一个最简单的比喻，膝盖就是分型，而大腿和小腿就是连接的两笔。

本次依据CC实际仓库的只读快照，HEAD `374268381a3eaeee4d220e67d63364b3907405f4`，2026-11-09复制，捕获时clean，来源与SHA-256已保存。[8] 不沿用旧网站快照的版本声明，不把CC项目变体写成缠论作者原话，也不据此替TDS选择口径。没有导入或执行CC代码。

### B.2 — 首笔候选、标准三道门与同型延伸

**首笔不是随便连接最早两分型。** 内部保存`_bis`和`_candidates`。尚无笔时，每来一个分型，按候选保存顺序扫描所有异型候选；首个通过标准三门的配对成为首笔并清空候选。都不通过便把当前分型也存入候选（155–163行）。首笔只尝试标准，未调用强势补救或repair。

**已有笔时的分支优先级。** 若新分型与末笔终点同型，直接尝试更极值延伸并返回；否则先尝试标准成反向笔，失败才试强势模式，再失败才在开关开启时试修正（136–153行）。同型顶只在更高时替换，底只在更低时替换；相等不替换，不重跑距离／端点门，也不回查修正（202–212行）。这说明“看到相反分型”与“已形成有效反向笔”不同。

标准三道门按顺序短路（277–288行）；下列前两项是距离门的两种模式，之后才是端点门与极值门：

1. **类型／距离。** 同型直接失败。`merged_center`用`end.index-start.index`；不足阈值且允许缺口折算，才遍历中心之间的相邻合并单元。缺口按每个单元对应的原始成员高低外包络算，严格满足`max(a_lo,b_lo)>min(a_hi,b_hi)`才加1，不按跳空金额加根数（291–329行）。
2. **新笔原始极值计数。** `raw_extreme`先要求`start.index+1 < end.index-1`（三根窗口不共用），再在起终中心单元的原始成员中找极值下标，相同极值取最早成员，检查原始下标差至少阈值（309–338行）。它不是简单把中心合并下标差改成3，也不在此路叠加缺口。
3. **端点有效性。** `none`跳过；`loss/half/strict/totally`选择不同的分型窗口部分。以向上`half`为例：起点中心low必须小于终点前根／中心low之min，终点中心high必须大于起点中心／后根high之max；向下用对应反向条件。`totally`要求相应价区完全分离（341–372行）。这些参数细节不是分型识别本身。
4. **端点极值。** 若`bi_require_peak`开启，向上要求起终中心之间所有high不超过终点顶；向下要求所有low不低于终点底，比较允许相等（374–379行）。实现没有在此额外检查起点是否也是整段最极值，不能扩大为“两端所有极值都已检验”。

### B.3 — 强势、修正、依赖水位与输出

**强势补救（166–197行）。** 幅度为两端选定顶底价的绝对差。先比当前候选幅度是否至少ratio×前一笔幅度；成功便追加。否则沿后方分型有界查找首条从当前终点起可标准成笔的反向笔，再比该后笔幅度；不会递归用强势笔验证后笔。依赖下标分别记当前终点或实际查到的后方端点，这一look-ahead不能伪装成候选当时已知的信息。

**项目修正（214–269行）。** 要至少已有两笔；先检查当前反向分型是否击穿反弹笔起点、反弹终点是否未反越前笔起点，以及前笔起点到该新极值的peak条件。通过后仍需向后扫描确认：若先越过反弹终点的极值，才视作假反弹并吸收；若先从反弹终点形成标准反向笔，或扫到末尾仍不充分，则保留旧结构。实际处理是弹出末笔并延伸前笔；若延伸没有改变端点，就把弹出的笔放回。最终依赖水位包含后方确认位置。不能只根据docstring“修正”二字就宣称能即时稳定回退所有历史。

**confirmed与provisional（57–79行）。** `bi_confirmed_flags`以每笔trace依赖水位、合并单元总数和末两笔位置计算：末笔恒provisional；缺依赖或`dep >= n_merged-2`者provisional；若末笔依赖仍不稳定，倒数第二笔也provisional。这是CC工程稳定性判据，不是作者对完成一笔的原文定义，也不是单看终点时间。

**finish与追溯（389–419行）。** 工作状态转为不可变Bi：由终点分型定方向；向上价为起底→终顶，向下起顶→终底；trace记录实际成笔rule ID、profile、config hash、中心合并下标闭区间和dep。来源时间包络扩大到`merged[start.index-1].start_ts…merged[end.index+1].end_ts`，包含两端分型的侧翼；几何端点时间仍是中心分型timestamp。Bi显示ID为`bi-{start_ts}-{end_ts}`（models.py:164–184），和TDS拟议整数ID不同。[9][11]

### B.5 — 相等、缺口／新笔分支与末端修订

**相等同型候选。** 将主例M16.high从18改为17，同时其他输入不变，T16仍可能作为原始顶分型（它严格高于邻根），但与较早T12顶价相等。`_extend_same_fx`要求严格更高，因此不替换T12，依赖仍12；这与A.3“相等先保留”的原文不能机械混称为完全同一实现。此处是另一个场景，不改主例数据。

**门禁分支的小例子（与主序列分开）。** 中心差3时，`merged_center`若在其间恰有1个代码所定义的严格原始价区缺口且开关开启，距离可以折算为4；这只通过距离门，端点／peak仍要继续。`raw_extreme`中，起终中心在2与5时，其三元窗口`[1,3]`及`[4,6]`不共用；若两个中心单元极值原始下标为4与8，则差4可过，若是4与7则差3失败。两个中心单元含多根原始成员时必须用成员里的极值位置，不能凭合并下标差推断结果。上述是条件算术示例，没有构造完整可达CC行情，也没有冒称运行样本。

**同时间R21修订。** 将主例最后单根R21由`[5,9]`改为`[2,6]`，原始根数仍22；M20不再是底，B20消失。引擎先更新末根、回退／重加合并器、增加版本，再从当前合并／分型列表重派生笔（engine.py:244–270、299–323）。[12] 剩余分型到T16为止，结果只剩首笔T4→B8和延伸后的B8→T16，不能保留旧的T16→B20当作已确认历史。此为下图快照；本例每根仍各自成合并单元，没有把“同时间修订”误当新追加。

**稳定性账本。** 未修订主例`n_merged=22`，dep=[8,16,20]，末dep20≥22−2，所以第三笔和倒数第二笔均provisional，第一笔confirmed。若只在末端继续上行追加M22=`[7,11]`、M23=`[9,13]`而没有新反向分型，则n=24、末dep20<22，第二笔可转confirmed，但末笔仍provisional。这仅按flags函数手算，不是运行后的引擎状态承诺。

### B.6 — 补查实际生效配置、强势绕过、修正取等与追溯限制

**生效配置。** `build_bis()`首先调用`cfg.normalize()`；`config.py:203–222`对named profile从完整预设取笔参数，只有`CUSTOM`保留调用者自由组合。因此“给bi_5k对象另填一个ratio／min_span”不保证该值进入执行分支；原B.1表列的是归一化后的值。`profile_id`／`config_hash`仍是调用者传给`finish()`的字符串，`build_bis()`没有用实际生效配置重算这两个实参；正常引擎怎样生成它们与helper本身是否校验匹配须分开。[9][10] 本入口也没有重新核对分型index是否属于这份确切merged／raw来源、列表时序和全部价格是否合法；正常调用链的前提不能自动算成helper自身的验证。

**强势的实际豁免。** 标准三门失败后，`_try_strong()`只比较候选幅度与相邻反向笔幅度；满足前笔或后笔条件便直接`_append()`，没有再把失败的距离、端点或peak门重新要求一遍。前笔优先，只有前笔不够才查后笔。`_lookahead_next_std_bi()`从当前位置扫描到当前分型数组末尾，取首个异型且标准成笔的反向候选；所谓“有界”是当前有限数组边界，没有额外固定K数／时间的前看上限。不能把它说成固定时间的实时操作。[9]

**修正首关与取等。** `_repair_sub_peak()`的起点破坏检查用`<`／`>`作失败条件，因此“刚好到达旧起点”并不在首关立即排除；但最后延伸仍要求严格新极值，若对象没变就恢复弹出的笔。`_confirm_reverse_break()`确认越过反弹端点也用严格`>`／`<`，取等不确认；候选／后方证据的先后顺序不可交换。repair中的`_is_peak()`始终执行，不因自定义配置关闭普通`bi_require_peak`而跳过。[9]

**来源与原因记录。** `source_to_ts`只扩到几何终点分型的右侧翼；strong_next／repair读到更晚证据时，额外水位由`dep_to_index`保存，并不自动把时间包络一直扩到该证据。`_extend_same_fx()`只改终点和dep，没有重写原`rule_kind`；所以被修正／同型延伸的笔仍可保留最初standard或strong规则ID。这个ID不能单独重建后来修正的完整原因链。`finish()`的high/low直接取起终几何价格，不重新遍历所有来源成员求生命周期外包络；也总构造trace，未读取`cfg.trace_enabled`，关闭观测配置不等于本helper不再产生这些字段。[9]

### B.7 — 从同一来源底稿补足强势与修正的完整条件链

以下四种是**彼此独立的教学输入场景**，都从B.4原始范围表出发，未导入或运行CC。所有合并单元均只含对应原始成员`Mi=Ri`，相邻无包含，时间依次为`t_i`；未列出的下标保持B.4原值，给定终点后的右邻包含在各自输入前缀中。算术脚本独立核对所有原始分型、零缺口、距离、half与peak前提，不把人为预置的内部状态冒充完整行情输出。

| 场景 | 与B.4底稿不同的原始范围；当前最后下标 | 形成的分型（序号／极值价） |
|---|---|---|
| strong_prev | M15=[5.5,14]；输入到M16 | B1=6、T4=16、B8=5、T12=17、B15=5.5 |
| strong_next | M15=[7,12]，M16=[9,13]，M17=[10,14]，M18=[11,15]，M19=[12,16]，M20=[9,12]；到M20 | B1=6、T4=16、B8=5、T12=17、B15=7、T19=16 |
| repair接受 | M12=[14,15.5]，M15=[4,14]；到M17 | B1=6、T4=16、B8=5、T12=15.5、B15=4、T16=18 |
| repair拒绝 | M12=[14,15.5]，M15=[4,14]，M16=[12,15]，M17=[8,12]，M18=[3,9]，M19=[6,11]；到M19 | B1=6、T4=16、B8=5、T12=15.5、B15=4、T16=15、B18=3 |

**强势前笔。** 固定归一化named `bi_strong`，ratio=0.95。开始仍由标准门建立T4→B8和B8→T12；T12→B15中心差3且零缺口，标准失败。候选幅度`17−5.5=11.5`，前笔幅度`17−5=12`，`11.5>=0.95×12=11.4`成立，立即追加17→5.5，rule=`strong_prev`、dep=15，不再查后笔。原始底分型B15要到M16出现才具备右侧信息，dep下标15不是最早可知的原始时间。

**强势后笔。** 同样使用named `bi_strong`。到B15时，候选17→7的幅度10不够11.4，标准距离3仍失败；look-ahead找到首个从B15标准成笔的T19：中心差4，half为`7<min(11,12)`且`16>max(12,13)`，中间high不超过16，后笔幅度9。`10>=0.95×9=8.55`成立，追加17→7，rule=`strong_next`、dep=19；正常扫描随后到T19再按标准追加7→16。若输入只到M16而没有T19候选，strong_prev、strong_next与repair均不通过，这条17→7尚不能输出。完整M20快照中的几何终点`t15`、时间包络到右侧翼`t16`、依赖19、及T19要等右邻M20才可识别是四件事，不能都标成t15时已确认。

![强势前笔／后笔两个独立输入：同价格轴与来源轴，后笔条件明确依赖19](memoWX_020_Chan_bi/cc-stroke-strong-recheck.png)

**repair接受。** 固定默认named `bi_5k`（standard且repair开启），先得到16→5和5→15.5。B15=4到来时，15−12=3且零缺口，标准失败；`4<=5`、反弹终点`15.5<=16`，前笔起点T4到B15之间所有low≥4，修正前提成立。未来先见T16=18严格超过反弹顶15.5，守卫返回确认下标16；弹出5→15.5，原向下笔终点从B8的5延伸到B15的4，最后得到16→4、dep=max(8,15,16)=16。来源中心范围[4,15]、侧翼时间`t3…t16`，而T16候选依赖原始M17；原standard规则ID被保留，不能据它看出这次吸收动作。
