# MergedKline family implementation plan
## 000 — Scope
Plan `MergedKline` and `MergedKlineSeries` from memo015’s definitions, algorithm tree, helper contracts and pseudocode.[1] Follow memo013’s plan, comparison, results and interface format.[2] Use memo009’s proposed class design.[3] **Status: plan only; implementation has not started.**
## 001 — Implementation plan
Use the existing immutable `KlineTSeries` and sample data prepared for memo013; preserve original data and provenance.
### 001.a — Implement the MergedKline family
1. Keep immutable records and shared inclusion processing in `src/chanlab/algo/`; keep adapters and rendering separate.
2. Implement memo009’s record fields: integer `id`, `low`, `high`, `direction`, `source_start`, `source_stop`, `status` and `confirmed_at`. Agree status and confirmation semantics before assigning values.
3. Retain the exact raw source object, immutable result tuple/configuration, versioned rule reference and agreed trace mapping. Provide automatic validation, length, iteration, indexing/slicing and ID lookup.
4. Translate memo015’s sequential processing: inclusive containment in either orientation, upward maxima/downward minima, and a new unit on strict noninclusion. Keep raw index, result position and ID distinct.
5. Preserve complete, continuous, nonoverlapping half-open source ranges. Completed output must be nonempty and adjacent records must have no inclusion, including equal boundaries; nonadjacent inclusion is allowed.
6. Support explicit `UP`, `DOWN`, `BOTH`, `OUTER` and `UNSET` initialization as specified in015; select no default. Preserve pending behavior and independent dual paths, with the upward path as BOTH’s main output. Difference metric and warning threshold remain pending.
7. Anchor display at `source_start` and its first raw timestamp; keep extrema and confirmation/availability time separate.
8. Agree configuration, pending/dual-path return shape and trace/explanation schema before implementing public signatures. Do not fill the deferred DecisionStep design implicitly.
9. Defer ChanTable registration, DataFrame/CSV interchange and later feature detection. Plotting is a separate optional extension.
### 001.b — Repeat the implementation using Python Pro
1. Freeze the baseline before reading the installed Python Pro skill.[4]
2. Repeat the same agreed interfaces, data and acceptance checks.
3. Preserve both versions in `artifacts/mas/merged-kline-family/`; record the exact invocation request and skill version in the execution task.
### 001.c — Compare the two implementations
1. Run identical synthetic fixtures and full data with identical explicit initialization settings.
2. Compare rule compliance, source coverage, immutability, pending/dual-path behavior, validation, explanation quality, readability and dependencies.
3. Preserve both versions and a comparison with selection reasons. Record prior skill exposure and iterative corrections without claiming a causal skill-only effect.
### 001.d — Test the MergedKline family
1. Cover single-bar input, strict up/down movement, both containment orientations, equality, equal boundaries and repeated inclusion.
2. Reproduce memo015 section002.b’s worked examples and sequential-processing counterexample.
3. Check every initialization choice, unresolved EOF, independent dual-path state and deterministic results. Warning checks depend on the agreed metric/threshold.
4. Check finite ordered prices, integer-ID uniqueness, source bounds, complete coverage and adjacent noninclusion; include valid nonadjacent inclusion.
5. Check source identity/immutability, sequence access, range mapping, first-member display time and agreed trace alignment.
6. Run the complete sample with recorded configuration/rule version; save results and verification in `artifacts/mas/merged-kline-family/`.
7. Run focused and existing regression tests plus report-only Ruff. Record actual commands, results, blockers and deferred work in `mas/tasks/`.
