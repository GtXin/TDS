# Fenxing family implementation plan
## 000 — Scope
按照 memo026 的结构安排分型实现：[1] 以 memo009 的 `Fenxing`／`FenxingSeries` 接口为边界，[2] 以 memo019 的定义版本二和002.a判断树为算法依据。[3] 本文仅设立计划，不执行算法编码。memo019尚未实现，002.b–002.d仍为空；这不妨碍先安排接口、实现顺序与验收，细节补齐后再冻结执行合同。
## 001 — Implementation plan
复用 memo013 的原始K线加载流程和 memo026 的完整 `MergedKlineSeries`，保留原始数据、上游配置和规则版本。执行前在 `mas/tasks/` 记录确切输入、允许修改路径、规则版本和共同验收条件。
### 001.a — Implement the Fenxing family
1. 在 `src/chanlab/algo/fenxing.py` 实现恰好两个不可变领域类；采用003所列成员和方法，不新增通用追踪类。
2. 将 memo019 的输入检查、相邻方向、窗口分类、原始锚点定位、保存及结果校验封装为 `FenxingSeries` 的私有方法。先补齐或核定019的数值例子、helper合同和伪代码，再固定具体私有签名。
3. 只接受完整且校验通过的确切合并序列；待定结果和双路包装不自动转空结果或代选路径。少于三根合法输入返回空分型序列，仍保留原因与来源。
4. 从中心下标1扫描至N−2，用价格重新计算两侧严格方向；上升转下降输出top，下降转上升输出bottom，单调窗口只记录依据。保留所有几何分型，允许窗口重叠；不做笔端点取舍。
5. 分型窗口为合并位置 `[i−1,i+2)`；顶取中心high、底取中心low。只在中心合并单元的原始成员内定位对应极值，默认最早匹配，可显式配置最晚匹配；无匹配报错，不加临时容差。
6. 输出ID从0递增，与合并ID和位置分开；保存确切来源、冻结配置、规则引用、全部窗口trace及每条输出的trace下标。初期沿019使用 `unconfirmed`／`None`，不把中心时间或右邻出现直接定义成确认时间。
7. 核心选定后，通过类方法及适配器扩展 ChanTable 注册／检索和紧凑DataFrame导出；将合并窗口投影到原始轴，锚点落在实际原始极值位置，保留其他特征注册及原始数据。
8. 核心与表集成通过后再安排绘图：复用既有显示轴与市场配色，区分几何中心、原始锚点与确认时间；新增调用选项须单列，不作为已存成员。
### 001.b — Repeat the core implementation using Python Pro
1. 完成无本轮技能指导的基线，冻结源码、共同测试、运行结果及哈希至 `artifacts/mas/fenxing-family/baseline/`。
2. 执行时逐字记录技能调用请求，读取 `mas/skills/python-pro/SKILL.md` 并记录实际来源／版本；本次计划未调用技能。[4]
3. 使用完全相同接口、规则、输入与验收集重复核心实现，独立保存到 `artifacts/mas/fenxing-family/python_pro/`。
4. 披露既往技能接触及后续修正；这是顺序工程比较，不作技能因果效果结论。表集成与绘图扩展另记。
### 001.c — Compare and select the core implementation
1. 在隔离进程用同一最终测试集运行两个冻结版本，核对实际导入路径并保留失败证据。
2. 比较接口覆盖、019规则一致性、来源身份、两层下标、同价锚点、不可变性、空结果、trace完整性、错误处理、类型与可读性。
3. 保存比较、命令与哈希至 `artifacts/mas/fenxing-family/`，说明选择理由和审阅修正。
4. 对现有完整数据及明确的上游配置计算，记录实际原始／合并／分型数量和版本；不以数量比例推断正确性。
### 001.d — Test the Fenxing family
1. **对象合同：** 自动校验、非法ID／kind／价格／下标、冻结嵌套状态、序列访问／切片／迭代、ID检索及缺失KeyError。
2. **窗口规则：** 顶、底、连续升降、1／2根、恰好3根、末端无右邻、重叠候选；等边、包含或方向不合法输入应报错。
3. **来源与锚点：** 合并ID不等于位置、多个原始成员、同价首／末匹配、无极值匹配、越界／错误来源、三根窗口及中心时序。
4. **依据与状态：** 无输出窗口仍有trace；输出映射非空且有效；空items允许非空trace；规则版本可追溯；不伪造确认。尾部修订后对新上游快照重算，旧结果保持不变，不承诺增量回退接口。
5. **例子与全量：** 将019最终数值例子转成共同验收；附录CC案例只能作为明确标注的对照，不直接替代TDS规则。核对源文件和原始对象未变。
6. **质量：** 运行聚焦测试和现有回归测试、Ruff报告检查，记录严格mypy、Black检查及改动模块coverage的实际结果，不复制026的历史通过数。
7. **扩展：** 单独检查表注册身份／上下文、窗口及锚点映射、未计算NA与计算为空的区别；绘图扩展需检查区间、配色、悬浮信息、Figure／HTML和代表图视觉效果。

## 003 — Planned classes, members and methods
### 003.a — Class count and scope
计划实现2个类；本节为拟议接口，尚未实现。沿用009，不将配置选项或适配器作为额外领域类。
### 003.b — Fenxing
**存储成员（8个）：** `id`、`kind`、`price`、`anchor_raw_index`、`source_start`、`source_stop`、`status`、`confirmed_at`。含义与类型沿用009；source范围指向合并序列，anchor指向其原始来源。

**方法：** `__init__(...)` 初始化并自动校验；`validate()` 校验本地字段。跨来源的窗口、极值和锚点一致性由所属series校验。
### 003.c — FenxingSeries
**存储成员（6个）：** `source_series`、`items`、`config`、`rule_tree_ref`、`trace`、`trace_by_point`。保留确切上游引用，结果与嵌套配置／依据不可变。

**核心方法：** `__init__(...)`、`validate()`、类方法 `derive_from(source_series, config, rule_tree_ref)`、`__len__()`、`__getitem__(key)`、`__iter__()`、`get_by_id(feature_id)`、`explain(point_index)`。

**集成方法：** 类方法 `from_chan_table(table, series_key)`、实例方法 `to_chan_table(table, series_key)`、`to_dataframe()`；通过适配器实现格式转换。绘图方法签名待核心选定后另定。

**私有方法：** 输入／规则检查、相邻方向计算、三根分类、原始锚点定位和trace组装按019分工；签名待019 helper合同核定，不作为公共API。
### 003.d — Object workflow and implementation boundary
拟议流程：`KlineTSeries.read_csv(...)` → `MergedKlineSeries` 的既有计算入口（显式上游策略）→ `FenxingSeries.derive_from(...)` → `explain(...)`／表集成。输入必须是选定的完整合并结果；几何分型输出供后续笔算法使用。
