## 001 — Implementation plan
复用 memo013 的原始K线加载流程和 memo026 的完整 `MergedKlineSeries`，保留原始数据、上游配置和规则版本。执行前在 `mas/tasks/` 记录确切输入、允许修改路径、规则版本和共同验收条件。
### 001.a — Implement the Fenxing family
1. 在 `src/chanlab/algo/fenxing.py` 实现恰好两个不可变领域类；采用003所列成员和方法，不新增通用追踪类。
2. 将 memo019 的输入检查、相邻方向、窗口分类、原始锚点定位、保存及结果校验封装为 `FenxingSeries` 的私有方法。先补齐或核定019的数值例子、helper合同和伪代码，再固定具体私有签名。
3. 只接受完整且校验通过的确切合并序列；待定结果和双路包装不自动转空结果或代选路径。少于三根合法输入返回空分型序列，仍保留原因与来源。
4. 从中心下标1扫描至N−2，用价格重新计算两侧严格方向；上升转下降输出top，下降转上升输出bottom，单调窗口只记录依据。保留所有几何分型，允许窗口重叠；不做笔端点取舍。
5. 分型窗口为合并位置 `[i−1,i+2)`；顶取中心high、底取中心low。只在中心合并单元的原始成员内定位对应极值，默认最早匹配，可显式配置最晚匹配；无匹配报错，不加临时容差。
6. 输出ID从0递增，与合并ID和位置分开；保存确切来源、冻结配置、规则引用、全部窗口trace及每条输出的trace下标。初期沿019使用 `unconfirmed`／`None`，不把中心时间或右邻出现直接定义成确认时间。
7. 核心选定后，通过类方法及适配器扩展 ChanTable 注册／检索和紧凑DataFrame导出；将合并窗口投影到原始轴，锚点落在实际原始极值位置，保留其他特征注册及原始数据。
8. 核心与表集成通过后再安排绘图：复用既有显示轴与市场配色，区分几何中心、原始锚点与确认时间；新增调用选项须单列，不作为已存成员。
### 001.b — Repeat the core implementation using Python Pro
1. 完成无本轮技能指导的基线，冻结源码、共同测试、运行结果及哈希至 `artifacts/mas/fenxing-family/baseline/`。
2. 执行时逐字记录技能调用请求，读取 `mas/skills/python-pro/SKILL.md` 并记录实际来源／版本；本轮执行已读取并应用技能，接触顺序见002.b。[9]
3. 使用完全相同接口、规则、输入与验收集重复核心实现，独立保存到 `artifacts/mas/fenxing-family/python_pro/`。
4. 披露既往技能接触及后续修正；这是顺序工程比较，不作技能因果效果结论。表集成与绘图扩展另记。
### 001.c — Compare and select the core implementation
1. 在隔离进程用同一最终测试集运行两个冻结版本，核对实际导入路径并保留失败证据。
2. 比较接口覆盖、019规则一致性、来源身份、两层下标、同价锚点、不可变性、空结果、trace完整性、错误处理、类型与可读性。
3. 保存比较、命令与哈希至 `artifacts/mas/fenxing-family/`，说明选择理由和审阅修正。
4. 对现有完整数据及明确的上游配置计算，记录实际原始／合并／分型数量和版本；不以数量比例推断正确性。
### 001.d — Test the Fenxing family
1. **对象合同：** 自动校验、非法ID／kind／价格／下标、冻结嵌套状态、序列访问／切片／迭代、ID检索及缺失KeyError。
2. **窗口规则：** 顶、底、连续升降、1／2根、恰好3根、末端无右邻、重叠候选；等边、包含或方向不合法输入应报错。
3. **来源与锚点：** 合并ID不等于位置、多个原始成员、同价首／末匹配、无极值匹配、越界／错误来源、三根窗口及中心时序。
4. **依据与状态：** 无输出窗口仍有trace；输出映射非空且有效；空items允许非空trace；规则版本可追溯；不伪造确认。尾部修订后对新上游快照重算，旧结果保持不变，不承诺增量回退接口。
5. **例子与全量：** 将019最终数值例子转成共同验收；附录CC案例只能作为明确标注的对照，不直接替代TDS规则。核对源文件和原始对象未变。
6. **质量：** 运行聚焦测试和现有回归测试、Ruff报告检查，记录严格mypy、Black检查及改动模块coverage的实际结果，不复制026的历史通过数。
7. **扩展：** 单独检查表注册身份／上下文、窗口及锚点映射、未计算NA与计算为空的区别；绘图扩展需检查区间、配色、悬浮信息、Figure／HTML和代表图视觉效果。

## 003 — Implemented classes, members and methods
### 003.a — Class count and scope
实现2个领域类，全部定义在 `src/chanlab/algo/fenxing.py`；适配器及绘图为独立函数，不新增领域类。配置、记录、trace及嵌套结构均冻结。
### 003.b — Fenxing

| 存储成员 | 含义 |
|---|---|
| `id: int` | 结果版本内非负整数ID；工厂从0分配。 |
| `kind: str` | top或bottom。 |
| `price: float` | 顶的中心high或底的中心low，有限数值。 |
| `anchor_raw_index: int` | 中心原始成员中匹配极值的实际位置。 |
| `source_start: int` | 三根窗口的首个merged位置。 |
| `source_stop: int` | 窗口的排他末位置，必须等于start+3。 |
| `status: str` | 本版仅unconfirmed。 |
| `confirmed_at: datetime / None` | 本版仅None，不推断确认时间。 |

**方法：** `__init__(...)` 经dataclass的 `__post_init__()` 自动调用 `validate()`；局部校验字段，跨来源与结果完整性由series校验。
### 003.c — FenxingSeries

| 存储成员 | 含义 |
|---|---|
| `source_series` | 确切完整MergedKlineSeries引用。 |
| `items` | 按中心时序保存的Fenxing元组，可为空。 |
| `config` | 规范化不可变映射，仅anchor_tie=FIRST／LAST。 |
| `rule_tree_ref` | 非空规则位置／版本，由调用方显式提供。 |
| `trace` | 每个完整窗口一条不可变依据；不足三根时一条原因。 |
| `trace_by_point` | 每条分型对应其窗口trace下标单元素元组。 |

| 方法 | 行为 |
|---|---|
| `__init__(...)`／`validate()` | 冻结输入并自动校验上游、完整分型、来源及依据，不修补结果。 |
| `derive_from(source_series, config, rule_tree_ref)` | 类方法；完整窗口扫描，不接受pending／dual包装。 |
| `__len__()`／`__iter__()`／`__getitem__(key)` | 标准位置访问、负下标、迭代；切片返回tuple。 |
| `get_by_id(feature_id)` | 结果内整数ID检索；缺失KeyError。 |
| `explain(point_index)` | 按结果位置说明规则、左右方向、价格／来源窗口、匹配数量／首尾／策略及上游版本。 |
| `from_chan_table(table, series_key)` | 类方法；返回确切注册对象。 |
| `to_chan_table(table, series_key)` | 返回新表，保留原表和其他注册；必要时注册确切上游。 |
| `to_dataframe()` | 返回独立紧凑8列表及版本／来源attrs。 |
| `plot(...)` | 返回Figure，由调用方显示或导出。 |

**私有方法：** 沿019的 `_normalize_config`、`_direction_between`、`_classify_window`、`_resolve_anchor`、`_validate_result`；另用 `_window_evidence`／`_short_evidence` 组装局部依据，`_same_evidence` 严格复核递归数据类型。处理及验证的时间为O(M+N)，存储为O(M+F)，其中M为合并数、N为原始数、F为分型数；锚点扫描不创建原始切片或匹配列表。包含上游validate成本，不将DataFrame／表元数据编码算入纯扫描复杂度。

**绘图调用选项（不存储）：** `raw_start=None`／`raw_stop=None`选原始位置范围；`volume=True`；`title=None`；`show_gaps=False`；`market="US"`或China。空视窗报错；空分型结果仍可显示原始／合并图。
### 003.d — Object workflow and implementation boundary
`KlineTSeries.read_csv(...)` → `MergedKlineSeries.derive_from(...)`（显式初始化）→ `FenxingSeries.derive_from(...)` → 解释／图／表。source范围指merged位置，anchor指raw位置；合并ID和分型ID不充当位置。几何分型可供后续笔层使用，本层不承诺笔端点有效性。
### 003.e — Usage examples
从仓库根目录运行（`PYTHONPATH=src .venv/bin/python`）：

```python
from pathlib import Path
from chanlab.algo.kline import KlineTSeries
from chanlab.algo.merged_kline import MergedKlineSeries
from chanlab.algo.fenxing import FenxingSeries
from chanlab.algo.chan_table import ChanTable

sample = Path("samples/chan_table")
raw = KlineTSeries.read_csv(next(sample.glob("*chan_table*.csv")),
                           next(sample.glob("*context*.csv")))
merged = MergedKlineSeries.derive_from(
    raw, {"initialization": "UP"}, "memo015:002:v1")
assert isinstance(merged, MergedKlineSeries)  # 其他输入可能为pending/dual
fx = FenxingSeries.derive_from(merged, {}, "memo019:002:v1")
print(len(fx), fx.explain(0))
frame = fx.to_dataframe()
table = fx.to_chan_table(ChanTable.from_source_series(raw, raw.context), "fenxing")
assert FenxingSeries.from_chan_table(table, "fenxing") is fx
fig = fx.plot(raw_start=len(raw)-80, market="China")
# fig.show() / fig.write_html(...)，调用方选择输出位置。
```

全量数据、配置、来源保护、oracle及表重载的复现脚本为[verify_full.py](../../artifacts/mas/fenxing-family/verify_full.py)；精确工具环境和命令见[执行任务](../../mas/tasks/20261109-memo027-execution.md)。
