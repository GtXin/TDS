当前结果：406项回归、20项Bi定向测试通过，新增算法／表／绘图模块合计语句覆盖94%；strict mypy、Black、Ruff通过。10,000条随机原始OHLCV经既有Kline→MergedKline→Fenxing→Bi，得到6,441根已提交笔、5,289条未完成缓存，零独立定义／参考差异。完整真实数据得到24根已提交笔＋1根未完成缓存；后续大量行情仍未决，不表示完成整段行情划笔。

## 001 — Implementation plan
### 001.a — Implement the Bi family
1. 使用src/chanlab/algo/bi.py中的两个不可变领域类。BiSeries.items只保存已提交R；scan报告另存未完成缓存Bi002、待定起点、下一读取位置及未决范围，不增加领域类。
2. 初次扫描以首个完整分型为待定起点；同型更极端才替换起点。同价／较弱保留原起点；异型检查首笔距离及终点侧极值。
3. 已有缓存后：较弱同型略过；同价／更极端仅查新增段两界；失败保持缓存与R不变继续读。反向通过距离及双侧极值检查后，只提交旧缓存的独立端点值，再滚动新缓存。
4. EOF不把缓存加入R。输出以001六项定义独立复核，已提交不等于市场永久确认。
5. 追加输入保留原R／缓存／待定起点和cursor；先核对原始、合并、分型及来源上下文前缀一致性。上游改写历史或状态伪造则报错，不静默重用缓存。
6. 表／DataFrame只导出R；图中R为实线，显式传入的缓存为虚线。保留此前注册结果与原始数据。
### 001.b — Repeat and review using Python Pro
冻结本轮baseline及共同测试，再按已读Python Pro1.1.0续作类型／状态／trace校验，保存python_pro快照。此前已接触技能；比较是顺序工程比较。任务保留用户原始调用请求。
### 001.c — Compare and select
两个冻结版本以独立进程运行相同200组输入，比较完整R、缓存、待定起点及cursor；核对实际导入路径／哈希。选择加强决策证据校验的续作，不按笔数量选择版本。
### 001.d — Tests and integration
覆盖首笔、同价／更极端延伸、失败保持状态、反向提交、EOF空输入／单分型／缓存、追加无新分型、前缀修订拒绝、记录只增不改、表往返及缓存分离。运行定向与回归pytest、覆盖、严格类型及样式检查；图片目视核对。
### 001.e — Monte Carlo validation
1. 从随机原始OHLCV起步，实际调用KlineTSeries→MergedKlineSeries→FenxingSeries，再执行Bi.scan，不直接随机生成分型或笔端点。
2. 至少10,000条序列，固定种子及长度分层，覆盖趋势、震荡、跳空、包含／等值、单价与变宽；额外探测初始化／锚点选项及价格变换。
3. 独立参考每次直接检查完整端点范围，不复用被测算法的简化helpers；比较R、缓存、待定起点和cursor。对R及缓存逐笔检查六项定义、共享端点及交替方向，检查每步R前缀不变、失败缓存不变和EOF不提交。
4. 出现异常、定义／参考差异时保存完整输入、种子、规则和配置，画可用的原始／合并／分型／Bi及失败位置并通知用户；不为消除反例擅改规则。合法开放缓存、无首笔与旧版blocked结果分开统计，不宣称所有行情都已划笔。
## 002 — Implementation notes and results
### 002.a — Current API and algorithm
[bi.py](../../src/chanlab/algo/bi.py)实现020滚动协议。私有方法包含_check_first、_compare_same_kind、_check_extension、_check_reverse、_check_state、_validate_output；完整定义检查另由_check_pair提供。首笔及延伸采用020的分支简化，输出仍用完整定义检查。

scan(source, rule_tree_ref, previous=None)返回只读报告：series为R，working为独立未完成Bi或None，cache_pair为来源分型位置对，pending_start为Bi001S，next_position为下一读取位置，unresolved_merged为半开合并范围。续读重新核对旧输入状态，拒绝伪造cache／cursor或改变规则；不制造EOF确认。
### 002.b — Baseline, skill continuation and selection
[本轮证据](../../artifacts/mas/bi-family/rolling020/)保留previous-bi及previous-test_bi历史、baseline、python_pro、独立进程输出和哈希。两版200组结果一致；续作增加rolling trace规则、提交前缀与cursor证据校验。Python Pro1.1.0已读且此前使用，不能归因技能产生正确性优势。
### 002.c — Tests
20项Bi定向测试和406项活动tests回归通过。旧27项测试属于已替换的候选枚举协议，不能比较总数量判断质量。本轮100组追加实验按17→33→65根原始K线续读，与一次性扫描的R／缓存完全一致；旧R前缀不变。严格mypy检查5个源模块通过，Black／Ruff通过。新算法94%、表适配90%、绘图96%，合计94%语句覆盖。[检查记录](../../artifacts/mas/bi-family/rolling020/coverage.txt)。
### 002.d — Monte Carlo result
种子0–9999，长度9／17／33／49／65，10,000条输入合计345,296原始K线、215,780合并单元、107,194分型；输出6,441根R记录、5,289条独立缓存。6,997条输入的R为空，其中可以已有缓存；不能把空R视作算法失败。额外100条输入×5种初始化×2种锚点，以及300次价格镜像／平移／缩放探测，均由独立参考核对。

零定义违例、零参考差异、无异常；本轮没有需触发失败图的反例。输入生成器、参考和失败捕获在[verify.py](../../artifacts/mas/bi-family/rolling020/verify.py)，[统计](../../artifacts/mas/bi-family/rolling020/monte-carlo/report.json)保留分层及资源信息。旧190个blocked案例及其图只对应旧协议，不再作为本轮失败统计。
### 002.e — Full-data result and limitation
完整样本10,060原始K线→6,200合并单元→3,027分型，所有分型均已读取；R有24根笔，未完成缓存为FX148→FX149，下一位置3027。独立完整范围参考一致；R的CSV／context往返一致，原始CSV和context哈希不变。

**明确限制：** 缓存终点后合并范围[306,6200)仍未决，持续遇到不合格候选会正常保留旧缓存，并非整段行情均已描画。当前020允许这种开放尾部；本轮不增加换起点、跳过合格反向或回退重选。若期望持续覆盖该尾部，需要先在020讨论规则。[全量证据](../../artifacts/mas/bi-family/rolling020/full-result.json)。
### 002.f — Integration and persistence boundary
BiSeries表／DataFrame只存R，不把缓存当作最终笔。每个key保留确切Fenxing→MergedKline→Kline来源、配置、规则与trace；固定bi列投影首个注册系列。缓存及续读报告目前为内存状态，表CSV不是缓存检查点。旧候选Bi上下文不兼容新rolling配置，应保留历史并重新计算，不把旧结果当现行结果。
## 003 — Implemented classes, members and methods
### 003.a — Class count and scope
实现2个领域类，均在 `src/chanlab/algo/bi.py`：Bi保存一根笔的不可变端点记录，BiSeries只保存已提交R。表适配及绘图为独立函数，不新增领域类。scan的缓存／续读报告为只读映射，不是第三个领域类。提交R不等于市场永久确认；所有Bi仍为unconfirmed／None。
### 003.b — Bi

| 存储成员 | 含义 |
|---|---|
| `id: int` | 本结果内非负整数ID；R从0分配，独立缓存暂用len(R)，缓存不属于R。 |
| `start_fenxing_index: int` | 确切源FenxingSeries中的起点位置；不是分型ID、合并中心或原始锚点。 |
| `end_fenxing_index: int` | 同一源中的终点位置，必须大于起点位置。 |
| `start_price: float` | 起点分型的有限价格，由series核对来源。 |
| `end_price: float` | 终点分型的有限价格，由series核对来源。 |
| `direction: str` | up或down，须与端点价格升降一致。 |
| `status: str` | 当前仅unconfirmed；是否提交R由所属容器区分，不增加状态含义。 |
| `confirmed_at: datetime / None` | 当前仅None，不用提交时刻或EOF推断市场确认。 |

| 方法 | 行为 |
|---|---|
| `__init__(...)` | dataclass生成；不可变初始化，经__post_init__自动调用validate。 |
| `validate()` | 检查整数ID／位置、端点顺序、有限价格、方向及unconfirmed／None；来源范围与完整成笔定义由series核对。 |

### 003.c — BiSeries

| 存储成员 | 含义 |
|---|---|
| `source_series: FenxingSeries` | 确切完整几何分型对象；沿来源链访问MergedKlineSeries和原始KlineTSeries，不复制原始数据。 |
| `items: tuple[Bi, ...]` | 按时间保存已提交R，可为空；不包含未完成缓存。 |
| `config: Mapping[str, Any]` | 冻结映射，保存protocol=rolling020及R的端点位置route；route是结果元数据，不是调用方路线选择器。 |
| `rule_tree_ref: str` | 调用方明确提供的非空规则位置／版本。 |
| `trace: tuple[Mapping[str, Any], ...]` | 冻结逐候选决策；记录rule和before／after。状态包含当时R端点元组、缓存、待定起点及读取位置。 |
| `trace_by_point: tuple[tuple[int, ...], ...]` | 每条R记录的trace索引元组；当前每条链接整个扫描trace，未压缩为只关联局部决策。 |

| 方法 | 行为 |
|---|---|
| `__init__(...)`／`validate()` | 冻结成员后自动校验；检查来源类型、rolling配置、结果route、决策规则／提交前缀／cursor、每根笔定义、唯一ID、共享端点、方向交替及trace映射。 |
| `scan(source_series, rule_tree_ref, previous=None)` | 类方法；按020初次扫描或续读，返回R、独立未完成缓存及读取状态，不把EOF缓存提交。 |
| `derive_from(source_series, config, rule_tree_ref)` | 类方法；config当前必须为空映射；初次扫描后只返回R。需要缓存和续读时直接使用scan。 |
| `__len__()`／`__iter__()`／`__getitem__(key)` | 标准位置访问、负下标、迭代；切片返回Bi元组；长度只计R。 |
| `get_by_id(feature_id)` | 按结果内整数ID查询；缺失KeyError；不在R中查找独立缓存。 |
| `explain(point_index)` | 返回只读依据：规则、Bi记录、合并中心、原始锚点、决策和R未覆盖合并范围；working恒False。范围针对R，不等于scan包含缓存后的未决范围。 |
| `from_chan_table(table, series_key)` | 类方法；校验表并返回该key确切注册的BiSeries；类型不匹配报错。 |
| `to_chan_table(table, series_key)` | 委托适配器返回新表，仅注册R，保留原始数据及其他注册；必要时注册确切分型／合并来源。 |
| `to_dataframe()` | 返回独立紧凑8列表，attrs保留配置、规则、trace及原始context；不导出缓存。 |
| `plot(**options)` | 返回Figure；基础图含原始K线、合并K线和全部可见分型，再叠加R及显式传入的working。调用方选择显示或导出。 |

**私有方法与自动钩子**

| 方法 | 行为 |
|---|---|
| `__post_init__()` | 将items、配置、trace及索引递归冻结，再调用validate。 |
| `_record(source, i, a, b)` | 从确切分型位置／价格新建独立Bi，避免复用缓存对象改变已提交R。 |
| `_compare_same_kind(source, a, b)` | 在同型前提下返回更弱−1／同价0／更极端1；顶更高、底更低为更极端。 |
| `_check_first(source, a, f)` | 首笔分支已知异型，检查中心距离至少4及F侧全范围极值；起点侧保证来自初始化过程。 |
| `_check_extension(source, a, b, f)` | 在旧A→B已合格且F同型同价／更极端的前提下，只检查(c(B),c(F)]是否落在A／F的新上下界。 |
| `_check_reverse(source, b, f)` | 反向分支复核B→F；当前委托完整_check_pair，包含距离和两侧范围极值。 |
| `_check_state(source, committed, cache, start, cursor)` | 检查读取位置、待定起点、缓存终点=start及R末端与缓存起点连接；无缓存不能有R。 |
| `_check_pair(source, a, b)` | 按完整定义检查时间、异型、中心间隔、端点区间关系和全范围极值。 |
| `_validate_output(source, pairs)` | 对R接上缓存的端点序列逐笔复核完整成笔条件及共享连接。 |

**scan报告字段（返回值，不是BiSeries存储成员）**

| 字段 | 含义 |
|---|---|
| `series: BiSeries` | 已提交R；保留确切输入及规则／trace。 |
| `working: Bi / None` | 独立未完成Bi002；EOF不加入series.items。 |
| `cache_pair: tuple[int, int] / None` | 工作笔的源分型位置对，供续读。 |
| `pending_start: int / None` | Bi001S；有缓存时等于缓存终点；尚无完整分型时为None。 |
| `next_position: int` | 下一未读完整分型位置；本批正常结束时等于源分型数量。 |
| `unresolved_merged: tuple[tuple[int, int], ...]` | 半开合并位置范围；无缓存时为全范围，否则为首端点之前及缓存终点之后。 |
| `status: str` | no_first_stroke或open_cache；不代表市场确认。 |

**调用选项（不存储）：** scan的previous必须是此前scan报告；只允许原始／合并／分型及来源上下文前缀不变的追加，规则改变、cursor／缓存伪造或历史修订会报错。当前通过重扫旧输入复核续读状态，因此不能把增量入口理解成恒定成本续算。

**绘图选项（不存储）：** `working=None`显式传入独立缓存；`raw_start=None`／`raw_stop=None`选择原始位置范围；`volume=True`；`title=None`；`show_gaps=False`；`market="US"`或China。全部可见顶／底分型均显示，未被选为笔端点的也保留；R实线，缓存虚线；空R仍显示上游图。
### 003.d — Object workflow and implementation boundary
`KlineTSeries.read_csv(...)` → `MergedKlineSeries.derive_from(...)`（显式初始化）→ `FenxingSeries.derive_from(...)` → `BiSeries.scan(...)` → R解释／图／表。原始锚点用于绘图和表投影，分型位置用于Bi端点，合并中心用于成笔范围判断；三者不混用。

原始／合并／分型输入须合法且完整；pending／dual包装需调用方先明确选择合法完整来源。R只追加不修改，缓存可以延伸或在合格反向出现后提交；尾部可以未决。CSV／DataFrame只保存R，不能据此恢复独立缓存／cursor；续读使用内存中的完整scan报告。旧候选枚举接口不属于当前实现。
### 003.e — Usage examples
从仓库根目录运行（`PYTHONPATH=src .venv/bin/python`）：

```python
from pathlib import Path
from chanlab.algo.kline import KlineTSeries
from chanlab.algo.merged_kline import MergedKlineSeries
from chanlab.algo.fenxing import FenxingSeries
from chanlab.algo.bi import BiSeries
from chanlab.algo.chan_table import ChanTable

sample = Path("samples/chan_table")
raw = KlineTSeries.read_csv(next(sample.glob("*chan_table*.csv")),
                           next(sample.glob("*context*.csv")))
merged = MergedKlineSeries.derive_from(
    raw, {"initialization": "UP"}, "memo015:002:v1")
assert isinstance(merged, MergedKlineSeries)
fx = FenxingSeries.derive_from(merged, {}, "memo019:002:v1")
state = BiSeries.scan(fx, "memo020:rolling")
committed = state["series"]
print(len(committed), state["working"], state["next_position"])
if len(committed):
    print(committed.explain(0))
frame = committed.to_dataframe()
table = committed.to_chan_table(
    ChanTable.from_source_series(raw, raw.context), "bi")
assert BiSeries.from_chan_table(table, "bi") is committed
fig = committed.plot(working=state["working"], market="China")
# fig.show() / fig.write_html(...)，由调用方选择输出位置。
# appended_fx必须保持原始、合并、分型及来源上下文的原前缀。
# next_state = BiSeries.scan(appended_fx, "memo020:rolling", previous=state)
```
