# Bi family implementation plan
## 000 — Scope and planning status
以[memo029](memoWX_029_Chan_bi.md)的六项定义、问题陈述、动态规划算法树、辅助函数及伪代码为本轮算法依据，替代此前按020滚动缓存的实施计划。保留memo009的Bi／BiSeries设计合同，复用011／013数据、015／026合并、019／027分型及010环境。020和历史实现／实验仅作参考，不沿用旧版R只追加、Bi002滚动及续读状态协议。[1–10]

当前仍为001规划阶段：活动Bi实现、专用适配器／绘图及测试此前已撤出，共享表集成已回退；本次只更新计划，不声称生产实现恢复。029的CC前200分型试算为独立可行性证据（强34笔、弱48笔），不替代本轮正式验收。固定输入快照为首轮范围；跨批提交、永久确认及历史修订策略尚未确定。

## 001 — Implementation plan
### 001.a — Implement the Bi family
1. **冻结合同。** 实施前冻结029版本、强／弱距离和009的Bi／BiSeries字段／状态语义。仅使用两个领域类；搜索数组及报告用普通工作数据，不新增领域类。不将旧scan/Q接口或永久确认字段语义自动带入新方案。
2. **完整配对。** 实现029002.e的来源校验、距离解析、单笔验证。每个端点对检查时间、异型、中心距、端点区间及全部中心闭区间的极值；任何失败仅否决本连线，输入无效则报错。距离默认strong/4，可选weak/3。
3. **动态规划。** 找到存在合法后续连线的最早起点并固定；其best=0，其他点不可达。终点与前驱均按位置递增，仅从可达前驱接入；合法时比较best[p]+1，严格增加才更新best[f]及prev[f]，同笔数保留先找到的记录。
4. **输出路线。** 选择最晚可达终点，沿前驱回溯；独立复核每笔、连接／交替、首尾及笔数。空解返回空路线和全部未决范围；正常结果保留首点以前及末点以后的未决行情，不强连末点。结果属于当前快照的选中路线，不标作永久提交R。
5. **性能。** 先完成可核验的区间扫描基线，再考虑等价的区间极值查询。分别报告预处理、起点搜索、DP、复核、依据及绘图成本；不通过静默截断候选或更换起点加速。保留真实资源超限信息。
6. **集成。** 按009及既有表合同导出选中路线，保留来源／规则／距离和暂定状态，不编造confirmed_at。表／DataFrame往返保持端点与状态；绘图显示原始／合并K线、全部可见分型及选中笔，并标明未决范围。保留已有注册结果和原始数据。
### 001.b — Repeat and review using Python Pro
冻结可运行baseline与共同测试，再依Python Pro1.1.0完成顺序工程复核，保存独立python_pro快照及实际类型／样式／测试结果。复核不更改029目标或以增加笔数替代规则；若缺少依赖，记录缺失及处理，不宣称检查通过。[10]
### 001.c — Compare and select
两个冻结版本在独立进程运行相同200组输入，核对导入路径／哈希，比较起点、终点、笔数、确定性端点序列、模式及未决范围；逐笔依据按共同合同比较。优化版应与基线选择一致；按正确性、可解释性及实际性能选择，不以偏离目标的笔数量选择版本。
### 001.d — Tests and integration
1. 覆盖空／单分型、无合法配对、最早起点不可用时后移、固定起点不可换、末点不可达、前面路线连续、最多笔数竞争及同笔数确定性。
2. 覆盖强4／弱3边界、窗口不重叠、同型、端点区间、区间越界、同价极值及被跳过行情仍参与验证；非法来源与损坏前驱报错。
3. 小输入枚举所有端点子集，按“起点最早→终点最晚→笔数最多”验证DP目标；并列路线另外验证固定遍历规则，不把任一枚举顺序当作唯一正确序列。逐端点对照最多笔数前缀。
4. 定向／回归pytest、覆盖、严格类型及样式检查；完成表／DataFrame往返和绘图目视检查。使用CC样本正式复算前200分型两档并对照029试算；不得用试算成功替代正式实现验证。
5. **CC数据分档验证与计时。** 使用有来源记录的真实CC数据，分别取前100、1000、10000个完整分型，两档独立计算并计时；数量以实际派生的完整分型为准，不以原始／合并K线根数代替。三个规模尽量使用同一标的、周期及数据版本的嵌套前缀，固定上游与算法配置。
6. **分档检查与记录。** 每档独立复核选中笔的六项条件、连续／交替、最早可成笔起点、最晚可达终点及最多笔数；最优性通过独立参考计算核对，不仅检查输出几何合法。记录原始／合并K线数、分型数、起终点、笔数、未决范围、数据哈希、规则版本及运行环境，保存结果和笔图。
7. **计时口径。** 分别记录数据加载、合并／分型派生、区间预处理、起点搜索、DP选路、独立复核及绘图耗时；另报告算法核心耗时与端到端耗时，并明确包含项。使用单调高精度计时器，同环境每档至少运行3次，报告各次及中位数；首次运行与后续运行分开标注，说明缓存与预处理是否复用。记录峰值内存及超时／资源上限，失败不得记为通过。
8. **数据不足。** 当前保留样本为10060根原始K线、3027个分型，不能完成10000分型档。执行时先查找更长的真实CC数据并保留来源；若仍不足，明确记录该档未执行、实际可用数量及缺口，不重复拼接、伪造分型或将10000根K线冒充10000分型。
### 001.e — Monte Carlo validation
1. 随机原始OHLCV实际经KlineTSeries→MergedKlineSeries→FenxingSeries，再运行新DP；不只随机生成端点。
2. 至少10,000条序列，固定种子及长度分层，覆盖趋势、震荡、跳空、包含／等值、单价与变宽，两档分别统计；额外探测合法的初始化／锚点选项及价格变换。
3. 独立参考直接扫描完整区间，不复用被测配对helpers。短输入用完整子集枚举检查选路最优性，较长输入用独立参考与逐笔扫描；明确各层验证范围与资源限额。核对每个可达端点的最多笔数、最早起点、最晚终点及输出路线，不能只检查笔本身合法。
4. 异常、定义／参考差异或资源超限均保存完整输入、种子、配置和版本，绘制原始／合并／分型／Bi及失败位置并通知用户，不擅改规则消除反例。空解、未决头尾和执行失败分开统计，不宣称行情均可完整划笔。
