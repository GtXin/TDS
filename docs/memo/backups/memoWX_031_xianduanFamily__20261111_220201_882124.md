# Xianduan family implementation plan
## 000 — Scope and current result
参考memo028的结构与实施顺序，准备线段领域类、集成、验证和图集计划。[1] 类设计以memo009为核对依据。[2] 本稿仅完成外围计划，尚未执行实现或验证。

本轮线段算法依据为memo030当前XD030-E：实际相邻S/T/U绑定破坏证据，多源选路目标为“已确认线段数最多→同段数已确认几何终点最晚”；两者相同按固定遍历保留先者，起点不评分。[4] 上游笔仍按029生成。[3] 实施时记录两份规格快照与哈希，不修改029／030。030现有隔离试算是参考证据，不代替本轮生产实现验收。

**默认配置：weak Bi＋weak Xianduan。** 本轮默认流水线显式传入笔distance_mode=weak（中心距至少3），线段xd_mode省略时取weak（不施加7a端点更极端条件，其余条件不变）。两个模式独立，支持显式四组合；传入既有BiSeries时尊重并校验其实际模式，不暗中重算。009／028及现有Bi接口的strong默认差异在实施时同步核对，计划将Bi工厂缺省也改为weak，并补调用方回归；本次仅改计划，尚未改变运行默认。

## 001 — Implementation plan
### 001.a — Implement the Xianduan family
1. 核对009的Xianduan／XianduanSeries设计与030 XD030-E规格，列明成员、来源、公开方法、状态及解释合同；有冲突先记录并讨论。
2. 计划在 `src/chanlab/algo/` 实现共享算法，保持独立于API和网站。输入保留确切BiSeries及其分型、合并和原始来源链；ID、序列位置、端点锚点与确认时间分别处理。
3. 按030002.a–f建立定义到代码映射：枚举全部Shape候选；第一类及直接破坏绑定实际S/T，第二类绑定实际S/T/U分界和成员；同侧包含、同价取最早、严格分型、触点交集及失效守卫逐项保留依据。Shape通过不代表确认，替换T／U必须重验。
4. 所有合法起点共同参与；以完整候选链作参考基线，生产相邻对状态(a,b,c)仅在无跨T剩余依赖的局部充分性前提下压缩。比较(count,已确认末端)，保留best／prev和稳定遍历；回溯后从原笔独立重算逐对证据。输出连续已确认前缀，未确认T／U尾部单列且不计数。unsupported和资源超限明确报告，不将局部最优称作原文全局最优；固定快照无永久提交／续读承诺。
5. 先实现可直接核对的基线，再评估优化；复杂度按实际状态数、候选数和范围扫描成本推导，记录时间和内存。
6. 核对后完成explain、DataFrame、ChanTable、CSV/context和绘图集成；不改变上游已选笔路线来适配线段结果。
### 001.b — Repeat and review using Python Pro
冻结基线、输入、规则版本、共同测试及哈希；续作时实际读取共享Python Pro并记录版本与请求。两版遵守相同规格；披露既往技能接触，按顺序工程比较报告，不作技能因果结论。
### 001.c — Compare and select
独立进程核对实际导入路径，比较完整线段端点、状态、确认依据、来源和未覆盖区间；若规格采用DP，再比较全部可达状态及best／prev。依据正确性、可读性、类型与实测资源选择，保留失败版本与诊断。
### 001.d — Tests and integration
1. 按030建立手算与边界表：奇数至少三笔、前三笔触点交集、强7a严格比较／弱7b、同高同低不成严格分型、同侧包含与禁止跨界归约、第一类／直接／第二类破坏、越界失效守卫、换T／U旧证书失效及未确认尾部。逐项验收实际S/T/U身份和原笔成员。
2. 验证空／短输入、非法来源、ID与位置分离、不可变结果、证据一致性及上游来源保持。
3. 小输入独立穷举规格允许的候选和路线；比较完整链枚举与压缩DP的逐状态计数和最终(count,末端)，覆盖“更多段胜过更晚末端”“同段数取更晚末端”“起点不评分”及确定性并列。分别检查逐段合法性、确认依据与选择目标。不能只验证最终线条看起来合理。
4. 验证表注册隔离、CSV/context往返、解释和绘图；执行相关pytest、strict mypy、Black／Ruff及覆盖检查，记录实际结果。
5. 沿用028真实CC的100／1,000／3,000完整分型前缀及Bi×XD四组合，weak／weak为主验收，记录实际笔数和线段数；不足如实说明。各至少3次，分别记录上游、线段核心、工厂与端到端中位耗时、缓存、环境和内存口径。
### 001.e — Monte Carlo validation
1. 计划至少10,000条可复现随机原始OHLCV，经过既有合并、分型及029笔算法后进入线段算法；覆盖趋势、震荡、跳空、包含和等值，按长度及Bi×XD四组合分层，默认weak／weak单列。
2. 独立检查器不调用被测识别helper；短输入穷举，较长输入独立参考，分别报告合法性、确认和选择目标。价格镜像、平移、正比例缩放仅按030规格所支持的不变量检验。
3. 保存种子、完整输入、来源哈希、规则版本、档位与统计；空结果、未确认、异常和资源未完成单列。
4. 差异保存最小可复现数据与问题图，向用户说明；不为通过实验擅改规格。
### 001.f — Full segmented chart validation
1. 完整真实样本从首根至末根原始K线连续分段，建议200根窗口、20根重叠；机器核对覆盖及缺页。全量结果计算一次，跨页线段保持真实端点。
2. 每页显示原始K线、合并范围、全部分型、源笔、线段及必要ID／锚点；确认与候选的显示方式待状态合同确定。四组合分图保存，并提供同轴紧凑纵向比较，默认weak／weak入口明确。
3. PNG、交互HTML、窗口清单、缩略图与总索引放入 `artifacts/mas/xianduan-family/` 的独立运行目录，记录UTC范围、规则版本及来源哈希。
4. 逐页目视检查端点、跨页连续性、确认标记、遮挡和未覆盖行情；明确未绘／未查页数。必要memo图片复制到本memo同名伴随目录，不用局部例图代替全量验收。
