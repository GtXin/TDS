## 000 — Scope

将memo015的研究过程抽象为可复用SOP：围绕一个Chan概念，整理带原图和出处的原文附录A，再按实现代码整理处理步骤附录B。memo保存研究结果，Skill保存可重复执行的方法。[1][2]

- 名称：`chan-source-code-study`。
- 状态（2026-11-08）：已创建，格式验证通过；尚未完成独立任务的使用验证，也未验证当前界面的技能列表发现结果。
- 由Codex使用内置 `skill-creator` 制作；无需额外调用Anthropic或Skill Curator。

默认交付两个附录，除非用户明确缩小范围：

- **Appendix A — Chan Theory原文：** 原文／作者答疑、相关原图及精确出处；理论原文不等于可执行代码。
- **Appendix B — CC源码与实现分析：** 保存并引用相关源码，以连贯语句与步骤解释逻辑，配适当流程图或数值图；仅在必要时列出少量关键代码，再按实际函数与分支总结步骤。仅有网站说明文字不足以完成此附录。

两套来源缺一时，标明对应附录尚未完成，不用其中一套解释代替另一套证据。

## 001 — 制作过程

1. 从memo015的实际要求提取流程：限定K线包含范围、扫描原文、精选段落、附相关原图、引用来源，再沿CC实际代码总结处理步骤。
2. 阅读 `skill-creator/SKILL.md`，将流程写成单一入口文件，避免另存一份重复SOP。[3]
3. 原文选录不以短小为目标，优先保留上下文和论证连续性。一课内连续展开定义与处理规则时，以完整连续段落为主体，再加其他课程补充；保留必要前提、过渡与配图，明确删节边界。邻近概念可作为必要上下文，但应与本次研究规则区分。
4. 在原文部分明确区分作者正文、答疑、读者提问与编者注；图片需实际查看，缺失或图文不符要标明。
5. 在代码部分要求核对入口、初始化、状态、比较分支、更新、回退和输出；区分可执行语句、注释意图、推论及待验证问题。
6. 加入交付检查：出处、图片、链接、引用编号、原有内容保护，以及项目备份与日志要求。只描述实际检查，不把静态阅读写成运行验证。

执行本Skill涉及memo时，必须先阅读并遵守 [memo006写作规范](memoWX_006_memoWritingGuide.md)，包括每次修改前备份、编号索引、引用、图片存放和文字风格；用户明确要求优先。

## 003 — 调用方法

### 完整研究：生成附录A与B

在TDS项目对话中输入 `$chan-source-code-study`，接着写清研究概念、两套来源、目标memo和修改范围。可直接复制以下示例；将概念与目标memo替换为本次任务的实际值。

```text
$chan-source-code-study
研究概念：K线包含及合并处理；排除特征序列包含。
来源A：references/chan_theory/，扫描全部原文资料。
来源B：references/cc_algo/，查找网站发布的相关CC源码。
目标：docs/memo/memoWX_015_Chan_mergedkline.md。

请生成两个附录：
Appendix A — Chan Theory原文：精选有独立价值的原文及作者答疑，
附相关原图、课号和精确出处；区分读者提问与编者注。
不以短小为目标：主要课程保留连续论述，其他课程作补充，
不要为精简或凑引文数量而切断上下文、前提与论证。
Appendix B — CC源码与实现分析：保存并引用实际源码，
以连贯语句与步骤解释逻辑，配适当流程图或数值图；仅在必要时列出少量关键代码，按输入、状态、初始化、
条件分支、合并、回退和输出总结处理步骤；主要依据代码，不复述网站介绍。
用一组连续数值例子走完整流程，列出每步输入、判断、方向、结果及来源，
再配原始K线与合并区间的对齐股票图，并说明相等边界和末根修订；明确哪些是手工推演，哪些实际运行过。

只修改两个附录及其必要引用，保留主章节和用户修改。
已有资料不要重复添加；缺少来源或图片时明确标记。
按项目要求备份并记录实际检查，区分静态分析与运行验证。
```

## 005 — 算法研究中的推理检查

本Skill也适用于研究过程中的追问，不能只在整理附录时执行：

1. **固定场景。** 写明有序输入、原始K线还是合并单元、方向是否已知、是否有更早历史。用户修正数字后保持新输入，不偷偷改场景；缺失条件会改变答案时先澄清，或明确给条件分支。
2. **先验前提。** 每条判断注明适用条件；区分“存在包含”“方向足以执行合并”“得到什么结果”。条件内不可能不等于市场中绝不发生。
3. **分开证据层次。** 原文明确规则、推论、CC实现选择、尚未解决的问题分别陈述，不能用实现补成作者原话。
4. **用反例检验。** 给一般性结论前，至少核对当前数值例子和相关最小反例。包含问题关注两种包住顺序、等号、起始未定向及修订；手算／运行检查不等于正确性证明。
5. **纠错要定位。** 指出失败的前提或推理，再按固定输入重算，不能为迎合纠正而改口接受更宽泛结论。证据不足时保留未决。
6. **决定需确认。** 未经用户确认的初始化或边界约定，不写成已确定算法规则。

调用时可加一句：

```text
讨论每个算法分支前，先列固定输入、已知状态、规则前提和证据来源；
给出结论后用最小反例检查。缺失条件与初始化约定保持未决，不自行补定。
```
