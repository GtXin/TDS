# cc 项目文件夹结构

## 000 — 背景

cc 是一个基于 Python、FastAPI、DuckDB、Vue 3 和 TradingView 的缠论行情分析项目，当前主要工作包括行情存储与维护、缠论结构计算、图形展示、回放调试和人工校验。项目把后端计算、网页界面、静态组件、测试、文档及研究工具分开组织，便于理解各部分的职责与协作关系。

本备忘录依据 2026 年 11 月 7 日核对的本地项目目录整理，使用可跨机器阅读的 cc-main/ 作为根目录名称。下文逐层列出文件夹并解释用途，暂不介绍单个文件；chanOrig/ 标注为“缠论原文参考”，只列出这一层。路径统一使用 /，目录树中每个文件夹及其说明各占一个完整行，不人为拆行。

## 002 — 逐目录说明

### `cc-main/`

这是项目根目录，汇集后端、前端、图表资源、测试、文档、参考资料和开发工具。理解结构时，可以先沿 src/cc/ 查看数据与算法，再沿 frontend/src/ 查看它们如何在页面呈现；docs/ 提供相关依据与状态背景。

### `src/`

集中保存后端可以导入和复用的源码。接口服务、辅助工具和自动化测试通过这里的实现使用数据处理与缠论计算能力。

### `src/cc/`

这是后端应用的主要 Python 包。它按职责划分数据、算法、网页接口、通知、调试和运行指标，使不同功能可以通过明确的接口协作。

### `src/cc/algo/`

保存缠论计算本身，以及结构对象、算法参数、引擎管理和结果追踪。主要计算关系从 K 线包含处理开始，逐步形成分型、笔、线段、中枢和走势，再扩展到递归与背驰；算法结果由接口层转换后供前端展示。

### `src/cc/api/`

组织 FastAPI 服务，负责应用启动、关闭、资源挂载和接口注册。它把浏览器发来的请求接到数据与算法能力上，并管理相关后台任务的生命周期。

### `src/cc/api/routes/`

按照请求用途划分具体接口处理逻辑，包括图表行情、缠论结构、图层快照、数据更新、导出和自选等。接口在这里读取或调用后端能力，并把结果转换成浏览器能够使用的响应。

### `src/cc/chart/`

这是后端图表模块的预留位置，目前没有承载实际图表集成。现有图表操作主要由前端适配接口及 TradingView 集成完成，后端接口提供行情与结构数据。

### `src/cc/data/`

集中管理行情进入系统、存入数据库和供业务读取的过程。除基本 K 线读写外，还包括品种与周期管理、交易时段、连续性检查、缺口修复、历史补齐、批量更新和导出。

### `src/cc/data/adapters/`

隔离不同外部行情来源的接口差异，把外部数据转换成项目统一的行情对象。目录包含天勤、CCXT/Binance 和通达信适配实现；适配器存在并不代表都已接入日常运行链路，通达信尚未接入运行时自动回退。

### `src/cc/debug/`

为人工检查图上问题提供可选的标注调试能力，管理标注的内存保存与连接间广播。它用于排查与沟通，不属于缠论结构的判定逻辑。

### `src/cc/notify/`

组织通知消息、发送接口和通道管理，已有飞书与企业微信发送能力。它与算法计算分离；当前存在通知通道和测试能力，不代表正式算法信号已经自动联动通知。

### `src/cc/perf/`

在程序运行过程中记录算法耗时、对象数量等指标，供监控和诊断使用。它负责提供观测数据；主动制造持续负载的长时间测试工具位于项目根目录的 perf/。

### `frontend/`

保存 Vue 网页应用及其开发、测试和构建所需内容。它负责把后端提供的行情、缠论结构和任务状态组织成用户可以查看与操作的界面。

### `frontend/src/`

保存组成网页应用的界面、状态逻辑、服务调用、类型约定和公共样式。应用在这里把左侧功能栏、主图、底栏及数据更新助手等部分连接起来。

### `frontend/src/adapters/`

定义项目统一使用的图表操作约定，例如切换品种、添加图层和读取可见范围。界面业务依据这套约定调用图表能力，具体的 TradingView 操作由对应服务实现。

### `frontend/src/components/`

把界面拆成可以组合的显示与交互单元，包括图表容器、左栏、底栏和数据更新助手。组件负责组织界面及用户操作，公共状态和外部调用再由其他前端目录提供。

### `frontend/src/components/LeftPane/`

集中保存左侧功能栏内部的各类面板，使品种目录、自选、参数、信号、通知与调试各自有明确位置。这里存在信号与通知界面，不代表正式交易信号业务已经完成。

### `frontend/src/composables/`

管理可供多个界面复用的状态与操作流程，例如参数选择、自选列表、回放进度、行情连接、历史补齐和任务轮询。可以把它理解为界面背后的状态与协调逻辑，组件使用这些逻辑保持显示和操作一致。

### `frontend/src/services/`

执行与后端接口、图表库等外部能力打交道的具体工作，包括请求结构图层、调用数据维护接口、操作 TradingView 和处理标注。用户更改参数时，状态逻辑保存选择，服务层据此取得数据并更新图表。

### `frontend/src/types/`

集中约定前端使用的数据形状，例如算法参数、图层项目和图表接口的字段。共享类型让组件与服务对同一份数据保持一致理解，并支持开发时的类型检查。

### `frontend/tests/`

检查前端组件、可复用状态、接口封装与图层处理等行为。固定的测试情景帮助发现参数、自选、回放、数据工具或图表逻辑在修改后发生的回归。

### `frontend/bench/`

保存专门用于测量图层性能的基准场景和浏览器测试。它关注图层绘制、更新等操作的耗时，与检查一般功能是否正确的前端自动化测试各有侧重。

### `static/`

保存浏览器直接读取的运行资源，主要包括 TradingView 图表库与其行情接入组件。后端把这些资源提供给浏览器，前端再使用它们显示图表和读取行情。

### `static/charting_library/`

保存 TradingView Advanced Charts 的运行资源，为页面提供 K 线、技术指标、绘图和交互能力。项目自己的界面和业务逻辑通过前端适配层使用这套图表库。

### `static/charting_library/bundles/`

保存图表库实际加载的功能与资源包，包括图表逻辑、工具栏、多语言、样式以及少量图片和字体。上层图表入口根据需要从这里加载资源。

### `static/datafeeds/`

集中放置供图表取得行情的数据接入组件。图表本身负责显示，数据接入组件把它的品种查询和 K 线读取需求转换成后端请求。

### `static/datafeeds/udf/`

保存遵循 TradingView UDF 协议的行情接入组件，使图表能够向本项目后端请求品种和 K 线。它是 datafeeds/ 下面具体的一种数据接入方式。

### `static/datafeeds/udf/dist/`

保存 UDF 接入组件已经构建好的发布成品，供浏览器直接加载。这里的 dist 表示打包结果，组件通过它进入实际页面运行。

### `chanOrig/`

此目录按本次约定标注为“缠论原文参考”，用于查阅缠论原文依据。本备忘录仅列出该目录，不展开内部文件夹。

### `docs/`

集中保存理解项目所需的说明、算法依据、重要决策、研究材料和阶段记录。当前状态、正式算法口径与历史过程分别维护，阅读时需要区分它们各自的用途。

### `docs/algo-cards/`

保存各算法的说明卡，解释定义、输入输出、规则边界、原文依据及验证方式。这里连接业务口径、实现和图上结果，方便人工判断某个结构为何成立。

### `docs/algo-cards/_archive/`

保留已归档的算法草案、失败原型与历史决策推导，用于复盘和理解方案演变。它们是历史参考，不作为当前正式算法口径。

### `docs/algo-cards/assets/`

按具体说明卡分组保存详细的参数示意和案例配图。当前分为笔算法与实战线段两组，配图由离线工具生成后嵌入对应说明卡。

### `docs/algo-cards/assets/bi-v1/`

保存笔算法参数的教学配图与真实行情对照图，解释成笔距离、跳空计数、端点极值和同型分型取舍等参数的影响。图形帮助读者把参数变化与实际划分结果联系起来。

### `docs/algo-cards/assets/xianduan-practical/`

保存实战线段变体的原理示意与真实案例图，解释强势笔破坏和非标准补齐等处理。资料包含参考实现对照与真实行情案例，两种图分别用于解释方案和观察结果。

### `docs/algo-cards/images/`

保存算法说明卡使用的结构关系示意图，涉及中枢进入方向、走势与中枢关系、同级分解及背驰等内容。相较于 assets/ 按卡片分组的参数和行情配图，这里主要帮助理解结构之间的关系。

### `docs/decisions/`

保存架构与算法路线的重要决策记录，解释为什么选择某个方案、适用条件是什么，以及接受了哪些取舍。它保留决策依据与边界，帮助后续修改者理解现有设计。

### `docs/research/`

保存缠论原文、参考实现与本项目之间的研究比较和验证资料。研究结果用于发现差异、支持方案讨论，其结论是否成为正式实现仍需要结合当前算法说明和决策记录判断。

### `docs/research/reference-runs/`

保存参考实现运行产生的结果、样本与环境记录、汇总和差异矩阵。把这些证据集中存放，便于研究报告引用和后续复核。

### `docs/research/reference-runs/images/`

保存研究报告引用的对比图，展示参考实现和本项目在分型、笔、线段、中枢及参数影响上的差异。这里服务研究分析，不承担应用页面的运行资源职责。

### `docs/stages/`

保存各阶段执行计划、总结、历史状态、专项修正与交接记录。它说明项目如何推进、发生过哪些变化，以及未完成工作如何接续；历史阶段记录不等同于当前状态。

### `docs/templates/`

保存重复协作任务使用的模板，例如独立代码审核任务的组织格式。模板帮助明确背景、范围、依据和输出要求。

### `docs/tools/`

保存项目工具的使用说明，涉及数据更新助手、标注调试和图表稳定性等。这里解释工具的用途与使用边界，具体实现位于相应源码或辅助脚本目录。

### `scripts/`

保存开发、研究和诊断时使用的辅助脚本，包括数据检查、结构追踪、规则对比、基准测试和图文生成。这些工具通常按具体任务调用，与日常网页请求的主流程分开。

### `scripts/algo_cards_html/`

保存算法说明卡的离线阅读版生成工具，以及对应配图生成逻辑。它把说明卡的 Markdown 主稿转换成便于浏览器阅读的版本，并产出相关教学图。

### `scripts/diagnostics/`

保存面向特定算法问题的可重放诊断探针，例如中枢相位、同级分解一致性和递归共享端点。它通过固定输入和专项检查帮助定位问题，而不直接承担生产算法的日常计算。

### `scripts/reffig/`

保存研究报告图集的生成工具，把真实 K 线和计算结构绘制成可比较的图。生成结果主要供研究与参考实现对照使用。

### `scripts/xianduan_diag/`

保存线段专题的离线诊断和图卡工具，用于检查数据完整性、特征序列以及线段确认或拒绝的原因。固定历史案例与可视化结果为算法讨论提供可以复核的材料。

### `perf/`

保存主动执行性能与长时间运行测试的工具。它持续建立连接、请求行情与图层并采样运行指标，以观察耗时、内存和长期稳定性；src/cc/perf/ 则负责提供程序内部指标。

### `tests/`

保存后端各层行为的自动化检查，覆盖算法、数据、接口、通知和相关工具。小而固定的测试情景帮助确认正常行为、边界处理以及历史问题是否再次出现。

### `tests/algo/`

检查缠论算法各层的规则、结构对象和状态变化，并保存历史问题的回归场景。它还覆盖批量与逐步处理等一致性要求，帮助保护既有结果。

### `tests/api/`

检查后端接口的请求处理、响应内容和相关状态变化。覆盖行情、结构、图层、回放调试、自选及数据维护等接口之间的约定。

### `tests/data/`

检查行情对象、数据源适配、数据库读写和品种周期管理，并验证连续性检查、补齐、修复及批量更新等行为。它保护算法和页面共同依赖的数据基础。

### `tests/fixtures/`

保存可以重复使用的固定行情或结构样本。不同测试使用相同输入，便于复现历史问题、对比修改前后结果，并减少对实时行情的依赖。

### `tests/notify/`

检查通知消息格式、通道注册和发送接口相关行为，并验证敏感信息保护要求。它验证通知模块本身，不代表自动交易信号已经完成。

### `tests/perf/`

检查运行指标接口、算法指标采集和长时间测试工具的行为。根目录 perf/ 负责执行实际压测，这里负责自动验证相关功能是否按预期工作。

### `tests/scripts/`

为部分诊断脚本提供自动化检查，验证专项探针的输入处理与结果判断。它帮助保持辅助诊断工具本身的可靠性。

### `.agents/`

保存面向 Agent 的项目专项工作流入口。此目录用于协作辅助，不属于行情处理或缠论算法的运行链路。

### `.agents/skills/`

集中存放面向 Agent 的项目专项技能。每项技能把一种重复协作任务的操作约定组织在自己的子目录中。

### `.agents/skills/gogogo/`

组织生成下一个 PR 新会话启动说明的项目工作流。其产物是可复制的任务提示，帮助新会话带上必要背景；它本身不执行 PR 实现。

### `.claude/`

保存面向 Claude 的项目专项工作流入口。它服务开发协作，与网页前端和后端业务源码分别维护。

### `.claude/skills/`

集中存放 Claude 使用的项目专项技能。这里的技能围绕项目协作任务组织，不承担应用运行时的业务功能。

### `.claude/skills/gogogo/`

提供 Claude 侧生成下一个 PR 新会话启动说明的工作流。用途与 .agents/skills/gogogo/ 对应，但引用 Claude 对应的协作规则；它同样只生成任务提示。

### `.githooks/`

保存本地 Git 操作的检查入口。配置启用后，推送前会运行代码检查和测试，并在检查失败时阻止推送。
