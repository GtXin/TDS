## 1. Study of CC Code and Notes

### 1.1 Core Overview

> [concept] **分型记录局部转折，笔从这些转折中选出值得保留的连接。**
> CC先找第一笔，再逐个判断：新转折是延长原笔、形成下一笔，还是让原来的画法需要修正。
> “值得保留”是对作用的概括；程序实际执行的是明确的价格、距离与证据条件，不计算信息价值评分。

**十二步各自解决什么。** 编号与1.2一致；这里先讲主旨，具体公式和全部分支在详细菜单中。

1. **拿到整段输入**：一次计算为本次整份数据选出全部笔；输入分型已经识别好。
2. **定规则**：明确本次采用哪套距离、端点、极值、强势和修正规则。
3. **准备工作列表**：本次从空候选池、空笔列表开始；计算中持续保留已选出的笔。未实现的secondary直接去第十一步返回空结果。
4. **按时间读下一个分型**：每次只推进一个当前分型；全部读完去第十一步。
5. **分清有没有第一笔**：没有去第六步寻找；已有去第七步处理末端。
6. **把第一笔立起来**：固定当前分型，按先后试旧候选；第一对标准合格就成笔，否则留下当前分型等待以后配对。处理完回第四步。
7. **先判断是不是原笔的延续**：与末笔终点同型，新顶更高或新底更低就替换终点，不再检查距离；同型处理完回第四步，反型去第八步。
8. **判断反向运动能否独立成笔**：依次检查距离、端点关系、区间极值；通过就接一笔并回第四步，失败去第九步。
9. **给强势运动一个可选例外**：仅strong模式比较候选与邻笔的振幅；先比前笔，失败才找后笔参照。接受就接一笔并回第四步，否则去第十步。
10. **判断旧转折是否应被替换**：新极值和后续反向证据满足修正规则时，吸收末笔并延长前一笔；不满足则保留原画法。都回第四步。
11. **交出选好的笔**：转换为Bi结果，不再重新选端点，本次选笔结束。
12. **另算确认状态**：调用方按需标注各笔是否confirmed，不改变笔；这个标记不保证以后永远不改画。

> [example] **同一段输入怎样逐渐变成笔。** 使用1.2的完整M数据和默认bi_5k；字母按时间排列。
>
> ```text
> 输入分型： A顶20 → B底8 → C顶17 → D底6 → E顶19
> 读到A：   尚无笔，先把A留在起点候选池。
> 读到B：   A到B标准通过，得到 A20 → B8。
> 读到C：   B到C标准通过，得到 A20 → B8 → C17。
> 读到D：   C到D标准失败；借助后续E的证据修正为 A20 → D6。
> 读到E：   D到E标准通过，得到 A20 → D6 → E19。
> ```
>
> 这里“读到D”是本次批量扫描的位置，不是说真实时间只到D就能改画。
> 本次输入已经包含E；如果历史输入只到D、尚无后续确认分型，主例仍保留A到B、B到C。

### 1.2 Recipe

> [workflow] **先理解这一步为什么做，再用例子看它改变什么，最后逐项检查条件。**
> 整个选笔过程是在已识别的转折中作取舍：先找第一笔，再判断新转折是延续原笔、接出新笔，还是使原来的画法需要修正。
> 下面十二步仍按程序执行顺序排列；各步的详细分支说明接收什么、实际做什么、去哪里、哪些状态改变或保持。
> 主例固定为第一步的完整A到E输入，采用默认bi_5k；每步例子记录该步的进入与离开状态，
> 不是在同一个步骤里执行整段算法。独立输入、配置和局部条件算例另行标明。
> 每个步骤的出口优先看本步的分支说明；参数说明与后续行为注释不是额外执行指令。
>
> [note] 本文分别称呼三个列表：**输入分型列表**保存本次全部分型，**起点候选池**暂存可能的第一笔起点，
> **笔列表**保存已接受的笔。“当前分型”只由第四步更新；在第六步换旧候选，或在第九、十步查后续分型，
> 都不等于第四步已经读取了新的当前分型。
>
> [notation] **符号与下标。** 下标从0开始；“第一个”对应下标0。符号是阅读辅助，不是新增类或字段。
> - $F_i$：当前输入分型。共有n个且不为空时，输入顺序为 $F_0,F_1,...,F_{n-1}$；若还有下一个，就是 $F_{i+1}$。
> - $P_j$：候选池中正在试的旧候选。池中有m个且不为空时，先试 $P_0$，有下一个再试 $P_1$，直到 $P_{m-1}$。
>   $P_j$本身来自输入分型列表，但j表示它在候选池中排第几，不是它原来的输入下标。
> - $F_q$：提前查看的后续分型，$q>i$。换下一个后续分型时，当前 $F_i$仍然不变。
> - $M_k$：第k号合并K线；$H_k,L_k$是这根M的高、低价。k不是分型下标i。
> - $S_r$：笔列表中的第r号笔；先输出 $S_0$，再输出 $S_1$。它不是输入分型，也不是旧候选。
> - 依赖下标：记录一笔目前用到的最晚证据M位置；不是输入分型列表下标，也不保证该笔以后不会改变。
> 主例对应 $F_0=A,F_1=B,F_2=C,F_3=D,F_4=E$，它们的中心分别为 $M_1,M_5,M_9,M_{11},M_{15}$。
> 下文代码块中的 `M1` 与正文的 $M_1$表示同一根M；A、B等字母继续作为主例的易读名称。

> [reading] 配图编号跟随本节步骤；1.4的子图展开共用标准检查。图中F是输入分型列表，P是起点候选池，S是已接受笔列表；dep是依赖M下标。

> **第一步：接收本次要分析的数据。**
>
> **这里的一次计算，是对本次整份输入选出全部笔，不是只找一笔。**
> 例如交入 `[A,B,C,D,E]`，目标是选出这整段的笔；不是为第一笔交一次数据，再为第二笔交一次。
> 分型是已经识别好的局部顶、底；本算法要从中选择哪些可以作为笔的两端。
> 原始K提供原始价格与位置，合并M提供距离与高低区间，分型提供候选转折，配置决定采用哪些规则。
>
> 调用方交给 `build_bis()` 原始K线、合并K线、已识别的分型列表、配置，以及规则版本标识。
> 本步接收这些输入，不重新合并K线、不识别分型、不建立笔。
>
> - **输入有分型**：原样交给第二步，尚未判断哪两个分型能成笔。
> - **输入无分型**：空分型列表也是本次输入，仍进入第二步，不在这里强行补分型。
> - **输入彼此不对应**：这段入口没有全面校验或修复，不能当作“无笔”分支；后续可能报错或产生不可靠结果。

> [reference] **以下是参数说明和独立条件算例，解释选项含义，不是第二步的执行指令。**
> 这些检查在后续各自负责的步骤执行；局部条件通过不等于已经成笔。
>
> **每种预设是什么意思**
>
> [note] 以下是CC代码的规则预设，不是经典缠论的统一分类。`CUSTOM`是自定义配置入口，
> 不是另一种成笔算法。以下距离与振幅算例只解释对应条件，不表示完整成笔判断已通过。
>
> **`bi_5k`：按合并K线的中心距离判断。**
>
> 例如顶在M1、底在M5，下标差为 `5-1=4`，包含两端共5根M，距离条件通过。
> 但不是有5根就一定成笔：还要检查两端朝向笔内部的高低关系（`half`），
> 以及区间内部有没有更高的高点或更低的低点否定所选终点。
> 距离不足时允许真实价格缺口补足；后续证据满足时，还允许反弹修正，撤销中间一笔并延长前一笔。
>
> **`bi_4k`：回到原始K线的极值位置计算距离。**
>
> 不是简单把上面的5根改成4根。先要求两个分型的三根M窗口不共用M，
> 再找两个中心M内部对应的原始极值K，检查其下标差是否至少为4。
> 例如起点窗口为 `M0,M1,M2`，终点窗口为 `M3,M4,M5`，窗口不重叠；
> 若中心M1、M4中对应的原始极值分别在K10、K14，则 `14-10=4`，距离条件通过。
> 若原始极值只相距3，或两个分型窗口共用M，都不能通过。
> 此预设不启用缺口折算、额外端点检查、区间极值检查和反弹修正。
>
> **`bi_strong`：标准判断失败后，再按振幅判断。**
>
> 振幅为 $|p_{终点}-p_{起点}|$；顶端点取分型中心M的高价，底端点取其低价，单位与价格相同。
> 不是涨跌百分比，也不是逐根累计涨跌。这里只解释参数含义，执行顺序见第九步。
> 继承 `bi_5k`，先尝试标准成笔，失败后增加一次强势判断机会。
> 例如上一笔振幅10，候选反向笔振幅9.6：`9.6 >= 10 × 0.95`，强势判断通过。
> 若候选振幅只有9，则与上一笔的比较不通过；后续查找固定当前候选的终点，
> 它后面可能有多个分型，先试第一个，不能标准成笔就试下一个；每次都用同一个固定终点作起点。
> 找到第一个能标准成笔的配对就停止查找，用该后笔振幅比较；全部试完仍未找到或比例比较不通过，就不能按强势笔接受，
> 不再另找振幅更合适的后笔。具体查找分支由第九步执行。
> 这里的振幅是两端价格差的绝对值，不是涨跌百分比。
> 第一笔仍必须通过标准检查，不能靠强势条件起步；预设比例是0.95，不是配置类字段初值0.9。
>
> **`bi_secondary`：目前只是预留。**
>
> 所检查的这版CC代码没有实现此模式。即使传入主例的五个分型，也会返回空笔列表 `[]`。
> 这不表示行情中没有笔，而是此模式没有执行成笔计算。
>
> **`CUSTOM`：自己组合规则参数。**
>
> 不套用命名预设。例如采用合并中心距离，把最小距离设为6，关闭缺口折算，保留区间极值检查。
> 此时M1到M5的距离4不够，M1到M7的距离6才通过距离检查；其他检查仍需继续。
> 相反，若选 `bi_5k` 同时手动填 `bi_min_span=6`，实际仍使用预设的4，手动填6不会保留。
>
> **这些检查究竟怎样判断？**
>
> [rule] 标准成笔先要求一顶一底，再依次检查“距离 → 端点关系 → 区间极值”。
> 某项不通过，就停止这次标准判断。这里提前解释所选规则，实际计算仍在后续步骤执行。
> 以下沿用第一步主例，取M0到M10，方便逐列比较。`H`是该M的高价，`L`是低价，
> 不是整个三根分型窗口的最高、最低价。
>
> ```text
> M序号   M0  M1  M2  M3  M4  M5  M6  M7  M8  M9 M10
> 高价    19  20  18  16  14  12  13  14  16  17  14
> 低价    15  16  14  12  10   8   9  10  12  13  10
> 分型     .   A   .   .   .   B   .   .   .   C   .
> ```
>
> **距离：两端隔得够不够远？**
>
> `merged_center`直接减中心下标：A到B为 `5-1=4`，B到C为 `9-5=4`，都达到默认要求4。
> 若只相距3且没有价格缺口，就不通过；有1个真实缺口且允许折算，则 `3+1=4`，通过距离检查。
> 缺口要看相邻M各自全部原始K成员的价格范围：例如 `[10,12]` 与 `[14,18]` 不相交，算1个；
> `[10,14]` 与 `[14,18]` 只是接触，不算；休市造成时间断开也不算价格缺口。
> `raw_extreme`则采用前述原始极值下标差与窗口不重叠规则，不使用缺口折算。
>
> **`half`：只取两端朝向笔内部的半边作比较。**
>
> 每个分型有左、中、右三根M。起点取“中心＋右邻”，终点取“左邻＋中心”；
> 起点左邻与终点右邻不参加这项端点检查，但仍是识别分型所需的数据。
> `half`不是取一半价格，也不是只检查一个端点。下面两个不等式必须同时成立。
>
> - 向下，A顶M1到B底M5：起点侧为M1、M2，终点侧为M4、M5。
>   起点顶要高过终点侧的高价：`H1 > max(H4,H5)`，即 `20 > max(14,12)=14`，通过。
>   终点底要低过起点侧的低价：`L5 < min(L1,L2)`，即 `8 < min(16,14)=14`，通过。
> - 向上，B底M5到C顶M9：起点侧为M5、M6，终点侧为M8、M9。
>   起点底要低过终点侧的低价：`L5 < min(L8,L9)`，即 `8 < min(12,13)=12`，通过。
>   终点顶要高过起点侧的高价：`H9 > max(H5,H6)`，即 `17 > max(12,13)=13`，通过。
> - 相等不通过。这是严格的 `>`、`<`，不是 `>=`、`<=`。
>   独立端点算例：起点顶22、终点侧高价21和19，第一项 `22>21` 通过；
>   终点底4、起点侧低价4和3，第二项 `4<min(4,3)=3` 不通过，因此整体失败。
>   若只把终点底换成3，`3<3` 仍失败；这是局部条件比较，不是改动主例后的完整行情。
>
> **端点检查还有哪些选项？**
>
> - `none`：不检查这项端点关系，不代表跳过距离或其他已启用的检查。
> - `loss`：只比较两个中心M。向下要求起点高价更高、终点低价更低；向上相反。
>   A到B就是 `20>12` 且 `8<16`；B到C就是 `8<13` 且 `17>12`，都通过。
> - `strict`：仍比较起点、终点中心的极值，但把另一侧的比较范围扩为完整三根窗口。
>   A到B要求 `20>max(H4,H5,H6)=14` 且 `8<min(L0,L1,L2)=14`，通过。
>   B到C要求 `8<min(L8,L9,L10)=10` 且 `17>max(H4,H5,H6)=14`，通过。
> - `totally`：要求起点中心M与终点整个窗口的价格范围完全分开。
>   向下A到B要求 `L1 > max(H4,H5,H6)`，即 `16>14`，通过；
>   向上B到C要求 `H5 < min(L8,L9,L10)`，即 `12<10`，不通过。
>   所以同一对B、C可以通过 `half`，却不能通过 `totally`。
>
> **区间极值 `require_peak`：中途有没有价格否定这个终点？**
>
> 向下只检查两端中心之间每根M的低价，必须都不低于终点底；向上检查高价，必须都不高于终点顶。
> 不含两个中心本身，也不扩到它们外侧的邻居。
> A到B的内部低价为M2到M4的 `[14,12,10]`，都 `>=8`，通过；
> B到C的内部高价为M6到M8的 `[13,14,16]`，都 `<=17`，通过。
> 局部反例：候选终点底为10，但中途出现低价8，则 `8>=10` 不成立，拒绝；
> 中途最低恰好为10则允许。这里允许相等，与 `half` 不同。
> 关闭 `require_peak` 只跳过标准成笔的这项检查，不会自动关闭反弹修正内部自己的极值检查。
>

> **第三步：建立本次工作区，并决定是否开始处理输入分型。**
>
> **为整份输入重新选笔，但在这一次计算中持续保留已经选出的笔。** 例如输入仍为 `[A,B,C,D,E]`，
> 开始时 `候选池=[]，笔=[]`；后来选出A到B，找第二笔时仍保留A到B，不重新清空。
> 输入已经存在，空的是工作列表，不是历史数据。起点候选池保存“还没有第一笔时，留下来试配对的分型”；
> 笔列表保存“本次已接受的笔”。建立第二笔、第三笔时仍使用同一笔列表，不会把前面的笔清掉。
>
> 配置已经由第二步确定。本步创建 `_BiBuilder` 保存本次输入，建立空的起点候选池和笔列表，
> 再检查成笔模式。输入分型原样保留；本步不读取第一个分型，也不计算任何一笔。
>
> - **standard或strong**：两个工作列表保持为空，进入第四步，从输入的第一个分型开始。
> - **secondary**：此版本尚未实现该模式，一个输入分型也不处理；保持空笔列表，进入第十一步整理返回。
>   这不是“行情没有笔”，而是该模式没有执行成笔计算。
>

> 工作列表每次调用只初始化一次；secondary不扫描输入，直接交第十一步返回空结果。

> **主例中的具体状态。**
>
> ```text
> 保存的输入：[A顶20, B底8, C顶17, D底6, E顶19]
> 起点候选池：[]
> 已接受的笔：[]
> 本次模式：  standard
> 下一步：    第四步
> ```
>
> [example] 独立模式情况：同一输入若选择strong，仍以这两个空列表进入第四步；
> 若选择secondary，则带着空笔列表进入第十一步。输入五个或1000个分型都不改变这条分支。
>
> [note] **状态的寿命。** 同一次调用中的后续步骤共享这两个列表，新建一笔不会清空旧笔。
> 重新调用 `build_bis()` 才重新建立工作区：即使上次已算出A到B，下次传入A到E也从头计算。
> 这些说明后续使用方式，不表示第三步已经处理A或B。
>
> [note] **正在处理哪个分型，与能看见多少数据，是两回事。** 保存整个输入不等于已经处理完所有分型。
> 独立设定：传入F0到F999，即使后续只处理到F5，F6到F999也已在输入中。

> 本次完整输入：F0 ... F5 ... F405 ... F995 ... F999
> 当前处理到：        F5
> 可访问的末尾：                              F999
> ```
>
> 同一次调用中，各笔可访问的截止位置相同，但实际读取范围不同。
> 第一笔若F0、F1已合格，就在处理F1时建立；不是先读完1000个才决定。
> 若始终没有合格组合，就要一个接一个地处理后续分型，寻找第一笔的过程才可能一直到最后一个分型。
> 标准检查不用后续分型作成笔证据，但终点分型的识别已需中心M右邻；
> 强势及修正的某些分支会向后查证据，最远到本次输入末尾。第一笔建立不走强势分支。
> 刚建立的笔也可能在后续处理时被延长或修正。
>
> 模拟真实时间时，调用方必须把原始K、合并K和分型都限制在当时可见的范围内。
> 整段历史的事后结果不能直接视为当时已知结果；以上是CC代码行为，不是我们自己的最终接口决定。

> **第四步：读取下一个分型，全部读完就结束。**
>
> **让每个分型按时间先后轮到一次正式判断。** 例如完整输入为 `[A,B,C,D,E]`，处理完B回到本步，
> 下一次交出C，已经选出的笔保留。“当前”指这轮交给后续步骤判断的那个分型，
> 不代表它是整份输入的最后一个，也不代表它已被选为笔端点。
>
> **输入分型列表可能有多个分型，按时间从早到晚排列。** 第一次进入本步，读取第一个分型；
> 处理完它并回到本步后，读取下一个分型，把它设为新的当前分型。不是每次都重新读取第一个。
> 用符号表示：第一个是 $F_0$；处理完当前 $F_i$，才读下一个 $F_{i+1}$。处理完 $F_{n-1}$ 后就没有下一个。
>
> - **还有下一个输入分型**：读取它，作为新的当前分型，进入第五步。
> - **所有输入分型都已读完**：没有新的当前分型，带着已有笔列表进入第十一步。
>
> 本步不比较价格、不修改候选池或笔列表。“读取”不删除分型，也不截短输入。

> **第五步：检查笔列表是否为空，决定下一步。**
>
> **先分清：现在还在找第一笔，还是已经有笔可以接着处理。** 例如 `笔=[]` 去第六步；
> `笔=[A到B]` 去第七步，列表都不在这里改变。要看的是已接受的笔有几条，不是输入有几个分型，也不是候选池是否为空。
> 空笔列表意味着还要找第一笔；已有笔则可以检查如何接续最后一笔。
>
> 第四步已经读出当前分型。本步只检查已接受的笔列表是否为空：
>
> - **为空**：还没有第一笔，保持当前状态，带着当前分型进入**第六步**寻找第一笔。
> - **不为空**：已经有一笔或多笔，保持当前状态，带着当前分型进入**第七步**。
>   第七步才会取末笔终点，判断它与当前分型的关系。
>
> **本步不比较顶底或价格，不增加、延长或删除笔，也不修改候选池。**
> 是否成笔、是否修正，都不在本步决定。

>   笔列表不为空，两列表原样保留，进入**第七步**。本步尚未判断B到C能否成笔。

> [note] 这里判断的是“有没有笔”，不是“是否只有一笔”。一笔和多笔都走第七步；
> 只有空列表走第六步。

> **第六步：从候选池寻找第一笔。**
>
> **找到第一对符合标准的转折，先把第一笔立起来。** 主例当前到B底8时，池中已有A顶20，
> A到B标准通过，便从 `笔=[]` 变为 `笔=[A20到B8]`，清空候选池并回第四步。
> 成功前起点尚未固定：旧候选 $P_j$只是可能的起点，当前 $F_i$是这轮固定的候选终点。
> 若旧候选有多个，按它们进入池的先后顺序试，不先按价格挑一个最极端的。
> 配对开始前可把状态读成：`笔=[]；候选池=[P0,P1,...]；当前=Fi`。
> 本步要找的是第一对标准合格的端点，不是把所有能成笔的配对都输出。
>
> 进入本步时，笔列表为空，当前分型已由第四步读出。本步负责尝试候选起点、建立第一笔或保留候选。
> **候选池里可能有多个旧候选。先试第一个，不合格就试下一个，直到某一对成功或全部旧候选试完。**
> 这里的第一个是最早放入候选池的那个，后面的也按放入先后排列。
> **这轮当前分型始终不变，只更换旧候选起点**，不是读取下一个输入分型。
> 固定当前 $F_i$，先试 $(P_0,F_i)$，再试 $(P_1,F_i)$，最后可能试到 $(P_{m-1},F_i)$。
> 旧候选 $P_j$这一对不合格且还有下一个旧候选时，下一个配对是 $(P_{j+1},F_i)$，不是 $(P_j,F_{i+1})$。
>
> - **候选池为空**：把当前分型放入候选池；笔列表仍为空，回第四步。
> - **候选池不为空**：先把第一个旧候选与当前分型配对，检查下面的条件。
> - **两者同为顶或同为底**：这一对不可能成笔，不执行标准价格检查；保留旧候选。
>   若池中还有下一个旧候选，就换成那个旧候选，与**同一个当前分型**重新配对，仍在第六步。
>   若已经是池中最后一个旧候选，就走下面“全部试完”的分支。
> - **两者一顶一底，但标准检查失败**：这一对也不成笔，保留旧候选。
>   若池中还有下一个旧候选，就换成那个旧候选，再与**同一个当前分型**试配对；
>   没有下一个旧候选，就走“全部试完”分支。
> - **一顶一底且标准检查通过**：用旧候选作起点、当前分型作终点建立第一笔，
>   记录standard规则与当前分型中心M下标作为依赖，清空候选池，回第四步。不再比较其他旧候选。
> - **所有旧候选试完仍没有成功**：把当前分型追加到候选池末尾；笔列表仍为空，回第四步。
>   刚追加的当前分型不在这一轮与自己比较；第四步随后读取下一个输入分型，才开始下一轮候选搜索。
>
> 本步调用与第八步相同的距离、端点、区间极值判定；判定结果返回本步处理。
> “标准检查”具体检查什么，见独立小节 [1.4 Standard Check](#14-standard-check)。
> **这里失败不会进入第九步或第十步。** 即使配置strong，第一笔也必须通过标准检查。

>
> 旧候选从早到晚试；同型跳过、标准失败、成功停止与耗尽追加各有出口。

> 第一次配对：P顶20 → X顶19。同为顶，跳过这一对；P保留，当前仍是X。

> **第七步：比较当前分型与末笔终点，同型处理，反型转下一步。**
>
> **已有一笔时，同型的新分型可能替换旧终点；反型的新分型才可能接出另一笔。**
> 局部例子：已有 `顶20到 底8`，新来底6，就延长为 `顶20到 底6`；新来顶17，则保留原笔并去第八步检查 `底8到 顶17`。
> “端点”是笔连接的起点或终点：由选中的分型定位到中心M，顶取高价、底取低价。
> 分型本身仍是三根M的结构，不是整组三根都变成一个价格点。
>
> 进入本步时笔列表不为空。本步取最后一笔的终点分型与当前分型比较，
> 不是拿第一笔起点，也不一定是输入列表的上一项，因为上一项可能未被接受为端点。
> 若最后一笔是 $S_r$，本步比较的是 $S_r$的终点分型与当前 $F_i$；不一定是 $F_{i-1}$与 $F_i$。
> 以下“依赖下标”记录这笔目前用到的最晚证据M位置，不一定等于终点位置，也不代表结果已经冻结。

> - **两个底，新底严格更低**：替换末笔终点，依赖下标同样取较大值；回第四步。
> - **两个底，新底相等或更高**：笔列表不改，回第四步。
> - **末端底、当前顶**：笔列表不改，带着“末端底 → 当前顶”这一向上候选，进入第八步。
> - **末端顶、当前底**：笔列表不改，带着“末端顶 → 当前底”这一向下候选，进入第八步。

> 同型处理只可能延长末笔，不增加笔数，不修改更早的笔，不重新检查距离、half或区间极值。

> **第八步：检查反向候选，标准通过才追加一笔。**
>
> **反向转折出现了，但要达到本次选用的成笔标准，才把它单独画成下一笔。**
> 主例已有A20到B8，B8到C17通过标准，才变为两笔 `A20到B8、B8到C17`；不是见到顶17就直接连线。
> 上一笔的终点固定作候选起点，当前分型固定作候选终点。
> 主例处理C时，先把三种角色摆清楚：
>
> ```text
> 输入时序： A顶20 → B底8 → C顶17 → D底6 → E顶19
> 已接受：   A → B
> 当前分型：               C
> 待检查：          B → C
> ```
>
> 从第七步进入时，已有末笔终点作起点，当前分型作候选终点。
> 本步有三个标准检查，先做第一个；通过或按配置无需检查，才做下一个。某一个失败，就不再做后面的检查：
> 三项检查使用同一对端点，不因某项失败而在本步另换端点。检查中间多根M时，先看第一根，再看下一根，终点价格始终不变。
> 起、终点中心分别记为 $M_s,M_e$。例如B到C就是 $s=5,e=9$，不是分型列表下标1和2。
>
> 1. **距离**：默认中心下标差至少4；不足时，只有开启缺口折算且“距离＋真实缺口数”达到4才通过。
>    采用raw_extreme时，改查分型窗口不共用M及原始极值下标差，不折算缺口。
> 2. **端点关系：两端朝内的局部价格是否合格？** 默认half只取起点中心与右邻、终点左邻与中心。
>    向上要求 $L_s<\min(L_{e-1},L_e)$ 且 $H_e>\max(H_s,H_{s+1})$；
>    向下要求 $H_s>\max(H_{e-1},H_e)$ 且 $L_e<\min(L_s,L_{s+1})$。相等不通过。
>    选择none则跳过本项，继续第3项；loss、strict、totally的范围见第二步参数说明。
> 3. **区间极值**：向上要求内部每根M高价不超过终点顶，向下要求内部每根M低价不低于终点底。
>    固定终点价，先检查起点后面的第一根M，未越界再查下一根，直到终点前面的最后一根M。
>    两端中心为s、e时，对应 `M(s+1)、M(s+2)、...、M(e-1)`。
>    任何一根越界就返回失败，不再查剩下的M；全部检查完都未越界才通过。允许相等；关闭require_peak则不做这项检查。
>    符号对应：向上检查 $H_k\le H_e$，向下检查 $L_k\ge L_e$，其中 $s<k<e$；更换k时，s、e和终点价格不变。
>
> - **任一启用的检查失败**：笔列表不改，带着同一候选进入第九步。
> - **所有启用的检查通过**：追加一笔，记录standard规则及当前分型中心M下标作为依赖，回第四步。
>   原有笔保留，候选池不变。
>
> [note] **第2、3项部分重叠，但不能互相替代。** 向上时，第2项已要求 $H_{s+1}<H_e$，
> 第3项又要求同一根的 $H_{s+1}\le H_e$，这一处重复。但第3项还查其他内部M，
> 第2项还约束两端的低价关系。向下则高低对调。不能把“看两头”和“看中间”理解为完全不相交。
> 下面的极值组就是第2项通过、第3项失败；相等在half中拒绝、在区间极值中允许。
>
> [note] **共用判定不等于共用出口。** 上述标准检查本身只返回通过或失败。
> 第六步借用后，返回第六步选择候选；第九步借用后，返回第九步取得参照振幅；
> 第十步借用后，返回第十步决定是否阻止修正。这些调用都不在本步追加笔，也不因失败自动跳第九步。
> 只有从第七步进入的“追加反向笔”主流程，使用上面的两个出口。判定函数还会直接拒绝同型配对。
>
> ![step08：本步只处理追加反向笔的调用；标准辅助函数的各子分支见1.4，其他调用者出口不套用本步。](../../artifacts/experiments/chan_theory/memo0026_step08.png)
>
> 本步只处理追加反向笔的调用；标准辅助函数的各子分支见1.4，其他调用者出口不套用本步。

> **第九步：标准失败后，按配置决定是否接受强势笔。**
>
> **“强势笔”是CC的一条可选接受规则：候选没有通过标准检查，但相对邻笔的价格运动幅度够大，仍可接受。**
> [example] 主例若改用strong：已有 `A20到B8、B8到C17`，候选C17到D6标准失败，
> 但候选的端点价差为 `|6-17|=11`，前笔为 `|17-8|=9`；`11>=0.95×9`，便额外接受C到D。
> 主例默认standard没有这条例外，原笔不变，直接去第十步。下面按真实顺序解释开关、前笔比较和备用后笔搜索。
>
> 这里保留的是相对邻笔幅度够大的运动，不是判断上涨或买卖信号，也不是把失败的标准重新判成通过。
> 这是CC的实现选择，不是经典缠论必然如此；第一笔不走本步。
>
> **先摆清楚正在判断谁。** 进入时已有末笔，当前候选在第八步失败，尚未追加。
> 主例处理到D时，角色如下；本步不改变当前分型D：
>
> ```text
> 输入时序： A顶20 → B底8 → C顶17 → D底6 → E顶19
> 已接受：   A → B，B → C
> 前笔参照：        B → C
> 当前候选：               C → D
> 假设后笔：                      D → E（只有需要且标准合格时才用）
> ```
>
> **振幅先定义，再比较。** 分型中心为M_k时，顶端点价取H_k，底端点价取L_k。
> 任意一对反型端点X、Y的振幅记为 $a(X,Y)=|p_Y-p_X|$，单位与价格相同。
> 它不是百分比、不是沿途涨跌的累计，也不是另找整段最高最低价相减。
> 主例候选 $a(C,D)=|6-17|=11$；前笔 $a(B,C)=|17-8|=9$。
> 比例记为 $\rho$，来自本次配置 `bi_strength_ratio`；`bi_strong`预设取0.95。
>
> **先看开关。** 未开启strong，笔列表不改，直接进入第十步；不计算上述振幅，也不搜索后笔。
> 开启strong，才计算候选振幅并读取比例，继续下面的前笔比较。上面的定义和算例不是开关关闭时也执行的操作。
>
> ![step09a：strong关闭直接进第十步；前笔比较成功立即追加，失败才进入后笔搜索。](../../artifacts/experiments/chan_theory/memo0026_step09a.png)
>
> strong关闭直接进第十步；前笔比较成功立即追加，失败才进入后笔搜索。
>

> **先比前笔，成功就结束本步。** 取笔列表最后一笔作参照，计算其振幅：
>
> - 前笔振幅大于0，且 $a(C,D)\ge\rho\,a(B,C)$：追加C到D，标记 `strong_prev`，
>   依赖记到D中心M下标，回第四步。既不找后笔，也不执行第十步修正。
> - 前笔振幅为0，或上述比例不通过：笔列表不改，才开始下面的后笔搜索。
> - 主例若改为strong：`11>=0.95×9=8.55`通过，得到 `[A20 -> B8, B8 -> C17, C17 -> D6]`，回第四步。
>   等于阈值也通过，例如候选9.5、前笔10。主例默认standard则在开关处直接进入第十步。
>

> ![step09b：D固定，后续G依次前移；先找到第一条标准后笔，再与它比振幅，比例失败也不再换参照。](../../artifacts/experiments/chan_theory/memo0026_step09b.png)
>
> D固定，后续G依次前移；先找到第一条标准后笔，再与它比振幅，比例失败也不再换参照。
>

> **前笔比较失败，才找第一条标准合格的后笔。** 固定当前D为假设后笔起点，按时间试D后面的分型。
> 当前D记为 $F_i$，正在试的后续分型记为 $F_q$，$q>i$；先试 $(F_i,F_{i+1})$，不合格再试 $(F_i,F_{i+2})$。
> 后面可以有多个分型；每次只换假设后笔终点，绝不改成 $(F_{i+1},F_{i+2})$。
>
> - 没有后续分型：没有后笔参照，笔列表不改，进入第十步。
> - 第一个后续分型与D同型：跳过这次配对，不删除它；有下一个后续分型就换成那个，与同一个D配对。
> - 一顶一底：检查“D到这个后续分型”是否标准成笔。失败就试下一个，D和原候选C到D都不变。
> - 找到第一条标准合格的后笔：立即停止搜索，计算这条后笔的振幅，进入下面的比例比较。
> - 所有后续分型都试完仍没有标准合格后笔：笔列表不改，进入第十步。
>
> **最后只与找到的这一条后笔比较。** 假设找到的终点为G：
>
> - 后笔振幅大于0，且 $a(C,D)\ge\rho\,a(D,G)$：只追加当前候选C到D，标记 `strong_next`，
>   依赖记到G中心M下标，回第四步。D到G只作证据，不在这里追加。
> - 后笔振幅为0，或比例不通过：笔列表不改，进入第十步。
>   **不继续寻找第二条标准后笔，即使它的振幅可能更容易满足比例。**
>
> 这是“先找到第一条标准合格参照，再比振幅”，不是“寻找第一条能让振幅比较通过的参照”。
>
> [example] 局部配对顺序：当前固定为X底10，后续依次为 `[Y底9,Z顶18,W顶20]`。
> 先试 `X -> Y`，同为底，不用Y；再试 `同一个X -> Z`。
> 若X到Z标准失败才试 `同一个X -> W`；若X到Z标准通过，搜索立即结束，使用X到Z的振幅。
> 此后比例不合格就去第十步，不能再改用W。这里仅说明给定标准结果时的循环，不预设它们一定成笔。
>
> 本步不会重跑候选已经失败的标准条件，也不执行反弹修正。
> 查找后笔只看本次输入中已有的后续分型，且只用标准检查，不等待新数据，也不再为假设后笔寻找强势依据。
> 后查期间第四步没有前移；使用G作依据的决定，不能声称在只看到D的真实时刻就已知道。
> 本步只在接受时追加当前候选，保留原有笔；起点候选池始终不变。
>
> **主例中的具体状态。**
>
> 当前D底6，已有 `[A20 -> B8, B8 -> C17]`，候选C17到D6。
> 主例为standard，故本步不比较振幅，原列表不变，进入第十步。

> **独立强势配置与数值例子。**
>
> - 独立数据采用strong，分型为 `底0@M1 -> 顶20@M5 -> 底10@M7 -> 顶18@M11`：
>
> ```text
> M序号   M0  M1  M2  M3  M4  M5  M6  M7  M8  M9 M10 M11 M12
> 高价     5   4   7  10  15  20  17  14  15  16  17  18  17
> 低价     1   0   3   6  11  16  13  10  11  12  13  14  13
> ```

> 进入本步时已有 `[0 -> 20]`，当前底10，候选20到10因距离2、无缺口而标准失败。
> 候选振幅10小于 `0.95×20=19`；固定当前底10，查它之后的第一个分型顶18，尝试10到18作参照。
> 10到18是找到的第一条合格标准后笔：距离4，half为 `10<min(13,14)`、`18>max(14,15)`，
> 内部高价15、16、17不超过18。其振幅8，`10>=0.95×8=7.6`，
> 因此只追加20到10，变为 `[0 -> 20, 20 -> 10]`，依赖M11，回第四步；尚未追加10到18。

> - 独立截断情况：上述输入只提供截至M8，尚无顶18，前笔比较失败又无后笔可找。
>   保留 `[0 -> 20]`，进入第十步。
> - 独立比例情况：候选10、前笔20、找到的第一条标准后笔12，则 `10<19` 且 `10<11.4`，
>   两次都失败，不改笔列表，进入第十步；不能再找一条更小后笔来凑比例。
> - 比例相等允许，例如候选9.5、前笔10，`9.5>=0.95×10`通过，追加并回第四步。
>   前笔振幅为0则不使用前笔作参照、留在本步从后面的第一个分型开始试后笔；找到的第一条标准后笔振幅为0则直接进入第十步。

> **第十步：判断新的转折是否应替代旧转折，重新画末尾的笔。**
>
> **前面看价格运动是否延伸得更深，后面看反向运动是否支持这个新转折；条件允许，就用新转折替换旧转折，重画。**
> 这是对本步作用的理解：保留更能代表这段运动的转折点。代码不计算“代表性”或“信息量”评分，
> 也不是第九步那种振幅比例比较；实际依据是下面的价格、区间极值和按顺序出现的后续证据。

> [example] **先看主例为什么把B换成D。** 完整输入仍为A到E，当前处理D，修正开启：

> 输入时序： A顶20 → B底8 → C顶17 → D底6 → E顶19
> 已经画出： A20 → B8 → C17
> 尚未接受：           C17 → D6
> 修正之后： A20 ─────────→ D6
> 后续依据：                            E19 > C17

> - **向后看**：D之后第一个分型就是E顶19，超过C顶17，给D处的反向转折提供了本规则要求的支持。

> 下跌后的反弹为 `A顶 -> B底 -> C顶`，D为底：

> 第九步检查假设后笔 $(D,F_q)$；本步阻止修正的标准笔检查则是 $(C,F_q)$。起点不同，不能混用。

> 2. 检查A到D内部所有M低价均 `>=D底`；有更低价则不改，回第四步。该项不受标准require_peak开关控制。
> 3. **D后面可能有多个分型，先看第一个，没有决定性证据再看下一个。** 每次正在查看的后续分型叫G，A、B、C、D始终不变。
>    G是顶且高于固定的C顶：取得确认位置，停止后查，进入本步第4项；
>    G是底且“固定的C顶 → G底”通过标准检查：立即拒绝修正，回第四步。
>    G是顶但不高于C，或G是底但C到G标准失败：保留G、笔列表不改；
>    若还有下一个后续分型，就把它作为新的G，与同一个C再判断；全部看完仍没有决定性证据，则回第四步，不修正。

> **第十一步：把工作笔整理成结果，结束本次调用。**
>
> **把已经选好的笔交给调用方使用，不再重新选转折。** 主例最后选出A到D、D到E，
> 本步返回对应的两个Bi对象，不多画一笔，也不删掉一笔。工作笔保存被选中的分型及依赖，

>
> 进入本步有两种原因：第四步已读完全部输入分型，或第三步选择未实现的secondary而没有处理任何输入分型。

> **第十二步：调用方另行选择是否计算确认标记。**
>
> **按CC的依赖位置规则，另给每笔标出当前的确认状态，不改变已经画出的笔。**
> 主例N=17时，两笔依赖都到M15，达到 `N-2=15`，所以 `[A到D,D到E]` 得到 `[False,False]`，两笔仍原样保留。
> `confirmed`是当前输入下CC给出的布尔判断，
> 不是承诺以后不会改画。先有第十一步返回的Bi列表，调用方才决定要不要计算标记。
> 两个输入必须对应同一份行情：`Bi列表=[S0,S1,...]` 与合并K总数N；输出为同顺序的 `[c0,c1,...]`。
> 本步所谓“末笔依赖不稳定”，专指末笔依赖未知或达到阈值 `N-2`，不是另算一个市场波动指标。
>
> 第十一步的 `build_bis()` 已结束。调用方若需要确认状态，另调 `bi_confirmed_flags()`，
> 提供返回的Bi列表及同一次数据对应的合并K总数N。本步只返回一一对应的布尔列表，不修改笔。
>
> - **不需要确认标记**：调用方不调用此函数，流程结束。
> - **需要且Bi列表为空**：返回 `[]`，确认计算结束。
> - **需要且Bi列表非空**：先读取并固定最后一笔的依赖状态；然后为第一笔计算标记，放入标记列表。
>   有下一笔就计算下一笔的标记，接在已有标记后面；全部笔算完才返回完整标记列表，确认计算结束。
>   第一笔对应第一个标记，第二笔对应第二个标记，后面同理；不覆盖前一笔的标记。
>   正在处理的笔记为 $S_r$，它的标记记为 $c_r$：$S_0$对应 $c_0$，$S_1$对应 $c_1$。
>
> 先读取依赖下标：trace不存在则依赖未知；trace存在且dep_to_index有值就用它，
> 否则退回merged_to_index。仍取不到数值时，按未知处理。
>
> 每笔满足以下任一条件，就标为 `False`；全部不满足才标为 `True`：
>
> - 是最后一笔，无论依赖多早都为False。
> - 自己的依赖未知，或依赖下标 `>=N-2`。
> - 是倒数第二笔，且最后一笔的依赖未知或 `>=N-2`。
>

**输入已经包含哪些事实**

`build_bis()` 接收原始 K 线、合并 K 线、分型列表和配置。
原始 K 线用于检查真实价格缺口或寻找原始极值；合并 K 线用于距离和价格比较；
分型列表提供候选位置。Bi 不重新合并 K 线，也不重新识别分型。

用 `H[i]、L[i]` 表示合并 K 线 `M_i` 的高低价。
一个分型的 `index` 是中心 M 的下标，不是它在分型列表中排第几。
例如，第3个分型可以位于 M9，距离计算使用9，而不是3。

CC 的分型 `high/low` 保存三根 M 的最高和最低。
顶分型的最高点在中心根，底分型的最低点也在中心根；另一侧价格不一定来自中心根。
分型时间使用中心 M 的起始时间，并不表示那一刻已经识别出分型；识别还需要右邻。

**先确定真正生效的配置**

`build_bis()` 先运行 `config.normalize()`。命名预设会换成预设的一整套参数，
不是在预设上自动保留所有手动修改。自由组合必须选 `CUSTOM`。

| 预设 | 实际采用的主要规则 |
| --- | --- |
| `bi_5k` | standard；合并中心距离至少4；缺口折算；half端点检查；区间极值检查；反弹修正 |
| `bi_4k` | standard；原始极值距离至少4且分型窗口不共用M；不检查端点与区间极值；不修正 |
| `bi_strong` | 继承bi_5k，标准失败后增加强势判断，振幅比例0.95 |
| `bi_secondary` | 虽有注释描述，当前 `run()` 实际返回空笔列表 |

注意：配置类里的比例初值是0.9，但命名强势预设用0.95。
因此，读类字段默认值不等于知道最终运行参数。

**每次从空状态开始**

`_BiBuilder` 保存输入，建立两个空列表：第一笔的候选池 `_candidates`，
以及已经接受的临时笔 `_bis`。每次调用重新建立它们，不跨调用保留状态。
行情追加或末根更新后，外层可以重新提供数据计算；这不是 Bi 对象自身的增量接口。

`run()` 按时间先处理输入列表的第一个分型，处理完才读下一个，直到全部分型处理完。
处理同一个当前分型时，可能需要在候选池里先试第一个旧候选，再试下一个旧候选；
也可能先看当前分型后面的第一个分型，再看下一个，寻找证据。
这两种查找都不会换掉当前分型。只有回到1.2第四步，才正式读取下一个输入分型。
代码中分型列表从下标0计数；中心M下标另用于距离、价格区间和依赖记录，不是分型在列表中排第几。

**第一笔从哪里开始**

尚无笔时，`_try_first_bi()` 固定1.2第四步刚读出的当前分型，只在起点候选池中换旧候选。
候选池里可能有多个旧候选，先取第一个与当前分型配对；同型就不做标准检查，反型才做标准检查。
也就是固定 $F_i$，先试 $(P_0,F_i)$，不合格再试 $(P_1,F_i)$，而不是换一个当前分型。
同型或标准失败都只放弃这一对，旧候选不删除，当前分型不变；还有下一个旧候选，就换成那个旧候选再试。
找到第一个标准通过的配对，立即接受、清空候选池、不再试剩下的旧候选，回1.2第四步读取新的当前分型。
如果试到池尾仍未成功，或池原本为空，则将当前分型追加到池尾，再回1.2第四步；
刚追加的分型不与自己配对。具体按P、Q、R次序试固定X的例子见1.2第六步。

[rule] 先试最早放入候选池的旧候选，再试下一个；不是先挑最近或价格最极端的分型。
即使开启 strong，第一笔仍必须通过标准检查。

**同型分型：延长还是不动**

已有最后一笔 `底8 -> 顶17`，新来的也是顶：顶19使末笔变成 `8 -> 19`；
顶16或顶17不改变结果。下跌笔相反，只有更低的底才延长。

`_extend_same_fx()` 只替换终点并更新依赖位置，不增加笔数。
此路径不重新运行距离、端点和区间极值检查；结束当前分型的处理，回1.2第四步读取下一输入分型，
不是结束整个 `build_bis()` 调用。
这里的“同型”是与当前末笔终点比较，不是机械地与上一条分型输入比较。

**反型分型：能否增加一笔**

末笔结束在顶，新来底；或末笔结束在底，新来顶，才尝试追加反向笔。
`_try_standard_form()` 按距离、端点、极值的顺序检查，前一项失败就停止标准检查。

下表是默认 `merged_center + half + require_peak` 的数值规则。
`s、e` 为起终点分型的中心 M 下标，内部M用k表示，范围为 `s < k < e`；i仍留给输入分型下标。

| 检查 | 向上：底s到顶e | 向下：顶s到底e |
| --- | --- | --- |
| 距离 | `e-s + 真实缺口数 >= 4` | 相同 |
| half条件一 | `L[s] < min(L[e-1], L[e])` | `H[s] > max(H[e-1], H[e])` |
| half条件二 | `H[e] > max(H[s], H[s+1])` | `L[e] < min(L[s], L[s+1])` |
| 区间极值 | 内部每个 `H[k] <= H[e]` | 内部每个 `L[k] >= L[e]` |

half检查两端朝向笔内部的一侧：起点中心与右邻、终点左邻与中心。
它问的不只是终点价格有没有涨跌，而是这两端附近的价格关系能否支持连接。
极值检查则问：所选终点是否被区间内部更高的高点或更低的低点否定。

[rule] half用严格不等号；区间极值允许相等。极值检查只看两端中心之间的M，不检查两个完整分型窗口，
也不是同时证明起点和终点都是整个跨度的双侧极值。

距离达到4时，代码直接通过，不再计算缺口；不足时才按开关补算。
每个相邻 M 对先取各自所有原始成员的价格包络，只有
`max(两个最低价) > min(两个最高价)` 才计一个缺口。
价格接触不算缺口；休市、缺时间戳不等于价格缺口。

全部通过后，`_append()` 增加一笔，起点直接使用上一笔终点，连接不留空隙。

**标准检查还有哪些选择**

- `raw_extreme`：先要求两个三根分型窗口不共用 M，即 `e-s >= 3`；
  再找到起终点中心 M 内对应的原始极值 K，检查其原始下标差是否至少为配置值。
  相等极值取最早一根，不使用缺口折算。这里的原始极值可能不同于合并后的边界价格。
- `none`：跳过端点检查；`loss`：只比较两个中心 M 的高低点。
- `strict`：将half的相应比较范围扩成完整三根窗口；
  `totally`更强，要求向上时起点中心的高价低于终点整个窗口的最低价，
  向下时起点中心的低价高于终点整个窗口的最高价。
- `require_peak=False`：跳过标准成笔的区间极值检查；
  不代表修正也不查极值，`_repair_sub_peak()` 自己仍执行该检查。

**标准失败后，强势模式还有一次机会**

只有 strong 才运行 `_try_strong()`。候选振幅是两端价格差的绝对值，不是百分比。
先比较候选振幅是否至少达到上一笔振幅乘比例；不满足，则固定当前候选的终点X，
X后面可能有多个分型，先取第一个作G，尝试假设后笔X到G。
用符号表示，固定 $X=F_i$，只更换后续 $G=F_q$，尝试 $(F_i,F_q)$。
同型或标准失败时，X不变，把下一个后续分型作为新的G再试；找到第一个标准通过的配对便停止查找，用X到G的振幅比较。
该参照比例不通过就返回失败，不再试剩下的后续分型；后面的分型全部试完仍无标准后笔也返回失败。
失败返回1.2第九步后转第十步；成功只追加原候选笔，不追加假设后笔，回1.2第四步。

例如比例0.95、上一笔振幅10、候选振幅9.6，则 `9.6 >= 9.5`，可以按强势规则接受。
这只是比例算例，不是另一组完整行情测试。
通过强势判断后，不要求刚才失败的标准条件重新通过。
向后寻找只用标准检查，不递归寻找强势笔；搜索边界是本次输入末尾，不是固定几根。

**仍未成笔，才尝试反弹修正**

修正开启、已有至少两笔、反向候选仍未被接受时，才进入 `_repair_sub_peak()`。
以下说明下跌中的反弹吸收；上涨中的回落吸收把高低关系对换。

这里的输入分型顺序为 `A顶 -> B底 -> C顶 -> D底 -> 后续分型`，不是起点候选池内容。
已有笔为 `A -> B -> C`，当前正在处理的分型是D：
这里 $D=F_i$、后续 $G=F_q$；查后续证据时固定C和D，只换q对应的G。

1. D不高于B的底，且C不高于A的顶；否则不修正。
2. D必须是A到D内部没有更低价的底；否则不修正。
3. 固定A、B、C、D。D后面可能有多个分型，先取第一个作为G。
   G为顶且高于固定C，停止查找、允许吸收；G为底且固定C到G标准通过，停止查找、不吸收。
   若这一个G既不允许也不阻止修正，就取下一个后续分型作为G，与同一个C判断；不是把C或D替换为刚查过的G。
   后面的分型全部看完仍无证据，也不吸收。
4. 允许吸收时，删除B到C，再尝试把A到B延长为A到D。
   若D没有使终点严格延长，恢复删除的笔；因此D恰好等于B仍不会成功修正。
5. 成功后记录后续确认分型所在的M下标。原笔的规则标签不会另改为专门的repair标签。

这个方法一次只修正末尾这一组，不递归清理全部历史；也不会给A到D重新跑完整的
标准成笔检查。它有自己的接受条件，不能理解为标准检查的另一种写法。
无论修正成功、被拒绝还是回滚，当前D的处理都在此结束，回1.2第四步读取D后面的输入分型。
刚才查阅过的G仍保留在输入列表中。第四步之后仍从D后面的第一个分型开始，处理完一个再读下一个，不因提前看过就跳过。

**返回什么**

`finish()` 将临时笔转换为正式 `Bi`：方向、两端时间和价格、高低价、规则与来源记录。
端点时间采用分型代表时间；来源范围覆盖两个端点分型的完整窗口；
`dep_to_index`另外保存判断使用到的证据位置。修正时证据可能比几何终点更晚。

正式对象虽然不可就地修改，后续重算仍可以换成另一个对象。
CC的Bi ID包含起终点时间，因此更换终点也可能改变ID，不能把它理解为永不变化的身份。

**同一行情关闭修正会怎样**

完整输入仍是 `A20 -> B8 -> C17 -> D6 -> E19`。
关闭修正后得到 `20 -> 8 -> 19`：D被拒绝，E与C同为顶且更高，直接延长B到C。

**分型字段与中心K线的区别**

本节例子中分型的完整`(high, low)`为A `(20,14)`、B `(14,8)`、C `(17,10)`、
D `(14,6)`、E `(19,12)`，不是简单复制中心M的两个价格。

**终点时间不等于知道结果的时间**

本节例子中修正后的下跌终点是D=M11，但判断使用E=M15的证据，
而识别E又需要右邻M16。因此不能把回看图上的A到D，当作M11时已知的事实。

`dep_to_index=15`记录证据分型中心，不是右邻16。
网站图16也区分几何终点、证据中心和证据右邻；绘图与历史回放必须保留这个区别。

**confirmed在这份代码中的含义**

`bi_confirmed_flags()`在笔生成后另外计算标记：末笔始终未确认；
依赖位置未知，或依赖下标不小于`M总数-2`，也未确认。
如果末笔的依赖未知或靠近右边缘，倒数第二笔同样未确认。

### 1.4 Standard Check

> [concept] **标准检查就是：固定一个旧候选起点和当前分型，判断这一对能不能按所选标准规则成笔。**
> 第六步调用的是 `_try_standard_form(start, end)`；这里 `start=P_j`、`end=F_i`。
> 它只回答 `True`（通过）或 `False`（不通过），不建立笔、不清空候选池，也不自己换下一个旧候选。

“标准”是CC代码中这套共用判定的名称，不表示有一套脱离配置的唯一经典标准。
本节先按主例默认 `bi_5k` 说明：合并中心距离至少4、缺口折算开启、端点方式half、区间极值检查开启。
其他配置怎样改变检查，见1.2第二步的参数说明。

```text
固定起点与终点
  → 类型：一顶一底？
  → 距离：间隔达到本次阈值？
  → 端点：两端价格关系满足本次规则？
  → 极值：内部有没有越过终点的价格？
  → True，交回调用者

任一必查项失败 → 立即False，不查后面的项。
配置明确关闭端点或极值检查 → 跳过对应项，不是跳过整个标准检查。
```

#### 1.4.a 固定输入：这一轮只检查同一对分型

第六步处理主例B时，旧候选只有A：$P_0=A=F_0$，当前 $F_1=B$。
因此检查的是 $(P_0,F_1)=(A顶20,B底8)$；它们的中心M是 $M_1,M_5$，所以 $s=1,e=5$。
分型列表中的“第一个、第二个”，不是计算距离时使用的M下标。
本次完整输入仍是A到E；下面只展示A到B检查所涉及的M，不是另换一份输入。

```text
M序号   M0  M1  M2  M3  M4  M5  M6
高价    19  20  18  16  14  12  13
低价    15  16  14  12  10   8   9
分型     .   A   .   .   .   B   .
```

固定符号：$M_s,M_e$是两端分型的中心；$H_k,L_k$是第k根M的高低价。主例 $s=1,e=5$。
检查过程中不换起点、不换终点；只有内部逐根检查时，k才移动。

#### 1.4.b 类型：先确认两端方向相反

> [concept] **标准成笔需要一顶一底，不用这一项决定同型分型留谁。**
> [example] 主例A顶、B底，类型通过；“旧顶20、当前顶19”则失败，不是比较谁更高。
>
> **判定与出口**
> - 同为顶或同为底：返回 `False`，本次标准检查结束，不检查距离或价格。
> - 一顶一底：保留这两个端点，进入下面第一项。
>
> 第六步本来就会跳过同型配对；标准函数保留这道检查，是因为其他地方也会调用它。

#### 1.4.c 距离：先确认这段运动有足够间隔

> [concept] **第一项用所选距离规则过滤过近的转折。它不比较运动幅度。**
> [example] A在M1、B在M5，中心差 `5-1=4`，达到默认阈值，进入端点检查。
>
> **默认判定：merged_center**
> 默认先算中心下标差 $e-s$，要求至少4。达到4就通过本项，进入第二项，不再数缺口。
> 不是计算两个分型在输入列表中的下标差 `1-0`。
>
> **距离不足：是否允许缺口补足**
> 距离不足4时：若不允许缺口折算，立即返回 `False`；允许时，统计这两个中心之间相邻M的真实价格缺口数g。
> $e-s+g\ge4$才通过并进入第二项，否则返回 `False`。
> 例如局部距离为3、缺口1，`3+1=4`通过；同样距离但无缺口，`3+0<4`不通过。
> 缺口比较的是每个M全部原始成员的价格范围，不是休市时间：`[10,12]`与`[14,18]`分离，算1个；
> `[10,14]`与`[14,18]`只接触，不算。
>
> **另一选项：raw_extreme，不与上面的算法混算**
> - 先要求两个三M分型窗口不共用M，即 $s+1<e-1$；失败就返回 `False`。
> - 再在各自中心M的原始成员中，顶找最高价K、底找最低价K；同价取最早一根。
> - 终点原始K下标减起点原始K下标，达到本次 `bi_min_span` 才通过；否则返回 `False`。
> - 不使用缺口折算。通过仍进入端点检查；不是距离通过就直接成笔。

#### 1.4.d 端点：检查两端价格关系，默认half

> [concept] **第二项检查两端朝向笔内部的价格关系；不是把所有中间M都检查一遍。**
> [example] A到B的half检查：起点顶20高于终点侧最高14，终点底8低于起点侧最低14，两项都通过。
>
> **比较对象**
> A的完整顶分型是M0、M1、M2；B的完整底分型是M4、M5、M6。
> half只取朝向这笔内部的部分：起点取 $M_s,M_{s+1}$，终点取 $M_{e-1},M_e$。
> 主例就是起点侧M1、M2，终点侧M4、M5；不是拿整段所有M来比较。
>
> **向下公式：顶到 底，两项必须同时成立**
> - 起点顶高于终点侧两根M的高价：$H_s>\max(H_{e-1},H_e)$。
>   主例 `20>max(14,12)=14`，第一项通过，再看下一项。
> - 终点底低于起点侧两根M的低价：$L_e<\min(L_s,L_{s+1})$。
>   主例 `8<min(16,14)=14`，第二项也通过，进入第三项。
>
> **失败与相等**
> 任何一项不成立就返回 `False`，不再查区间极值。这里必须严格大于或小于，相等不通过。
> 局部边界：终点底14、起点侧最低也是14，则 `14<14`不成立；这是单项比较，不是修改主例行情。
>
> **向上公式：底到 顶**
> 要求 $L_s<\min(L_{e-1},L_e)$ 且 $H_e>\max(H_s,H_{s+1})$。
> 用主例B底8到C顶17作对称算例：`8<min(12,13)=12` 且 `17>max(12,13)=13`，half通过。
> 这只解释向上判定，不表示第六步在建立A到B后又重新找B到C作为第一笔。
>
> **配置与出口**
> 两项通过才进入区间极值检查。若端点选项为none，就跳过端点比较，直接进入第三项；
> loss、strict、totally的范围与公式见1.2第二步，不把它们当作half的额外条件。
> **换端点选项不等于换当前这一对分型。**

端点配置的范围与方向公式：每次只选一种方式；none跳过，其他方式的不等式均为严格比较。

#### 1.4.e 极值：检查内部有没有越过终点的价格

> [concept] **第三项让终点代表这段运动的方向极值；中间有更极端的价格，就不接受这个终点。**
> [example] A到B的终点底为8，内部低价依次为14、12、10，均不低于8，本项通过。
>
> **比较对象与公式**
> 固定终点价，只检查两端中心之间的M，即 $s<k<e$。
> 向下要求每根 $L_k\ge L_e$；向上要求每根 $H_k\le H_e$。
> 不同时要求起点也是整个区间的最高或最低，更不检查整份输入中的所有M。
>
> **逐根执行：终点不动，只换被检查的M**
> 主例A到B，固定终点底 $L_5=8$，中间有三根M：
> - 先查第一根M2：`14>=8`，通过，再查下一根。
> - 再查M3：`12>=8`，通过，再查下一根。
> - 最后查M4：`10>=8`，通过；中间三根全部查完，本项通过。
>
> **失败与相等**
> 任意一根低于8就返回 `False`，不再查剩下的M；等于8允许，与half不同。
> 向上算例B到C，固定终点顶17，依次检查M6、M7、M8的高价13、14、16，都不超过17，因此通过。
> 局部失败例子：终点顶17、中间某根高价19，则 `19<=17`不成立，返回 `False`。
>
> **配置与出口**
> 若关闭require_peak，就不做本项检查。前面已通过，本函数直接返回 `True`。
> 若开启且中间所有M均合格，也返回 `True`。标准检查到此结束。

### 2.a 笔是什么：先定义对象，再讨论怎样求出它

> [concept] **笔，是把一段价格运动概括为一次上涨或下跌的结构单位：保留两端的转折，省略不需要独立表达的内部波动。**
> 哪些转折需要保留，应由明确的结构规则决定，不是凭视觉或主观判断。

第62课把核心说得很直接：

> [source] “顶和底之间的其他波动，都可以忽略不算。”

连接顶底的直线只是画法。笔表达的是：这段内部虽然有变化，但在当前结构尺度下，被视为一次方向性运动。
这不意味着每根原始K线都单调上涨或下跌；能忽略哪些内部变化，还要受分型、包含处理和间隔等条件约束。
来源：[第62课原文转载](https://chanlun108.cn/chanzhongshuochan108ke/62.html)。

### 2.b 数学对象：带有内部路径约束的方向性区间

[interpretation] 以下是帮助理解的数学化表述，不是原文公式，也不是声称CC所有配置都已经满足这些性质。

把包含处理后的K线写成按时间排列的价格区间序列：

$$
X=\bigl([L_0,H_0],[L_1,H_1],\ldots,[L_n,H_n]\bigr).
$$

一笔的几何表示可以写为：

$$
B=(a,b,p_a,p_b,d),\qquad a<b.
$$

- $a,b$：选定端点在M序列中的位置，不是输入分型列表的下标；实际时间可由来源记录定位。
- $p_a,p_b$：两端价格；顶分型取顶价，底分型取底价。
- $d$：方向。向上是底到顶，$p_b>p_a$；向下是顶到底，$p_b<p_a$。

**这五个值描述了几何形状，却还没有给出完整的合法性定义。**
两端相同、中间路径不同，未必都能构成一笔。两端的分型结构及区间 $X_{a:b}$ 还必须满足所采用的规则；
端点分型的邻根证据也需要保留。不能只看两个端点，就丢掉用于判断它们的原始路径。

> [concept] 因此，笔不是普通的“两点连线”，而是**带有内部路径约束的、有方向的价格区间**。

### 2.c 保留什么：从详细路径得到转折骨架

> [example] 以下只是价格路径的概念示意，不是完整OHLC输入，也不据此断言符合CC成笔条件。
>
> ```text
> 路径甲：10 → 12 → 11 → 15 → 14 → 20
> 路径乙：10 → 13 → 16 → 18 → 20
>
> 若内部波动按所选规则无需独立表达，两者都可能概括成：
>         10 ─────────────────→ 20
> ```

[interpretation] **这是有损的结构粗粒化：保留转折顺序、运动方向、端点价格和位置，舍弃部分内部路径细节。**
两条原始路径并不相同，却可能得到同一种笔表示；被省略的波动仍在源数据里，只是不在笔这一层独立表达。
这不是按固定频率截止的线性低通滤波，也没有因此获得最小拟合误差的保证。

选出一串端点 $a_0<a_1<\cdots<a_m$，相邻端点连接成：

$$
B_j=(a_j,a_{j+1},p_{a_j},p_{a_{j+1}},d_j),\qquad 0\le j<m.
$$

目标是得到**共享端点、上下交替的价格运动骨架**，再供线段等更高层结构使用。
第65课也提出上下交替的笔连接及唯一分解的主张；这里引用的是原文目标，
不是已经证明CC实现具有同样的唯一性或历史结果不变性。
来源：[第65课原文转载](https://chanlun108.cn/chanzhongshuochan108ke/65.html)。

### 2.d 定义与算法：合法不等于已经选定

完整的数学说明必须分开回答两个问题：

1. **合法性：什么样的价格区间允许称为一笔？** 距离、两端关系和内部极值等规则约束候选；具体口径必须明确。
2. **选择性：若有多个合法连接，为什么选这一组？** 候选顺序、同型取舍和修正优先级决定最终保留哪些连接。

CC的标准检查主要回答第一个问题；其候选池、同型延伸和修正流程参与第二个问题。
但同型延伸、强势接受与修正并非每次都重跑完整标准检查，所以不能从“程序这样输出”直接推断“每笔都满足同一套静态标准”。
是否满足期望的几何性质，要对各条输出路径分别核对。

> [conclusion] **笔是价格路径在指定规则下的一次方向性运动；笔序列是这条路径的转折骨架。**
> **第1章的流程是CC构造这个骨架的方法，不是对象本身的完整数学定义。**
> 确定地产生一组结果，不等于已经证明它唯一合法、全局最优，或最能代表价格运动。

### 2.e 矩形覆盖：把“一笔概括了什么”画成一个区域

> [interpretation] **Sid提出从几何和矩形覆盖的角度理解笔：不仅看两点之间的连线，也看这次运动在时间和价格上覆盖了什么。**
> 下面的矩形公式是对此思路的数学展开，尚未作为Project 009算法规则确定，也不是CC已有的通用覆盖条件。
> 这与前面讨论的“笔记有没有覆盖全部分支”不同：那里检查说明是否完整，这里讨论价格结构本身。

**先固定坐标。** 横轴用M序号k，纵轴用价格p；一根M是一条从低价到高价的竖线。
若改用实际时间，横轴跨度会受休市等间隔影响；矩形面积的解释也随之改变，不能混用。

**端点矩形：问两端能否包住内部运动。** 对候选笔B定义：

$$
R_B=[a,b]\times[\min(p_a,p_b),\max(p_a,p_b)].
$$

矩形的宽是这段的位置跨度，高是端点价差的绝对值。上涨和下跌可能具有同样的矩形，
所以仍必须保留起终点顺序和方向d；单靠矩形不能区分上涨与下跌。

> [example] 概念路径，不是完整K线或成笔测试：
>
> ```text
> 位置k       0   1   2   3   4
> 路径甲     10  14  12  18  20
> 路径乙     10  14   9  18  20
> ```
>
> 两者端点都给出同一个矩形：横向[0,4]，纵向[10,20]。
> 甲的全部价格点在里面；乙的位置2、价格9落在下面。
> 因而“端点相同”不意味着“内部覆盖关系相同”，更不意味着两者都应选成一笔。

![图6：同一端点矩形内的路径与越界路径](../../artifacts/experiments/chan_theory/memo0026_rectangle.png)

图6只对应上面的概念价格路径：右图的9低于矩形下边界10。这里没有完整OHLC和分型输入，不能据图判定CC成笔。

**若把完整覆盖作为候选约束，就要写出具体条件。**
例如，只针对两端中心之间的合并M，要求每一根的高低区间都落在端点矩形内：

$$
\forall k\in\{a,\ldots,b\}:\quad
\min(p_a,p_b)\le L_k\le H_k\le\max(p_a,p_b).
$$

这是待讨论的更强条件，不是对当前CC的概括。CC标准极值检查只检查方向对应的一侧，
并且不含两端中心；half另查端点局部关系，不能自动等同于上述双侧全覆盖。
若覆盖对象改为原始K线或连同分型外侧邻根一起检查，也会得到不同规则。

**不要把端点矩形与路径包围盒混为一谈。**

$$
Q_{a:b}=[a,b]\times
\left[\min_{a\le k\le b}L_k,\max_{a\le k\le b}H_k\right].
$$

Q按路径真实最高最低价定义，因此总能包住该区间；但“包得住”本身不能证明这是一笔。
R按选定端点定义，才有“中间是否越界”的问题。二者用途不同。

**从一个矩形到一串矩形，还缺选择原则。**
可以研究由共享端点、时间有序的方向性矩形表达价格运动，而不是任意放置矩形覆盖二维平面。
但即使所有数据都被覆盖，也可能有许多不同的分法；一个足够大的包围盒同样能覆盖全部数据，却失去了转折结构。

    direction: BiDir
    rule_kind: str
    dep_index: int


def build_bis(
    merged: list[MergedKline],
    fenxings: list[Fenxing],
    raw_klines: list[Kline],
    cfg: ChanConfig,
    *,
    profile_id: str,
    config_hash: str,
) -> list[Bi]:
    """从分型序列派生笔序列（纯函数，按 cfg 统一参数 + 成笔模式判定）。"""
    cfg = cfg.normalize()
    builder = _BiBuilder(merged, fenxings, raw_klines, cfg)
    builder.run()
    return builder.finish(profile_id, config_hash)


class _BiBuilder:
    """单次派生的内部状态机（不跨调用持久）。"""

    def __init__(
        self,
        merged: list[MergedKline],
        fenxings: list[Fenxing],
        raw_klines: list[Kline],
        cfg: ChanConfig,
    ) -> None:
        self._merged = merged
        self._fxs = fenxings
        self._raw = raw_klines
        self._cfg = cfg
        self._bis: list[_WorkBi] = []
        self._candidates: list[Fenxing] = []  # standard/strong 首笔候选

    def run(self) -> None:
        if self._cfg.bi_formation_mode is BiFormationMode.SECONDARY:
            # 次笔 = 高一级别一笔 = 老笔的线段(特征序列法)。**暂搁置不输出**(用户 2026-06-17)：
            # 旧"破坏式合并"在长趋势上过度合并 → 已回退；待特征序列法线段草案确认后实现 (§5.8)。
            self._bis = []
        else:
            for i, fx in enumerate(self._fxs):
                self._feed_std_strong(i, fx)

    # ── standard / strong 主循环 ─────────────────────────────────────────
    def _feed_std_strong(self, i: int, fx: Fenxing) -> None:
        if not self._bis:
            self._try_first_bi(fx)
            return
        last = self._bis[-1]
        if fx.fx_type is last.end_fx.fx_type:
            self._extend_same_fx(fx)
            return
        if self._try_standard_form(last.end_fx, fx):
            self._append(last.end_fx, fx, "standard", fx.index)
            return
        # 标准失败 → 强势 (前/后一笔)
        if self._cfg.bi_formation_mode is BiFormationMode.STRONG and self._try_strong(
            i, last.end_fx, fx
        ):
            return
        if self._cfg.bi_fractal_repair:
            self._repair_sub_peak(i, fx)

    def _try_first_bi(self, fx: Fenxing) -> None:
        for cand in self._candidates:
            if cand.fx_type is fx.fx_type:
                continue
            if self._try_standard_form(cand, fx):
                self._append(cand, fx, "standard", fx.index)
                self._candidates = []
                return
        self._candidates.append(fx)

    # ── 强势笔 (前一笔 / 后一笔；前优先) ─────────────────────────────────
    def _try_strong(self, i: int, start_fx: Fenxing, end_fx: Fenxing) -> bool:
        cand_amp = _bi_amplitude(start_fx, end_fx)
        ratio = self._cfg.bi_strength_ratio
        # 前一笔 (实时，已构建的相邻反向笔)
        prev = self._bis[-1]
        prev_amp = _bi_amplitude(prev.start_fx, prev.end_fx)
        if prev_amp > 0 and cand_amp >= ratio * prev_amp:
            self._append(start_fx, end_fx, "strong_prev", end_fx.index)
            return True
        # 后一笔 (有界 look-ahead: 从 end_fx 起首个 standard 反向笔；禁递归强势)
        nxt = self._lookahead_next_std_bi(i, end_fx)
        if nxt is not None:
            next_amp, dep_fx_index = nxt
            if next_amp > 0 and cand_amp >= ratio * next_amp:
                self._append(start_fx, end_fx, "strong_next", dep_fx_index)
                return True
        return False

    def _lookahead_next_std_bi(
        self, i: int, from_fx: Fenxing
    ) -> tuple[float, int] | None:
        """从 from_fx 起，按 standard 规则形成的下一条反向笔的 (幅度, 其端点分型下标)。

        只认 standard（不递归强势，已定 2）；取首个 standard 成笔的反向分型（有界）。
        """
        for q in range(i + 1, len(self._fxs)):
            nf = self._fxs[q]
            if nf.fx_type is from_fx.fx_type:
                continue
            if self._try_standard_form(from_fx, nf):
                return _bi_amplitude(from_fx, nf), nf.index
        return None

    # 次笔(=老笔线段, 特征序列法) 暂搁置, 见 run()。实现待线段草案确认 (用户 2026-06-17)。

    # ── 同型延伸 / sub_peak 修正 (与 standard 共用) ──────────────────────
    def _extend_same_fx(self, fx: Fenxing) -> None:
        # 同型分型永远取更极值 (两顶取更高 / 两底取更低, 第 65 课)。原 first 变体 v7 删除。
        last = self._bis[-1]
        if last.direction is BiDir.UP:
            if fx.high > _top_value(last.end_fx):
                last.end_fx = fx
                last.dep_index = max(last.dep_index, fx.index)
        else:
            if fx.low < _bottom_value(last.end_fx):
                last.end_fx = fx
                last.dep_index = max(last.dep_index, fx.index)

    def _repair_sub_peak(self, i: int, fx: Fenxing) -> bool:
        """笔破坏修正 (bi_fractal_repair, 项目变体)：反弹笔起点被反向更极值 fx 击穿时，
        仅当**反向确认守卫**通过 (fx 为真极值、反弹是假反弹) 才吸收反弹笔、把前一笔延伸到 fx。
        守卫见 ``_confirm_reverse_break``；吸收笔 dep_index = 确认处下标 (确认前恒 provisional)。
        """
        if len(self._bis) < 2:
            return False
        last, prev = self._bis[-1], self._bis[-2]
        if last.direction is BiDir.DOWN:
            if fx.high < _top_value(last.start_fx):
                return False
            if _bottom_value(last.end_fx) < _bottom_value(prev.start_fx):
                return False
        else:
            if fx.low > _bottom_value(last.start_fx):
                return False
            if _top_value(last.end_fx) > _top_value(prev.start_fx):
                return False
        if not self._is_peak(prev.start_fx, fx, _direction_of(fx)):
            return False
        confirm_index = self._confirm_reverse_break(i, fx, last)
        if confirm_index is None:
            return False
        popped = self._bis.pop()
        before = self._bis[-1].end_fx
        self._extend_same_fx(fx)
        if self._bis[-1].end_fx is before:
            self._bis.append(popped)
            return False
        self._bis[-1].dep_index = max(self._bis[-1].dep_index, confirm_index)
        return True

    def _confirm_reverse_break(self, i: int, fx: Fenxing, last: _WorkBi) -> int | None:
        """反向确认守卫 (bi-v1 笔破坏修正小节，项目变体)。

        fx 击穿反弹笔 ``last`` 起点后，从 fx 在分型序列向后**有界扫描**：
        - 若价格在「从反弹笔顶/底 T 形成有效反向笔」**之前**先**越过 T 的极值** →
          反弹是假反弹、fx 是真极值 → 返回确认处合并下标 (供 dep 水位线，确认前恒 provisional)。
        - 若先形成「T→反向有效笔」 → 反弹是真实摆动、T 成立 → 返回 ``None`` (不吸收)。
        - 扫到末尾两者皆无 (数据不足) → ``None`` (保守不吸收，随回补再判)。
        """
        t = last.end_fx
        up = last.direction is BiDir.UP
        for q in range(i + 1, len(self._fxs)):
            g = self._fxs[q]
            if up:
                if g.fx_type is FxType.TOP and g.high > t.high:
                    return g.index
                if g.fx_type is FxType.BOTTOM and self._try_standard_form(t, g):
                    return None
            else:
                if g.fx_type is FxType.BOTTOM and g.low < t.low:
                    return g.index
                if g.fx_type is FxType.TOP and self._try_standard_form(t, g):
                    return None
        return None

    def _append(
        self, start: Fenxing, end: Fenxing, rule_kind: str, dep_index: int
    ) -> None:
        self._bis.append(_WorkBi(start, end, _direction_of(end), rule_kind, dep_index))

    # ── 标准成笔判定 (距离 → 端点检查 → 端点极值) ───────────────────────
    def _try_standard_form(self, start: Fenxing, end: Fenxing) -> bool:
        if start.fx_type is end.fx_type:
            return False
        if not self._check_distance(start, end):
            return False
        if not self._check_endpoint(start, end):
            return False
        if self._cfg.bi_require_peak and not self._is_peak(
            start, end, _direction_of(end)
        ):
            return False
        return True

    # ── 距离 (bi_span_mode 分派) ─────────────────────────────────────────
    def _check_distance(self, start: Fenxing, end: Fenxing) -> bool:
        if self._cfg.bi_span_mode is BiSpanMode.MERGED_CENTER:
            return self._check_center_span(start, end)
        return self._check_raw_extreme(start, end)

    def _check_center_span(self, start: Fenxing, end: Fenxing) -> bool:
        base_span = end.index - start.index
        if base_span >= self._cfg.bi_min_span:
            return True
        if not self._cfg.bi_gap_as_bar:
            return False
        gap_count = sum(
            1
            for i in range(start.index, end.index)
            if self._has_gap(self._merged[i], self._merged[i + 1])
        )
        return base_span + gap_count >= self._cfg.bi_min_span

    def _check_raw_extreme(self, start: Fenxing, end: Fenxing) -> bool:
        # ① 不共用 K (三元窗口无公共合并单元，内建)
        if start.index + 1 >= end.index - 1:
            return False
        # ② 极值原始 K 索引差 ≥ bi_min_span
        if end.fx_type is FxType.TOP:
            start_raw = self._extreme_raw_index(start, want_high=False)
            end_raw = self._extreme_raw_index(end, want_high=True)
        else:
            start_raw = self._extreme_raw_index(start, want_high=True)
            end_raw = self._extreme_raw_index(end, want_high=False)
        return end_raw - start_raw >= self._cfg.bi_min_span

    def _has_gap(self, a: MergedKline, b: MergedKline) -> bool:
        a_lo, a_hi = self._raw_extremes(a)
        b_lo, b_hi = self._raw_extremes(b)
        return max(a_lo, b_lo) > min(a_hi, b_hi)

    def _raw_extremes(self, u: MergedKline) -> tuple[float, float]:
        members = self._raw[u.start_index : u.end_index + 1]
        return min(k.low for k in members), max(k.high for k in members)

    def _extreme_raw_index(self, fx: Fenxing, *, want_high: bool) -> int:
        u = self._merged[fx.index]
        members = self._raw[u.start_index : u.end_index + 1]
        if want_high:
            best = max(range(len(members)), key=lambda i: (members[i].high, -i))
        else:
            best = min(range(len(members)), key=lambda i: (members[i].low, i))
        return u.start_index + best

    # ── 端点有效性 (bi_endpoint_check；none 跳过) ───────────────────────
    def _check_endpoint(self, start: Fenxing, end: Fenxing) -> bool:
        method = self._cfg.bi_endpoint_check
        if method is BiEndpointCheck.NONE:
            return True
        s_pre, s_mid, s_next = self._fx_units(start)
        e_pre, e_mid, e_next = self._fx_units(end)
        if start.fx_type is FxType.TOP:  # 向下笔: 顶 → 底
            if method is BiEndpointCheck.HALF:
                item2_high = max(e_pre.high, e_mid.high)
                self_low = min(s_mid.low, s_next.low)
            elif method is BiEndpointCheck.LOSS:
                item2_high = e_mid.high
                self_low = s_mid.low
            else:
                item2_high = max(e_pre.high, e_mid.high, e_next.high)
                self_low = min(s_pre.low, s_mid.low, s_next.low)
            if method is BiEndpointCheck.TOTALLY:
                return s_mid.low > item2_high
            return s_mid.high > item2_high and e_mid.low < self_low
        else:  # 向上笔: 底 → 顶
            if method is BiEndpointCheck.HALF:
                item2_low = min(e_pre.low, e_mid.low)
                cur_high = max(s_mid.high, s_next.high)
            elif method is BiEndpointCheck.LOSS:
                item2_low = e_mid.low
                cur_high = s_mid.high
            else:
                item2_low = min(e_pre.low, e_mid.low, e_next.low)
                cur_high = max(s_pre.high, s_mid.high, s_next.high)
            if method is BiEndpointCheck.TOTALLY:
                return s_mid.high < item2_low
            return s_mid.low < item2_low and e_mid.high > cur_high

    def _is_peak(self, start: Fenxing, end: Fenxing, direction: BiDir) -> bool:
        if direction is BiDir.UP:
            thr = _top_value(end)
            return all(u.high <= thr for u in self._merged[start.index + 1 : end.index])
        thr = _bottom_value(end)
        return all(u.low >= thr for u in self._merged[start.index + 1 : end.index])

    def _fx_units(self, fx: Fenxing) -> tuple[MergedKline, MergedKline, MergedKline]:
        return (
            self._merged[fx.index - 1],
            self._merged[fx.index],
            self._merged[fx.index + 1],
        )

    # ── 输出 ─────────────────────────────────────────────────────────────
    def finish(self, profile_id: str, config_hash: str) -> list[Bi]:
        out: list[Bi] = []
        for wb in self._bis:
            up = wb.direction is BiDir.UP
            start_price = _bottom_value(wb.start_fx) if up else _top_value(wb.start_fx)
            end_price = _top_value(wb.end_fx) if up else _bottom_value(wb.end_fx)
            rule_id = _rule_for(wb, self._cfg.bi_span_mode)
            trace = StructTrace(
                algo_card_id=_ALGO_CARD_ID,
                rule_id=rule_id,
                profile_id=profile_id,
                config_hash=config_hash or None,
                source_from_ts=self._merged[wb.start_fx.index - 1].start_ts,
                source_to_ts=self._merged[wb.end_fx.index + 1].end_ts,
                merged_from_index=wb.start_fx.index,
                merged_to_index=wb.end_fx.index,
                dep_to_index=wb.dep_index,
            )
            out.append(
                Bi(
                    period=wb.end_fx.period,
                    direction=wb.direction,
                    start_ts=wb.start_fx.timestamp,
                    end_ts=wb.end_fx.timestamp,
                    start_price=start_price,
                    end_price=end_price,
                    high=end_price if up else start_price,
                    low=start_price if up else end_price,
                    trace=trace,
                )
            )
        return out


def _rule_for(wb: _WorkBi, span_mode: BiSpanMode) -> str:
    """rule_id 按成笔实际规则派生 (bi-v1 §7)。standard 再按 span_mode 分 5k/4k。"""
    up = wb.direction is BiDir.UP
    if wb.rule_kind == "strong_prev":
        return _RULE_STRONG_PREV[0 if up else 1]
    if wb.rule_kind == "strong_next":
        return _RULE_STRONG_NEXT[0 if up else 1]
    if wb.rule_kind == "secondary":
        return _RULE_SECONDARY[0 if up else 1]
    # standard
    pair = _RULE_STD_MERGED if span_mode is BiSpanMode.MERGED_CENTER else _RULE_STD_RAW
    return pair[0 if up else 1]


def _bi_amplitude(start_fx: Fenxing, end_fx: Fenxing) -> float:
    """笔幅度 = abs(端点价差)（绝对价差，本轮锁定）。方向由 end_fx 决定。"""
    if end_fx.fx_type is FxType.TOP:  # 向上笔: 底→顶
        return abs(_top_value(end_fx) - _bottom_value(start_fx))
    return abs(_bottom_value(end_fx) - _top_value(start_fx))  # 向下笔: 顶→底


def _direction_of(end_fx: Fenxing) -> BiDir:
    return BiDir.UP if end_fx.fx_type is FxType.TOP else BiDir.DOWN


def _top_value(fx: Fenxing) -> float:
    return fx.high


def _bottom_value(fx: Fenxing) -> float:
    return fx.low
