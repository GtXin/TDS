## 0. 范围与目的

> [core] **线段划分不是每次价格反向就画一段，而是判断哪个转折足以成为两段之间的分界。** 先选起步，再检验结束位置；确认一个分界后，下一段从同一点接续。

全文围绕一个问题展开：**从 A 开始的上行，应该在 D 结束，还是继续延长？** 用原始点 A、B、C……和笔 B1、B2、B3……说明判断，不另换一套点名。第 1 章先给六步概述，再按时间展开；第 2 章解释几何含义；附录保留来源与核验记录。

[scope] 当前服务于阶段 7.4 的算法研究，不是完整实现规格，也不批准 `XianduanSeries` 实现。输入是首尾相接、上下交替的有效笔，笔的高低价取两端价格的极值。首段采用本文约定的严格三笔右移搜索；平价、复杂结构与历史回改等未决规则集中在 1.4。已有笔、分型、合并和绘图类不因本篇而改变。

### 0.a 点、笔与方向

> [concept] **点记录位置，一笔连接相邻端点，线段则对连续的笔作更高一层的分组。** 后面的比较都指价格，字母顺序表示时间，不能把两种顺序混为一谈。

```text
点的时间顺序： A → B → C → D → E → F → G → H → I → J
对应的笔：       B1  B2  B3  B4  B5  B6  B7  B8  B9
笔的方向：       上  下  上  下  上  下  上  下  上
```

- `p_A` 是 A 的价格，`t_A` 是 A 的时间。B1 是 A→B，B2 是 B→C，B3 是 C→D；点 B 不是笔 B1。
- `B_i_S`、`B_i_E` 是第 i 笔起、终点的价格。例如 `B3_E=B4_S=p_D`，说明 B3、B4 共享 D。
- `L_i=min(B_i_S,B_i_E)`、`H_i=max(B_i_S,B_i_E)`。`[L_i,H_i]` 是笔的价格区间，不是它的时间范围。

正文里的“F>D”均指 `p_F>p_D`，不是 F 的时间晚于 D。同样，“向上合并”指高、低边界的取值规则，不代表被合并的原始笔必须向上。

判断上行 A→D 在哪里结束时，候选结束点是 D、F、H……这些高点；E、G、I……是回撤低点，不能结束这条上行段。判断后面的下降段在哪里结束时，才把低点作为结束候选。**同一个点的角色，要连同正在判断的方向一起说明。**

### 0.b 起步不等于结束

> [core] **三笔通过起步检查，只说明可以从这里开始找一条线段，不说明第三笔的终点已经是分界。**

全文主例不变；各步骤标注“独立例”的输入仅用于说明另一个分支：

```text
点             A     B     C     D     E     F     G
价格          100   110   105   115   108   112   103
笔间方向         上    下    上    下    上    下
```

前三笔的区间是 `[100,110]、[105,110]、[105,115]`，公共部分为 `[105,110]`；A 最低、D 最高。因此 A→D 通过本文的上行起步检查，但读到 D 时，D 仍是候选，后面的笔才可能提供结束依据。

标准线段至少三笔，开始三笔有公共价格区间；在连续交替的笔序列中，完整线段由低到高或由高到低，成员笔数为奇数。这些是结构要求，不是“三笔一到就结束”。[第77课](https://chzhshch.org/2007/09/05/0675-教你炒股票77/)

[concept] **特征序列是按时间排列、用于分界判断的反向笔区间。** 判断上行结束，取下降笔 B2、B4、B6……的 `[L,H]`；判断下降结束，改取上升笔。这里的“反向”是相对于正在考察的上行或下降运动，不是说相邻特征元素的方向交替。

**有效区间是处理包含后实际用于比较的元素。** 没有合并时，一个有效区间对应一根原始笔；合并后，T 可以代表 B4、B6 两根下降笔。B4、B5、B6 仍在原始输入中，T 不替代它们，也不改变成员归属。

**区间的顶、底转折，要同时看高边和低边。** 最近三个有效区间中，中间区间的高、低边都严格高于左右，称为顶转折；都严格低于左右，称为底转折。这里只比较笔派生的区间，不重新寻找原始 K 线分型；平价另见 1.4。

[concept] **特征缺口是相邻特征元素之间的价格空隙。** `[105,110]` 与 `[112,115]` 有缺口；与 `[108,115]` 是重叠，与 `[110,115]` 是同价接触。后两者都没有正宽度缺口。后文必须先明确在比较哪两个元素，再说有无缺口。

### 0.c 一次判断要保留什么

> [core] **保留同一个待检验分界，直到证据决定确认它、替换它，或继续等待。** 不能把“没有确认”直接理解为“已经否定”。

主例开始判断时，保存 A、上行方向、候选 D，以及已读笔 B1～B3。随着读取继续，另外保留当前步骤、比较阈值、合成区间及其原始成员；原始点和笔不因候选变化而删除。

- **等待 D**：还缺相关笔，D 不变；记录下一根应读哪一笔。
- **否定 D**：出现了反对这个候选分界的证据，改查实际的新高点，如 F 或 H。
- **确认 D**：依据本篇对应规则，把 D 记为上行结束、下降开始的位置。
- **规则未决**：数据已有，但平价等情况缺少规则；暂停依赖该规则的判断，不能只等待新数据。

第四、第五步都可能更新合成区间，也都可能继续向后移动比较位置；**这些中间变化并不自动更换 D。** 只有否定 D 的分支才去第六步改查实际新高，确认 D 的分支才结束这次分界判断。

一次局部比较不等于整次计算。本文按时间读取已完成笔，等待时保留判断位置；完整输入先校验，后来新增或回改的数据也不能绕过输入检查。这里只规定研究过程，不预设未来 API 如何保存、恢复或重算状态。

## 1. 线段的分界算法

### 1.1 流程概述

> [workflow] **起点决定从哪里开始，后续证据决定在哪里分段。** 下面先讲上行；下降按 1.4 镜像，原点名不变。

1. **选起步**：从 A 后的 B1/B2/B3 开始检查。通过则保留 A→D；发现当前起点明确失败就右移一笔；点接触不单独暂停，剩余纯端点平价见 1.4。
2. **只分流**：比较 E 与 C。E<C 去第三步，E>C 去第四步，E=C 暂停等待规则。
3. **直接下破后固定 D、E**：简单回摆中，先破 D 则上行延续，先破 E 则确认 D 为分界；两端未破就依次读下一笔。
4. **检查下降区间**：每次先看反弹是否超过 D；没有新高，才处理下一根下降笔的包含。在本步既定前提下，不包含就已形成顶转折；当前区间无缺口则确认 D，有缺口才去第五步。
5. **有缺口，再检查反弹区间**：从 D 后的 B5/B7/B9……持续处理包含，用最近三个有效区间找底。没有底就换下一组，D 不动；底先成立则确认 D，新高先超过 D 则否定它，同次冲突则未决。
6. **落实结果与接续**：写明成员、分界和证据位置；确认 D 后从 D 接续，替换 D 后重建新候选的比较区间，不能跳过未解决的规则。

**第三、第四步是二选一，第五步只接第四步的有缺口出口。** 主例走 1→2→4→6；直接下破例走 1→2→3→6；缺口例走 1→2→4→5→6。第四步途中再跌破 C，不自动改走第三步；第五步也不是所有“尚未跌破”的统称。

令当前第一笔编号 s=1。按 B1/B2/B3、B2/B3/B4、B3/B4/B5……尝试，直到第一组通过或剩余笔不足。前一组用 A/B/C/D，后一组用 B/C/D/E；移动的是窗口，不是原点名。每组按以下顺序检查：

- **先看公共区间。** `ZL=max(L_s,L_{s+1},L_{s+2})`，`ZH=min(H_s,H_{s+1},H_{s+2})`。ZL>ZH 表示无重叠，s 加 1，仍在第一步试下一组；ZL≤ZH 则继续检查端点。ZL=ZH 只是共同价格只有一个点，不能据此宣布规则未决或停止搜索。
- **先排除已经确定的端点失败。** 第一组上/下/上时，C<A 或 D<B 任一成立，就否定 A 起点并右移到 B；下/上/下时，C>A 或 D>B 任一成立，同样右移。即使另一项恰好平价，已成立的失败条件也不能被平价挡住。
- **无明确失败，再处理剩余平价及通过条件。** A=C 或 B=D 且没有上述失败时，本章的严格起步研究仍待 1.4 决定；CC 的处理见 3.b 和 4.3，不能说代码也暂停。无平价时，上/下/上要求 `A<C<B<D`，下/上/下要求 `A>C>B>D`；从 B 下行则对应 `B>D>C>E`。通过后去第二步。

**通过、失败或不足三笔，各自去哪**

- **通过。** 第一组通过就固定候选 A→D，方向与 B1 一致，停止右移，去第二步看 B4；B4 未到就等 E。若下一组通过，则固定 B→E，方向与 B2 一致，去第二步的下降镜像看 B5；E 仍未确认。

#### 第四步：判断 B2、B4 及后续下降区间能否确认 D

> [core] **先看反弹是否创新高；没有创新高，再看新下降区间是否被当前区间包含。包含就合并、继续等；不包含则顶转折已成立，直接检查缺口。** D 始终是这次待检验的结束点，合并改变的是比较区间，不是原始笔。

本步由第二步 E>C 进入，且第一步已保证 D>B。主例保留 A→D，左侧区间为 B2，中间区间起初为 B4；下一根下降笔先作为右侧区间参与比较：

**第一项：检查反弹是否创新高，第一次比较 F 与 D**

B4 从 D 回落到 E，B5 从 E 反弹到 F。保留起点 A，比较反弹高点 F 与候选高点 D：

- **F>D。** 原上行又创新高，去第六步把候选 A→D 延长为 A→F，候选成员 B1～B5。D 成为内部点，F 是新的待确认结束点；随后仍需读取 B6，但不再用它确认旧 D。新候选的历史重建限制见第六步。
- **F<D。** 没有创新高，保留 A、D，读取 B6（F→G），进入本步第二项。
- **F=D。** 同价取舍未定，保留状态，按 1.4 暂停，不当作延长或确认。

缺 B5 就等 F；F<D 而缺 B6 就等 G。以后读到 B7、B9……时，也先把其高点 H、J……与仍待检验的 D 比较；若创新高，使用实际的新高点替换 D。

**第二项：比较新低点，决定合并还是进入缺口检查**

第一次比较的两个区间是 B4=`[p_E,p_D]`、B6=`[p_G,p_F]`。包含是一个区间完整覆盖另一个；原始输入仍保留，合并只改变供判断使用的区间。

D 前的 B2 与从 D 出发的 B4 不作这次包含合并。B2 保留为左侧参照，D 后的 B4/B6 才是这次处理的同类对象。[第71课](https://baiyunju.cc/1901)

**有效的上升笔 B5 保证 F>E，第一项又保证 F<D，所以 B6 的上端 F 在 B4 内。这里只需新比较 G 与 E：**

- **G<E：B4 不包含 B6。** B6 的低边伸到 B4 下方，顶转折必然成立，保留 B2/B4/B6，直接进入本步第三项检查缺口。不再设置一次独立的“顶转折是否通过”关卡。
- **G>E：B4 包含 B6。** 生成合成区间 T：高价取 `max(p_D,p_F)=p_D`，低价取 `max(p_E,p_G)=p_G`，即 T=`[p_G,p_D]`；保存来源 B4/B6，D 尚未确认。只剩 B2/T 两个有效区间，回第一项读 B7 的 H；H<D 才继续读 B8，回第二项比较新低点 I 与 T 的当前低价，而不是与旧 E 比。

> [figure] **相等时要说清楚等于谁：旧 E，还是当前 T 的低边。** 第一图尚未合并，G=E；第二图已经合并，I=L_T。两个独立输入都按现有平价约定暂停，不擅自通过或合并。

以后 T 已存在时，新的下降区间仍按这三种情况处理：新低点低于 T 的低价，就去第三项；高于 T 的低价，就继续向上合并并回第一项读下一根反弹；相等则规则未决。T 的高价仍为 D，因为任何超过 D 的新高已在第一项退出。

[reason] **为什么“不包含”已经足够，不用再检查四遍？**

```text
D > B：第一步的上行起步已保证。
E > C：第二步据此进入第四步。
D > F：本步第一项已检查。
G < E：F<D 时，由“B4 不包含 B6”推出。
```

所以中间 B4 的高、低价都高于左右。这是已有前提的推论，不是新的成段规则。也不是要求 G<C：C 参与的是 E/C 的比较，右侧比较的是 G/E。

合并后同理：T 的高价保留 D，低价只会抬高，因此仍高于左侧 B2 的低价 C；新高严格低于 D、新区间又不被 T 包含，就必然低于 T，顶转折随之成立。**这个推论只用于当前已建立的候选及其向上合并过程；候选替换后历史未重建，不能直接套用。**

**合并怎么做，以及为什么向上**

方向看的是已有的 B2→B4：高价从 B 抬到 D，低价从 C 抬到 E，两者都向上。因此采用向上合并：**高价取较高值，低价也取较高值。** 不是因为 B4、B6 本身都是下降笔，就采用向下合并。[第62课](https://chanlun108.cn/chanzhongshuochan108ke/62.html)

**第三项：用当前区间检查缺口，决定能否确认 D**

- **有缺口：去第五步补证据。** 未合并时 `p_B<p_E`，合并后 `p_B<L_T`；保留 A、D 和已读区间，D 仍未确认。

#### 第五步：固定 D，在反弹区间中持续找底

> [core] **有缺口时，第一组顶转折还不足以确认 D；继续看 D 后的反弹区间是否先降低、再抬高。** 找到这样的底转折就确认 D；没有找到就继续整理下一组。若在此之前价格先超过 D，则否定旧 D，不再等它得到确认。

**进入条件有两个：第四步的顶转折已经成立，而且左侧与中间有效区间之间有缺口。** 不是只要“还没跌破”就来第五步。待确认的分界始终是 D；本步考察的是从 D 开始的下降运动，但尚未把它宣布为一条已确认的下降线段。

[example] 独立缺口例，先看最终要比较哪些对象，再按到达顺序执行：

```text

价格          100   110   105   115   112   114   108   111   109   113

第四步的下降笔      B2         B4         B6
高价              110        115        114
低价              105        112        108

第五步的上升笔      B5         B7         B9
高价              114        111        113
低价              112        108        109
```

读到 G，第四步的顶转折成立，但 B2 高价110低于 B4 低价112，存在缺口，因此进入本步。此时只读到了 B5，不能提前使用 B7、B9。后来读到 J，三段反弹区间的高、低价都先降后升，才确认先前的 D。**底转折中间的低点是 G，确认依据到达于 J，原上行的分界却仍是 D。**

> [figure] **G、J、D 分别承担不同角色：底转折的低点、证据到达点、原上行分界。** 三幅图按到达顺序展开同一输入。

**第一项：从 D 后第一根反弹开始，按时间整理**

第一根反弹是 B5（E→F），接着是 B7（G→H）、B9（I→J）、B11（K→L）……。这些上升笔的价格区间构成第二组特征序列；中间的下降笔仍按时间读取，只是不加入这组区间。

- 有效区间列表开始为空；从 B5 开始整理已经读到的反弹笔，B5 先成为第一个有效区间。若第四步经过多次合并才进入，不漏掉此前已读到的 B7、B9；整理历史不能把确认时间写到本步入口之前。
- 每读完一根新的反弹笔，把它交给第二项处理包含，再由第三项检查底转折、第四项决定 D 的去留。没有完整新笔时不提前拿未来高点比较。
- **提前否定的简单情况：处理新笔前只有零个或一个有效区间，而新笔高点已经超过 D。** 加入它也不可能凑足三个，底转折此时不可能同时成立，直接去第六步否定 D；高点等于 D 则按 1.4 暂停。不能为了凑够三个而错过已经出现的新高。
- 其他情况按第二至第四项执行：不能一见新高就先退出，漏掉“同一根笔也使底转折成立”的冲突。

主例在 G 进入时，B5 已完整，B7 还缺 H；H 到达后，还须依次读 B8 的 I、B9 的 J。每次缺数据都记录确切位置，例如“已读 H，等 B8 的 I，再等 B9 的 J”，不笼统说等三个区间。

> [figure] **缺 H、缺 I、缺 J，是三个不同等待位置。** 同一缺口例逐次显示 G、H、I 已到时拥有哪些完整区间；没有 J 就没有完整 B9，不能提前使用其高边。

**第二项：有包含就按已有方向合并，没有包含就追加**

新反弹区间只与列表里**最后一个有效区间**比较。前者可能包住后者，后者也可能包住前者；一个区间完整覆盖另一个，就有包含。没有包含则追加新区间；有包含且方向已经建立，则用合成区间替换最后一个有效区间，原始笔全部保留。

合并方向取自列表中**倒数第二个有效区间到最后一个有效区间**的变化，不取自新笔自身的上升方向：

```text
最后区间的高、低边都比前一个低 → 向下：新高=min(两高)，新低=min(两低)
最后区间的高、低边都比前一个高 → 向上：新高=max(两高)，新低=max(两低)
```

[example] 独立包含例：B7 包含 B9，为什么这里要向下合并？

```text
点             A     B     C     D     E     F     G     H     I      J      K     L
价格          100   110   105   115   112   114   108   111   109   110.5  109.5  112

上升笔            B5         B7         B9          B11
高价              114        111        110.5       112
低价              112        108        109         109.5
```

在 J 到达之前，B5→B7 已经建立向下方向：高价114→111，低价112→108。J 到达后，B9 的 `[109,110.5]` 完全位于 B7 的 `[108,111]` 内，所以：

```text
                         B7        B9          T
高价                     111       110.5       110.5
低价                     108       109         108

H_T = min(111,110.5) = 110.5，来自 J
L_T = min(108,109)   = 108，来自 G
T 的来源成员：B7、B9

有效区间：B5、B7、B9 → B5、T
```

**B7、B9 都是上升笔，但它们所在的区间序列此前向下，因此用 min/min。** 这与第四步的 max/max 不矛盾：第四步的 B2→B4 高低价都抬高。方向性取值与非包含处理的依据分别见[第62课](https://chanlun108.cn/chanzhongshuochan108ke/62.html)和[第67课](https://chzhshch.org/2007/08/01/0614-教你炒股票67/)。

合并后只有 B5/T，尚不足三个，D 仍待定。再读 B10 的 K 和 B11 的 L，比较 T 与 B11；本例两者不包含，得到 B5/T/B11，交第三项检查。若下一根仍被包含，就再次用**当前有效区间**确定方向和合并值，不回头套用原 B7 的111。

> [figure] **先看完整输入，再看 J 与 L 到达时各做了什么。** J 到达后只剩 B5/T 两个有效区间；L 到达后才有 B5/T/B11。

![第五步包含例：min/min 合并与后续底转折](../../artifacts/experiments/chan_theory/memo0029_step5_merge.png)

**第三项：比较最近三个有效区间；不成底就准备下一组**

每次追加或合并后，都检查当前有效区间，而不只是每凑到三根原始笔才检查。少于三个时，底转折尚未成立，去第四项决定是否还能等待。三个及以上时，只比较最近三个的高、低边。

回到本步开头的缺口例，无需合并，检查中间 B7 是否低于 B5、B9：

```text
比较              左侧 B5 与 B7       右侧 B7 与 B9
高边                  H<F                 H<J
低边                  G<E                 G<I

主例高价           111<114             111<113
主例低价           108<112             108<109
```

**在这个未经合并、由 B2/B4/B6 直接进入的例子里，G<E 已由第四步保证。** 后续新得到的信息是 H<F、I>G、J>H：H 到达时比较左高边，I 到达时知道右低边，J 到达后才有完整 B9，可作出本次底转折判断。不能把 G<E 再包装成一个新关卡，也不能把它搬到合并后或右移后的任意窗口。

不要求 J>F，也不要求 I>E，更不要求填平原来的缺口。合并例则比较 B5/T/B11 的实际值：中间高价110.5低于114和112，低价108低于112和109.5，在 L 到达时取得确认 D 的证据。

> [figure] **原缺口未填平，也可能满足这里的确认条件。** 独立输入中，D 后所有低点都高于110，原缺口仍未完全回补；B7 的高、低边却已低于 B5、B9，且 J<D。图示本章规定的底转折条件，不额外增加填缺口门槛。

**第四项：结束这次判断，或返回第一项读取下一根反弹**

第二、三项完成后，把“底转折是否成立”与“本根反弹高点是否超过 D”放在同一次更新里判断：

- **底转折成立，高点严格低于 D：确认 D，去第六步。** 原上行仍是 A→D、成员 B1～B3；不把本次中间低点或最后读到的点改成旧上行终点。
- **底转折未成立，高点严格超过 D：否定 D，去第六步。** 采用实际新高点 H、J、L……作为新候选；停止寻找旧 D 的底转折证据，不是结束整个序列的研究。
- **底转折成立，同时高点超过 D：规则未决。** 保留 D、新笔和两项结果，按 1.4 等待冲突规则；已完成笔的端点不足以说明笔内哪个事件先发生。
- **高点等于 D，或转折判断依赖尚未决定的平价取舍：规则未决。** 不算严格突破，也不把相等当作已经通过。
- **底转折明确不成立，高点严格低于 D：继续等待。** 保留 D 和有效区间，回第一项按时间读下一根相关上升笔，再处理包含、再检查最近三个；不是放弃 D。
- **输入结束：返回未确认尾部。** 保存 D、已读位置、有效区间及来源，并注明下一根待读的笔；不补造底转折。缺规则时则记录具体规则，不能冒充缺数据。

> [figure] **合成区间没创新高，不代表原始价格没创新高。** 独立例 B9=[107,118] 与 B7 向下合成 T=[107,111]，有效区间不足三个，底未成立；但原始 J=118 已超过 D=115，仍应否定旧 D。T 的111不能遮掉原价118。

#### 第六步：落实 D 的结论，交代成员和接续位置

> [core] **确认 D，就在 D 分段；否定 D，就保留 A、改查实际新高；仍无结论，就保留当前状态。** 本步只登记前面判断的结果与接续位置，不重复价格比较，也不把候选范围写成已确认线段。

**确认 D：结束 A→D，下一段从 D 开始**

主例由第四步在 G 到达后确认 D：输出上行 A→D，成员 B1～B3，末笔 B3，结束点 D；B6 提供证据，但不是原上行的成员。

接续从 B4 开始，已有三笔是 B4/B5/B6，即 D→E→F→G。主例满足 `p_D>p_F>p_E>p_G`，也就是 `115>112>108>103`，因此保留下降起步候选 D→G；**G 还没有被确认是下降终点。**

接着检查 B7（G→H），与前次反弹 B5（E→F）比较。第二步的下降镜像只比较 H 与 F=112：H>F，进入第三步的反向直接突破检查；H<F，进入第四步的反向区间检查；H=F，规则未决。只有 G 时，等待 B7 的 H，不使用未来价格。

> [figure] **接续候选是 D→G，新的比较对象就变成 H 与 F。** 三个独立接续例都先在 G 确认 A→D，再局部检查 H>F、H<F、H=F。这里只核对下一次分流，不声称已经算完后续全部线段。

**等待与规则未决：保留状态，不造结果**

- **缺数据。** 记录所在步骤与下一笔：第二步等 B4 的 E；第三步按 D/E 等下一笔；第四步按原始顺序等下一个下降区间；第五步等下一个上升区间。补齐后恢复原步骤，不重找起点 A。
- **缺规则。** 保留候选、已读位置、比较阈值、合成区间和来源，说明缺的是平价、重建还是复杂结构规则；不是笼统等新笔。
- **输入结束。** 保留已确认部分与未确认尾部，返回相应状态；不能把最后一个候选自动当作已确认终点。

### 1.3 容易混淆的关系

> [core] **每一步都有自己的参照与可变对象，不能把一种判断搬到另一种判断里。**

- **第三步守住 D/E，第四、第五步都整理区间。** 第四步取下降笔，处理包含后检查顶转折及缺口；第五步取 D 后的上升笔，持续处理包含并移动窗口找底。三者都围绕当前候选 D，不能把第五步写成只换窗口、不再合并。
- **第四步不重复检查已经由前提保证的条件。** D>B、E>C、F<D 已成立时，B4 不包含 B6 就推出 G<E，顶转折随之成立。C 是左侧参照的低价，不是后续必须跌破的下界；发生合并后，右侧比较使用合成区间的当前低价。
- **第四、第五步的合并方向不必相同。** 第四步的 B2→B4 高低价都抬高，采用 max/max；第五步例子的 B5→B7 高低价都降低，采用 min/min。看有效区间的位置变化，不看原始笔的涨跌，也不凭“要找底”指定方向。
- **B7 不成底，不等于 D 被否定。** 没有新高、平价或其他未决规则，就继续处理 B9、B11……；D 不动，直到底转折或新高给出结论。B7、B9 是本步的中间区间候选，不是替换 D 的候选高点。
- **“破”必须说明破谁。** B4 跌破 B2 是 E<C；进入第三步后，B6 是否继续下破是 G<E。后一个不成立，不会把此前 E<C 改成 E>C，也不转去第四步。
- **破坏不是缺口。** `L_4<L_2` 是低价下破，`L_4>H_2` 是价格区间之间有向上缺口；参照不同，结论不能互换。
- **特征元素不是一根新的真实笔。** T 可以由 B4、B6 合成；公式相同也不意味着可以无条件套用 K 线合并，还须先确定两者是否属于允许合并的同类对象。
- **提供证据，不等于成为成员或端点。** B6 可以帮助确认 D，而原上行仍只含 B1～B3。低点 E/G/I 不能结束当前上行，但可以是后续下降的结束候选。
- **候选失败，不删除输入。** 起步右移保留前缀；候选延长保留内部笔；已确认段之间仍须连续。
- **未确认、被否定、输入无效是三件事。** 未确认保留候选；被否定才换候选；输入无效须修正数据后重新校验，不能当作某条线段不成立。

### 1.4 通用规则与未决边界

> [scope] **已明确的规则继续执行；缺数据就等指定的数据，缺规则就标明缺什么。** “未决”不是一种隐含的通过或失败，也不等于已经有可覆盖全部输入的算法。

**方向镜像：交换高低与上下，不改原点名**

下降段从高点寻找结束低点，第一组取上升笔判断底转折；需要第二组时，再取后续下降笔判断顶转折。所有高/低、上/下、严格大于/小于成对交换。

例如上行第一组 B2/B4 的缺口是 `H_2<L_4`；镜像到下降后是 `L_2>H_4`。包含也成对交换：向上取较高高价与较高低价，向下取较低高价与较低低价。第六步给出主例接续后的 H/F 比较。

**平价：保留已知规则，不替未定选择作决定**

严格突破不含等号；闭区间同价接触没有正宽度缺口；包含的数学定义允许等号，但允许等号不代表任何同价区间都可直接合并。

[open question] 平顶/平底是否构成转折、并列极值取早还是取晚，以及没有明确失败的纯起步端点平价，仍属本章未决研究项。起步三笔点接触不再列为独立暂停理由：先执行已确定的失败与右移。CC 的闭区间重合接受 `ZL≤ZH`，不是缺少等号规则；但通过重合不等于找到结构候选，更不等于冻结线段。其他理论选择不在本次修订中改成 CC 规则。

**成员与时间：原始数据不变，归属与确认另记**

主例 A→D 确认后，成员 B1～B3，结束位置 D，证据笔 B6；缺口例的证据笔是 B9，但也不归入原上行。相邻段共享端点，不重复占用同一成员笔；合成特征元素须保存原始笔索引及极值来源。

**复杂回摆与候选更新：缺少的规则是什么**

- **简单回摆何时需要改用内部结构判断。** 第三步有固定 D/E 的主线，但尚无完整的内部结构识别与接管规则；不能把第77课的所有嵌套情况压成两个价格比较。
- **D 改为 H 后，怎样重建 H 左侧。** 已知新候选 A→H、成员 B1～B7、下一根 B8；未知的是 B2/B4/B6 应怎样按新候选处理包含。不能预先指定 B6 或沿用旧阈值。
- **确认 D 后，怎样保留固定起点寻找更长接续。** D 后三笔不通过时，不能用首段右移搜索跳过 B4；更长候选怎样建立、保存并继续判断，尚未完整规定。
- **第二组开头就包含时，合并方向怎样初始化。** 只有一个旧有效区间就遇到包含，缺少前一个区间来确定方向；不能从“反弹笔向上”推出向上合并，也不能从“要找底”推出向下合并。若第五步第一项已因不足三个区间而明确新高否定 D，直接退出；否则保留该包含对，等待初始化规则。
- **同次更新同时出现确认与否定证据，谁优先。** 第五步的 B9 可能同时形成底转折、使 J 超过 D；端点数据没有笔内事件顺序，须另定冲突规则，不能自行择一。

第71课转载还提示其末图存在后续更正。本文保留该限制，没有声称已核验该课全部图形或穷尽第77课的复杂组合。

**旧数据改变：不能按“再来一笔”处理**

[open question] 旧笔回改后的重算范围、数值容差与缺失值处理仍需明确。本文数值例以一根已完成笔为新增信息，不推断笔内触价顺序；这些规则未解决前，不能据本文验收全输入的线段实现。

## 2. Sid 的几何解释

[interpretation] 本章解释这些规则保留了什么信息，不增加新的成段条件，也不把直观类比当成已证明的目标函数。

### 2.a 分界决定如何解释同一批笔

**分段改变的是归属，不是价格路径。** 若确认 D，D 连接前面的上行与后面的下降；若 D 被否定、原上行延至 H，D 就成为内部转折。原始 A/B/C/D……与 B1/B2/B3……都还在，变化的是哪些笔被归在同一段、哪个点承担更高一层的分界。

### 2.b 为什么保留反向区间，而不是只记低点

**区间同时保留一次运动的起、终价格，只记一个极值会丢掉另一端。** 对下降笔，比较 E、G 只知道退到哪里；同时保留 D、F，才能判断整个回撤区间是否降低，还是仅在旧范围内收缩。第五步对反弹也一样：既看从哪里反弹，也看反弹到哪里。

因此，特征序列使用 `[L,H]`，而不是只保存一串低点。它提供价格结构证据，不直接测量真实供需或参与者意图。

### 2.c 几何覆盖不等于分界规则

**矩形能展示某段覆盖的时间与价格范围，却不能单独决定在哪个点分段。** 一个大矩形也能覆盖整段历史，所以“能覆盖”不能说明为何选 D、不选 F。

要分别解决：一组笔是否合法、多个分界如何取舍、后续证据如何改变候选。本文没有定义最少矩形数、拟合误差或全局最优目标；覆盖是解释方式，不是另一个划段算法。

### 2.d 多尺度压缩与递归

**逐层分组保留较大尺度的转折，但不同层的递归不能与同一步的补证据混为一谈。** K 线→合并 K 线→分型→笔→线段，可以理解为多尺度结构压缩；它并未给出离散小波的基函数、频带或重构关系，不能直接等同于小波分解。

层级递归是由低层结构组成高层结构。第五步的第二组特征序列，则仍在同一层确认某个分界；不继续索要第三组，不等于取消层级递归。

### 2.e 缺口为什么要求额外证据

**有缺口时，判断没有换问题，仍是在问 D 能否结束原上行；换的是继续观察的区间。** 第四步看下降区间的顶转折，第五步看 D 后反弹区间的底转折。没有底就向后整理，不因第一次失败就放弃 D；先创新高才否定旧候选。

这里改变的是证据要求，不是任意调大反转幅度阈值。结构条件成立也不等于已经证明预测能力或交易收益。

### 2.f 位置时间与知道时间

**图上的分界可以落在过去，但观察者只能在证据到达后知道它。** 主例分界在 D、证据到 G 才齐；回放应分别保存 `t_endpoint` 与 `t_confirmed`，不能把最终图上的 D 当成当时已知。

软件若还设“冻结”，须单独说明冻结比理论确认多了什么条件；不能用一个时间字段代替分界位置、确认时刻和软件冻结时刻。

### 2.g 对后续类设计的影响

**类设计应保存原始事实与推导结果之间的关系，而不是只存最终折线。**

- 原始行保留合并、分型、笔和线段归属；未归属前缀、已确认成员、未确认尾部可区分。
- 起点、方向、候选终点、成员范围、证据笔与确认时间分别记录，不混用“终点”一个字段。
- 合成区间保存 H/L、成员索引与极值来源，不冒充原始 K 线或真实笔。
- 计算层给出结构、归属和证据，绘图层决定线型与标记。
- 先解决 1.4 的规则选择，再批准接口与实现；本文不自动授权线段类开发。

## 3. 第 1 章与 KWX 代码的差异

> [core] **附录代码不是第 1 章六步流程的直接翻译。两者共享特征区间、包含和转折这些工具，却在起步、确认时机、平价和尾部处理上采用了不同规则。** 因此，画出了同一条 A→D，不等于在同一时刻、凭同一种证据确认了 D。

本章只作对照，不修改第 1 章，也不修改附录 C。这里的“差异”指文档与实现之间的差异，不是价格区间的“缺口”。代码行为不自动代表理论正确；第 1 章也已经声明，它尚不是覆盖全部输入的实现规格。

### 3.a 先统一对象、编号与比较范围

第 1 章的对象是**正在检验的分界 D**：从 A 开始，后续价格决定确认、否定还是继续等待。代码则同时组织**若干相接的线段候选**，再决定哪些可以冻结、哪些仍用于尾部显示。

代码里的三个名字指的是候选位置，不是固定点名：

- **N0** 是当前较早、尚未冻结的候选，状态为 `soft_n0`；某一时刻可以是 A→D。
- **N1** 是紧随 N0 的反向候选，状态为 `pending_n1`；可以是 D→G。
- **N2** 是代码正在寻找的下一条候选，方向与 N0 相同；可以是 G 后开始的上行。它不保证一到达就让 N1 冻结。

下文沿用 B1、B2……表示原始笔。代码列表从零开始，所以 B1 是 `bis[0]`，B3 是 `bis[2]`。例如 `end_bi=2` 表示末笔 B3，几何终点是 D；`dep=5` 指依赖到 B6，不是第五个原始点。

[scope] 数值对照固定使用代码的默认 `standard` 预设。每根测试笔的高低价由两端价格生成，时间按 A、B、C……递增，确保双方看到同一批有效笔。第 1 章使用既有的有限范围核验脚本作辅助；代码一侧同时区分公开入口、候选辅助函数和区间辅助函数，不把辅助返回冒充最终结果。

[source] 版本为附录 C 的 1,353 行教学版；代码 SHA-256 为 `9d88f079ab4bf32af1538d8d2b49285eb03efd5f77a1e050c1423feba1fbd6b6`。下述函数均可在附录 C 搜索，原文件为 [xianduan.py](../../records/cc/xianduan-study-20260912/reference/manual_rebuild/algo/xianduan.py)；配置来自 [config.py](../../records/cc/xianduan-study-20260912/reference/manual_rebuild/algo/config.py)。

### 3.b 第一步：三笔起步与候选配对，不是同一个门槛

> [comparison] **第 1 章先保留一个三笔起步；代码的主流程要先找到“这一段候选＋紧接的反向候选”，才正式启动候选链。**

第 1 章第一步在 A/C/B/D 严格有序、前三笔有正宽度公共区间时，就保留 A→D，接着等 B4。代码的 `_first_xianduan()` 则从第一个起点开始，依次执行：

1. 用 `_candidate(begin, direction)` 向后寻找特征转折，取得这一段的候选。
2. 从该候选末笔的下一笔开始，再找反向候选。
3. 两个候选都有，才采用这个起点；缺任意一个，就尝试下一个原始笔起点。

`_candidate()` 自己要求至少三笔，并检查起、终点是否为候选范围内的极值，但不等同于第 1 章的严格三笔起步检查。`_basic_valid()` 中的奇数笔数、首尾方向及前三笔重叠等基础检查，并未在候选生成时全部执行，而是在冻结的 `_gate_ok()` 中约束；其公共区间允许同价接触，使用的是 `<=`。第 1 章现已撤回“点接触就暂停”的说明，但仍保留严格端点的局部筛选；两者的候选搜索和冻结顺序仍不同。

**点接触例：重合通过、起点搜索右移、输出仍可能是兜底。** 对 `100→110→90→100`，单独调用 `_basic_valid(0,2,UP)` 返回 True，单独调用 `_extreme_problem(0,2,UP)` 返回 `"start"`，因为90低于起点100。后者先查起点，不能再声称这个调用也执行了终点失败分支。真实入口在该短输入中连足够的特征元素都没有，`_candidate` 返回 None，调用方依次尝试 A、B、C 的起笔后耗尽输入；它并非实际先跑完这两个辅助检查。

公开入口最后仍画 A→B 的 forming，是搜索耗尽后的显示兜底，不能推断搜索停在 A。`pending_n1` 标签在这里没有对应的内部 N1 候选。到 B 只是下一次尝试，不等于 B 已被选定。4.4 的同一前缀续例给出真正选定及冻结的证据时点。

[example] 只提供前三笔，再把同一组输入扩展到 G：

```text
点             A     B     C     D     E     F     G
价格          100   110   105   115   108   112   103
先提供        A、B、C、D
再提供        A、B、C、D、E、F、G
```

- **只到 D：**第 1 章保留起步候选 A→D。代码尚无足够特征元素，`_candidate(0, UP)` 返回 `None`，主流程却仍可输出一条 A→D 的 `forming/pending_n1`，因为它有单独的尾部显示兜底。
- **到 G：**第 1 章第四步确认 D。代码的候选函数已经找到了 A→D，但紧接的反向候选还没找到，`_first_xianduan()` 仍返回 `None`；公开入口依然只给出 A→D 的 `forming/pending_n1`，没有 frozen 结果。

[evidence] 上述结果都从实际价格输入运行到 `build_xianduans()`，不是手工塞入 N0/N1 的状态测试。**同样的 A→D 可能来自起步候选、特征转折候选或显示兜底，不能只比折线坐标。**

输入责任也不同：第 1 章要求先检查时间、连接和方向交替；`build_xianduans()` 入口并未提供同等的整批校验，它主要假定上游已经给出有效 Bi。不能把输入校验写在文档里，就认为这个函数已经执行了它。

### 3.c 第二、三步：代码没有 E/C 的二选一分流

> [comparison] **第 1 章把“B4 直接跌破 C”单独分流；代码主要让同一个特征序列识别器处理两类价格路径。**

第 1 章第二步先比较 E/C：E<C 去第三步守住 D/E，E>C 去第四步整理下降区间。代码里没有与这一步对应的 `if E<C` 分流，也没有把简单回摆完全实现为“固定 D/E，哪个先突破就选哪个”的独立循环。

代码先由 `_EigenFX` 生成转折候选，再由 `run()`、`_first_new_extreme()` 与 `_advance_n0n1()` 决定候选延伸或替换。因此，一条直接下破的价格路径，也可能在代码中由“顶转折”辅助判断生成候选。

[example] 一组独立的直接下破输入：

```text
点             A     B     C     D     E     F     G
价格          100   110   105   115   103   112   101

下降区间          B2        B4        B6
高价             110       115       112
低价             105       103       101
```

第 1 章先有 E=103<C=105，再有 F=112<D=115、G=101<E=103，于是在第三步确认 D。

代码按时间向 `_EigenFX(UP)` 加入 B2、B4、B6，也会得到转折并生成 A→D 候选。**但 B4 的低价103低于 B2 的105，不满足第 1 章所说“中间区间高低价都高于左右”的四项严格顶转折。** 这并非数值矛盾，而是代码采用了不同的组合条件。

具体而言，代码 `_is_fx()` 对左、中、右三个已构造元素使用：

```text
顶：左高 < 中高，右高 <= 中高，右低 < 中低
底：右高 > 中高，左低 > 中低，右低 >= 中低
```

这些公式还受前面的包含处理与 `_actual_break()` 约束。不能只数条件，便断言代码一定更宽松；也不能把它们改写成第 1 章的四项严格比较。此例只证明两种路径都能取得 D 的结构证据，**不证明确认状态或全局流程相同**；公开输出仍是 3.b 所述的未冻结状态。

### 3.d 第四、五步：合并数值有相同例子，方向来源与重排规则不同

> [comparison] **第 1 章从已有有效区间的高低变化确定合并方向；代码把待分析线段方向直接存入每个特征元素，再据此取 max/max 或 min/min。**

`_Eigen.merge()` 不检查前两个有效区间是否已经建立方向。它只看 `xianduan_dir`：UP 取较高高价、较高低价，DOWN 取较低高价、较低低价。原上行的第一序列由 UP 驱动；从原上行高点开始检查第二序列时，`_revert_confirm()` 改用 DOWN 驱动。

所以，第 1 章第四步的 max/max 例子、第五步的 min/min 例子，确实可以算出相同值；**但计算值相同，不表示“什么时候允许开始合并”也相同。**

[example] 第五步刚开始就包含的独立输入：

```text
点             A     B     C     D     E     F     G      H      I
价格          100   110   105   115   112   114   113    113.5   110

反弹区间          B5             B7
高价             114            113.5
低价             112            113
```

第 1 章在 I 进入第二组研究后，只见 B5 包住 B7，尚无前后两个无包含区间建立方向，因此保留为规则未决。代码的第二序列辅助函数已经持有 DOWN，直接合并：

```text
合成高价 = min(114,113.5) = 113.5
合成低价 = min(112,113)   = 112
来源成员 = B5、B7
```

此处已从顺序输入运行辅助函数核对；它只剩一个合成元素，尚未给出转折。不能把“代码可以合并”说成“代码已经确认 D”。

**包含的两种方向也有不同待遇。** 代码在形成第二个元素时，旧元素包含新笔就合并；新笔反包旧元素则因 `exclude_included=True` 而保留为另一个元素。形成第三个元素时，才一般允许反包合并，另有平高、平低例外。第 1 章第五步则是在方向已知时，对两种包含都进行合并，没有按“第二槽位、第三槽位”分成这两套规则。

**窗口右移也不是简单删掉最左有效元素。** 代码 `_reset()` 丢开本轮已喂入的第一根原始特征笔，再把其余原始特征笔重新喂入识别器。若最左有效元素曾合并多笔，这与第 1 章保留合成结果、比较最近三个有效区间，并非同一操作。没有包含时，二者看起来都像 B5/B7/B9→B7/B9/B11；有包含后，需要比较来源成员和重建结果，不能只比较窗口编号。

### 3.e 第四步：平价、合并后的参照与前看

> [comparison] **第 1 章明确暂停的边界，代码往往已经选了处理规则；第 1 章始终用当前合成低边的地方，代码第一序列还会改查最后一根成员笔，并可能向后看两笔。**

**平价已有代码规则。** 下列独立输入让反弹高点 F 与 D 同价：

```text
点             A     B     C     D     E     F     G
价格          100   110   105   115   108   115   103
```

第 1 章第四步在 F=D 暂停。代码处理 B6 时允许“同高、低边更低”的右侧区间不被合并，`_is_fx()` 又接受右高等于中高，因此 `_candidate(0, UP)` 返回 A→D。公开入口仍未冻结它。这是已执行的平价分支差异，不能用“代码也用了严格突破”掩盖其他比较含等号的事实。

**第一、第二序列的突破参照不同。** 在 `_actual_break()` 中：

- 第一序列 PRIMARY：先比较右侧区间与**中间元素最后一根原始成员笔**的低价或高价；不直接使用整个合成元素的极值。若这项未通过，还可能读取右侧原始笔之后的第二笔。
- 第二序列 GAP_REVERT：直接比较合并后的中间元素高低价，不使用上述前看。

[example] 下列独立输入实际触发第一序列的前看路径：

```text
点             A     B     C     D     E     F     G     H      I      J     K
价格          100   110   105   115   108   116   107   114    107.5   113   106
```

按代码从 A 搜索：B4=`[108,115]` 被 B6=`[107,116]` 反包，第三元素处理允许把它们合成 `[108,116]`。最后成员 B6 的低价却是107。

读到 B8=`[107.5,114]`，其低价107.5低于合成低边108，却没有低于最后成员的107，所以第一项突破检查失败。若输入已经给到 B10=`[106,113]`，代码在考察 B8 时可前看 B10，因106<107.5而取得突破依据，最后生成 A→F 候选，依赖下标为9，即 B10。只有 A～I 的前缀时，该候选函数返回 `None`。

第 1 章会更早在 F=116>D=115 时否定旧 D；如何重建新 F 左侧的历史仍留在 1.4。因此，上例不是“同一个 D 的直接反例”，而是说明**代码已经替文档尚未决定的历史重建与可见数据规则作了具体选择**。

[evidence] 两个前缀均运行了候选辅助函数与公开入口；公开入口都只显示 A→F 的 forming，不能由候选函数成功推断 F 已冻结。代码只读取本次传入列表内的数据，不是越过列表边界；但回测若把完整未来笔序列传入，就不能把扫描位置当作当时的可见范围。

### 3.f 第五步：第二组比较相似，证据到底确认谁却不同

> [comparison] **第 1 章的第二组底转折直接回答“D 能否结束原上行”；代码的第二组辅助函数只是提供证据，主状态机还要决定现在检查哪个候选，以及是否轮到用这份证据。**

[example] 重用第 1 章的缺口例，并单独列出同次冲突变例：

```text
点             A     B     C     D     E     F     G     H     I     J
缺口例        100   110   105   115   112   114   108   111   109   113
冲突变例      100   110   105   115   112   114   108   111   109   116
```

在缺口例中，第 1 章在 J 得到第二组底证据，确认 D。单独调用代码 `_revert_confirm(UP, 2)` 也返回 `(8,5)`：第一个下标指证据笔 B9、到达点 J；第二个下标指 B6、终点 G，它可用于后续反向候选，不是把原上行终点改成 G。

但公开入口的实际结果是：

```text
A→D：soft_n0，来源 gap，尚未冻结
D→G：pending_n1，对外按 forming 显示
```

**为何辅助函数能找到 D 的证据，公开入口却没有冻结 D？** 调用轨迹显示，主流程已经把 A→D 放在 N0，把 D→G 放在 N1；后续缺口补充分支检查的是 N1 的终点 G。它调用 `_revert_confirm(DOWN, 5)`，从 G 之后的 B8 等下降笔中寻找另一组证据，而不是调用上面的 `_revert_confirm(UP, 2)`。该调用返回 `None`，所以保留 N0 soft、N1 pending。

这就是**同一个“第二序列”函数，作用于不同的候选，回答了不同的问题**。不能只证明某个辅助调用成功，就说主流程在同一时刻确认了同一分界。

代码的 `_advance_n0n1()` 还规定了不同于“所有证据按时间竞赛”的优先级：

1. 先寻找 N2，并检查 N1 能否延伸；能延伸就先返回延伸结果。
2. 随后若 N2 存在，优先交出 confirm；默认路径并不另要求“此前从未击破 N1 起点”。
3. N2 不存在时，若同时找到击破 N1 起点、又回到 N1 方向创新极值的两份证据，就决定撤销或转接；这项只检查两者存在，没有比较两份证据的先后下标。
4. 上述分支都未返回，且 N1 来自缺口，才尝试第二序列补充；这里才比较 `证据下标<=击破下标`，或没有击破。
5. 都不满足则保持未决状态。启用 strong 预设时还有单笔候选的优先分支，不属于本章默认数值对照。

冲突变例中，J=116 同时完成底证据、又超过 D。第 1 章报告规则未决；代码没有相同的冲突状态，公开入口在这个前缀仍输出上面两个未冻结对象。**它既不是照第 1 章报冲突，也不是此时直接确认 D 或改到 J。**

双方仍有明确的共同点：第二组取原运动方向的笔，使用反向运动的识别方向；第二组本身不因有缺口再索要第三组。区别在于调用对象、比较细节与最终确认调度，不能把全部差异归结为“多等一会儿”。

### 3.g 第六步：几何、结构证据、冻结与显示必须分别比较

> [comparison] **第 1 章的“确认 D”是一个分界判断；代码还把同一段分成 forming、soft 与 frozen 等生命周期状态。**

默认主流程中，N2 使 N0 冻结后，N1 升为新的 N0，N2 成为新的 N1。`gap_revert` 分支则可能同时冻结前驱 N0 与缺口候选 N1，并用第二序列的中间极值建立下一候选。两者不是“每找到一个转折就冻结末段”的同一种动作。

冻结前还要过 `_gate_ok()`：普通 confirm 检查 N0；gap_revert 检查 N0、N1，并要求两者反向相接。任一要求不满足，当前循环退出、保留未冻结状态并生成显示结果，不会只凭辅助函数的 confirm 返回就强行冻结。

[example] 独立生命周期例，使用附录 B 的原数值：

```text
点             A    B    C    D    E    F    G    H    I    J    K    L    M    N    O
价格          100  110  104  114  108  112  102  106  100  109  105  113  107  111  101

提供前 6 笔，到 G： A→D pending_n1
提供前11 笔，到 L： A→D soft_n0；D→I pending_n1
提供前14 笔，到 O： A→D frozen；D→I soft_n0；I→L pending_n1
```

三次公开入口调用中，第一条折线都还是 A→D，状态却不同。到 O 时，第一段的 `dep_to_index` 仍是5，即 B6；`confirmation_ts` 为 `None`。它保留的是该候选原来的结构依赖，**不是一个可直接读取“本次在哪个点冻结”的通用字段**。本次三个前缀也不足以证明首次冻结一定发生在 O，只证明到 L 尚未冻结、到 O 已冻结。

第 1 章要求分开保存分界位置与知道时间，这是必要的信息要求；代码已有一些 trace 字段，但不能只凭字段名认为两种时间已完整对应。完整确定首次可知时刻，需要逐前缀记录实际事件，另检查上游笔是否回改。

成员几何有共同基础：代码用连续成员笔的首、末端点组成线段，原始笔并未被改写。但 `_emit()` 会把 pending 尾段延伸到该方向的极值，甚至在没有正式候选链时生成 forming 兜底。这个输出终点不一定就是此前候选函数给出的终点，也不保证每个 forming 都满足 frozen 段的全部约束。

同样，`_feature_elements()` 是显示辅助，没有照搬识别器的全部反包例外与前看步骤。**显示矩形、候选记录、冻结结果应分别核对；图看起来一样不能替代算法对照。**

### 3.h 配置、异常与整段运行，是第 1 章尚未覆盖的另一部分

**配置不是标签装饰。** `build_xianduans()` 先调用 `cfg.normalize()`，按预设重设底层策略。本章实际核对的 standard 为 line_only/off/off/peak。单独把 break_policy 改为 strong_bi、却仍保留 standard，经过这一步会被改回 line_only；要启用该变体必须改变对应预设。

代码里实际还有第 1 章没有对应菜单的行为：

- **单笔强势段。** strong 预设可以由 `_try_strong_bi_break()` 生成单笔候选，并在 `_gate_ok()` 豁免通常的至少三笔条件。这是另外的行为，不可拿来验证第 1 章的标准段。
- **失败笔破坏吸收。** 即使默认路径也可能在反向候选未成、原方向又创新极值时，将越过原起点的区域吸收进原候选，标为 `pen_break_absorb`；冻结检查对该来源豁免通常的端点极值要求。第 1 章尚没有定义这一套接管规则。
- **选项未必已有行为。** nonstandard、oscillation 在该文件中被接收并保存，但没有相应执行判断；left_method 也不是当前入口传给 builder 的自由选择。不能从配置字段或旧注释推断所有变体已经实现。
- **每次调用重新派生。** `build_xianduans()` 创建新的 builder 与状态机，不接续上次调用内部的 N0/N1。`frozen` 在一次运行内得到保护，不等于已经证明任意新增输入、旧笔回改下的跨调用不变性。
- **规则未决没有同等的返回类型。** 第 1 章明确区分缺数据、缺规则、无效输入；代码多处使用 `None`、循环退出与 forming 兜底。它也有防御性次数上限和断言，不能把所有退出都解释成“再等一根笔即可”。

[scope] 本节的变体与异常覆盖差异来自函数控制流和配置读取，不声称本次已把 strong、absorb 或所有异常分支逐一运行到最终输出。第 1 章未覆盖，不代表代码必然正确；只是说明比较范围必须先一致。

### 3.i 对照结论与核验范围

**两边已对上的，是部分对象和局部算式；尚未对上的，是完整的判定合同。** 如果目标是复现 KWX 输出，就需要以附录代码的候选、冻结、平价、预设和尾部规则定义验收，不能直接把第 1 章当作其逐步规格。如果目标是实现第 1 章的独立解释，则必须先完成 1.4 的规则选择，再决定是否采用这些代码行为。本章不替用户选择其中一条路线。

1. **先定义什么叫确认。** 比较的是 D 的几何位置、转折证据到达，还是软件 frozen？
2. **再对齐判断条件。** 首段门槛、包含方向、反包例外、等号与第一序列前看必须明确。
3. **最后对齐生命周期。** 候选更新、第二序列作用对象、优先级、历史重建与 forming 输出分别验收。

## 4. 用代码校准第 1 章的算法

> [core] **仍然研究“从 A 出发的上行应在哪里分段”，但必须分两次作答：先找到有结构依据的 A→D 候选，再根据后续候选决定是否冻结它。** 找到转折、建立候选、冻结结果和画出尾段，是四个不同动作。

本章沿用第 1 章的点名和区间解释，但按附录 C 的实际条件、顺序和返回结果重写流程；不修改前面章节或代码。第 1 章的“确认 D”不能直接搬过来：下文明确说“找到 A→D 候选”或“冻结 A→D”。

[scope] 主流程固定为当前代码的 **standard 预设**，不是所有变体，也不声称代码等于唯一理论定义。强势笔选项另见 4.5。源码与第 3 章同一版本，入口是 `build_xianduans()`；代码注释与实际分支不一致时，以分支为准。来源：[KWX 网页](https://www.kwx.me/cc/#segment-implementation)、[保留的 xianduan.py](../../records/cc/xianduan-study-20260912/reference/manual_rebuild/algo/xianduan.py)。

### 4.1 先明确这次计算要处理什么

**一次调用处理一整份已提供的笔列表，不是只建立一条线段，也不是每调用一次就接着上次内部状态往下算。** 主循环可以反复整理候选；寻找候选的内部循环才逐根读取笔。两种循环不要混为一谈。

调用者提供有效、按时间相接且方向交替的 Bi 列表，以及配置和用于追溯的 `profile_id/config_hash`。本章继续把每笔高低价视为其端点价格的最大、最小值。入口没有完整检查时间逆序、断接或无效价格，不能把第 1 章的输入校验说成它已经实现的行为。

贯穿本章的主例，保留第 1 章的 A～G，再向后延长：

~~~text
点       A    B    C    D    E    F    G    H    I    J    K    L    M    N    O
价格    100  110  105  115  108  112  103  107  101  110  106  114  108  112  102
笔        B1   B2   B3   B4   B5   B6   B7   B8   B9  B10  B11  B12  B13  B14
~~~

**候选是一份暂定的连续笔分组。** 它保存起、终笔编号、方向、两端关键价、来源 `feature_seq/gap` 和结构依赖编号 `dep`。例如 A→D 包含 B1～B3；代码下标为0～2，`dep=5` 表示它的结构判断依赖到了 B6。

候选可能有几个，程序把正在处理的相接候选放在以下位置：

- **N0 是较早、尚未冻结的一段**，状态叫 `soft_n0`；主例先为 A→D。
- **N1 是紧接 N0 的反向候选**，状态叫 `pending_n1`；主例随后为 D→I。
- **N2 是紧接 N1、方向与 N0 相同的新候选**；主例为 I→L。它是当前计算中的临时结果，不是第三个长期保存的工作位置。
- **frozen 是已经冻结的结果列表**。本次运行不会从这个列表中取回旧段重画；这不等于证明不同调用、旧笔回改时结果都不变。

[workflow] 主流程按代码重排为六步，详见 4.3；**编号不与第 1 章逐步对应**：

1. 准备本次输入、配置与空状态。
2. 从第一个起点开始，寻找能相接的正反两个候选。
3. 只有 N0 时，先处理其延长，再决定是否登记 N1。
4. 已有 N0/N1 时，按优先级判断延长、后续候选、撤销或缺口补充。
5. 执行上一项决定，需要冻结时先检查冻结条件。
6. 把冻结段、未冻结候选和尾部显示转换为输出对象。

其中第二至第四步会反复调用同一个候选计算；下面先把这个共用计算说清楚。

### 4.2 共用计算：怎样找到一个候选

> [core] **固定起点和方向，向后找能支持某个结束位置的特征转折。找到后先返回候选，不在这里冻结。** `_candidate()` 回答的是“从这个起点能找到哪一个合格候选”，不是“整个输入从哪里开始”。

#### 先固定搜索范围与端点要求

调用者给出第一根成员笔 `begin` 和候选方向。找 A 开始的上行，`begin` 对应 B1，依次扫描 B1、B2、B3……，只把下降笔 B2、B4、B6……交给特征识别器；找 D 开始的下降，改从 B4 扫描，只交入 B5、B7、B9……。

每次调用新建识别器 `_EigenFX`。它保存左、中、右三个有效元素，以及本轮交入的原始特征笔列表。**元素可以合并，原始笔不会删除。** 本节的“向上/向下”参数始终指正在寻找的候选方向。旧元素包含新笔的条件是 `旧低<=新低且旧高>=新高`；反包则互换新旧。代码先检查旧包新，所以完全相同会走合并。

端点极值检查 `_extreme_problem()` 使用整个拟议成员范围，按以下顺序判断：

- 上行先检查有无成员低价小于起点关键低价；有则返回 `start`。再检查有无成员高价大于终点关键高价；有则返回 `end`。都没有才通过。
- 下降先检查有无成员高价大于起点关键高价，再检查有无成员低价小于终点关键低价；对应返回 `start/end`，都没有才通过。
- 同价不使这项失败。它检查起、终点是不是区间极值，不是要求每根笔单调前进。

#### 先放左侧，再形成中间元素

第一根相关笔直接成为左侧元素，不判断转折。下一根相关笔与左侧比较：

1. **左侧包含新笔，包括完全相同：合并到左侧。** 仍只有一个有效元素，读取下一根相关笔。
2. **不满足上一项：把新笔放在中间。** 此处即使新笔反包左侧，也不合并。
3. **检查前两元素方向。** 找上行时，若中间高价低于左高价；找下降时，若中间低价高于左低价，就执行本节的“右移重建”。其他情况保留左、中，读取下一根相关笔。等高或等低不在这项自动暂停。

合并的数值由固定候选方向决定，不再从前两个区间临时推测：

~~~text
候选向上：合成高价=max(两高)，合成低价=max(两低)
候选向下：合成高价=min(两高)，合成低价=min(两低)
~~~

因此，只有一个旧元素时也能合并。合成元素保留全部成员索引，方向参数不因窗口内出现回摆而改变。

#### 再放右侧：先包含，后突破，最后检查转折

已有左、中以后，新笔先与中间元素比较，按下列顺序处理：

1. **中间包含新笔，包括完全相同：合并到中间。** 右侧仍为空，读取下一根相关笔。
2. **新笔反包中间：通常也合并。** 只有两种例外：找上行时，新笔与中间同高但更低；找下降时，同低但更高。这两种不合并，把新笔作为右侧。
3. **互不包含：把新笔作为右侧。**
4. **右侧形成后，先查实际突破。** 未通过就右移重建；通过才查下面的转折公式。公式未通过也右移重建；通过才记录缺口并返回成功。

这就是第 1 章包含解释需要校准的地方：**代码对“正在形成第二元素”与“正在形成第三元素”采用不同反包规则。**

[example] 主例寻找 D 后的下降候选时，会处理上升笔 B5、B7、B9、B11：

~~~text
对象          B5          B7          B9          B11
区间       [108,112]   [103,107]   [101,110]   [106,114]

已有：左=B5，中=B7
B9 反包 B7，处于第三元素处理，允许合并。
候选方向为下降：
合成高价=min(107,110)=107
合成低价=min(103,101)=101
中间 T=[101,107]，来源 B7、B9；左侧仍为 B5。

随后 B11=[106,114] 与 T 不包含，成为右侧。
~~~

B7/B9 的原始值和中间的 B8 都保留；T 只是比较元素。后续检查须明确使用 T，还是 T 的最后原始成员 B9，不能混用。

#### “实际突破”先比较什么

**第一序列 PRIMARY** 用于 `_candidate()`：

- 找上行，先看右侧低价是否严格低于中间元素**最后一根原始成员笔**的低价；找下降，先看右侧高价是否严格高于该原始笔高价。
- 未通过时，代码查看右侧原始笔之后的第二笔。例如右侧是 B8，就可能查看 B10，不是下一根相关元素合并后的结果。
- 上行要求右侧原始笔向下，且 B10 的低价小于 B8 的低价；下降镜像为右侧向上、B10 高价大于 B8 高价。通过时，依赖编号记到被前看的笔。
- 后第二笔不存在，或比较不通过：本次突破失败，执行右移重建，不返回候选。

**第二序列 GAP_REVERT** 用于后面的缺口补充：上行看右低是否小于**合成中间低价**；下降看右高是否大于**合成中间高价**。不读取后第二笔。

主例上面的下降候选，T 的最后成员 B9 高价为110；B11 高价114>110，第一序列直接突破通过，不需要前看。第 3 章 3.e 则记录了实际需要前看的另一组完整输入。

**前看只读本次提供的数据，但可以越过内部当前扫描位置。** “程序刚扫描到 B8”不等于“调用者只提供到 B8”；逐时回放时应另一次调用只传当时已有的前缀。

#### 转折通过后，怎样得到结束点

实际突破通过后，还要按代码检查：

~~~text
上行找顶：左高 < 中高，右高 <= 中高，右低 < 中低
下降找底：右高 > 中高，左低 > 中低，右低 >= 中低
~~~

这里保留代码的等号，不改写成四项严格比较。任一项失败就右移重建。

通过以后：

- **记录缺口。** 上行用 `左高<中低`，下降用 `左低>中高`；严格成立才标为 `gap`，否则标为 `feature_seq`。同价接触不算缺口。
- **定位结束笔。** 上行在中间元素的原始成员里找最高 high；下降找最低 low。取该成员的前一根原始笔作为候选末笔。并列极值取成员列表里最早的一根。
- **检查候选范围。** 至少三根成员笔，且通过前述端点极值检查，才返回候选给调用者。来源标记与结构依赖一起返回，不在这里判断 frozen。
- **找到转折但范围不通过。** 起点 `begin` 不变；清空特征识别器，从这个拟议末笔的下一笔重新扫描，继续找更后的转折。不是换下一个起点。
- **扫描到输入末尾仍无合格候选。** 返回 `None` 给调用者。它表示这次搜索没有结果，不自动等于整个计算结束，也不是第 1 章的“规则未决”。

主例 B5/T/B11 的比较是 `114>107、108>101、106>=101`，得到底转折；`108>107` 又使它带缺口。T 最低价101来自 B9（I→J），所以末笔是 B8，终点是 I。最终返回的是 **D→I，成员 B4～B8，来源 gap，依赖 B11/L**，不是 D→G。

依赖字段也有具体写法：每次进入第三元素处理，先把 `last_evidence` 记为本次原始笔编号；前看成功则改为后第二笔编号。返回候选时，dep 取这个字段，字段为空才退回候选末笔。下面的右移重建只清空元素与已交入笔列表，没有显式清空 `last_evidence`；这是代码字段的行为，不额外保证它就是最早可知时间。

#### 右移重建：丢开哪一个，再比较谁

`_reset()` 移动的是**本轮已交入的原始特征笔列表**：丢开第一根，清空左/中/右，把剩余原始特征笔按原顺序重新交入上述规则。

例如已交入 B5/B7/B9/B11，就先丢开 B5，重新交入 B7、B9、B11；即使此前 B5 与其他笔合成过，也不是直接丢掉整个合成元素。重放过程中第一次得到转折，就立刻返回成功；全部重放仍无转折，才回到外层扫描读取下一根原始笔。原始输入列表没有被删改。

### 4.3 主流程：从输入到输出怎样执行

#### 第一步：准备这次计算

> [core] **用本次数据重新派生结果，不偷偷接续上次候选。**

- 少于三笔，直接返回空列表，整个调用结束；连尾部兜底也不画。
- 三笔及以上，先用 `cfg.normalize()` 按预设确定实际参数。默认 standard 对应 line_only/off/off/peak，不启用强势单笔分支。
- 新建 builder；此前调用的 N0/N1、冻结列表都不带入。进入第二步。

本次默认假定输入有效；若数据使代码断言或其他异常触发，调用会报错，不存在一个统一的“无效输入结果对象”。这不同于第 1 章自行定义的错误返回。

#### 第二步：从第一个起点找相接的两个候选

> [core] **先找到能继续接下去的候选链，而不是前三笔形状合适就启动。**

先固定 A，按 B1 的方向调用 4.2 的候选搜索。没有候选，就改从 B、按 B2 的方向重试；再失败就从 C、按 B3 的方向试。若已有 A→D，则固定 D，从 B4 开始搜索反向候选。

- **两个候选都有：**采用当前起点，停止右移。代码再计算一次第一候选，把它放入 N0；N1 此时仍空，进入第三步。先找到的反向候选只用于选起点，第三步会重新计算它。
- **第一候选有、反向候选无：**仍换下一个原始起点，不保留这个起点继续等。内部搜索只使用本次已提供列表。
- **所有起点试尽：**保持空工作状态，直接去第六步；三笔以上的输入可能得到一条 forming 兜底，而不是已确认首段。
- **重复计算第一候选意外返回空：**代码防御性地走同样的第六步兜底，不继续主循环。

[example] 起点失败的独立输入，不替换主例：

~~~text
点       A    B    C    D    E    F    G    H    I    J    K
价格    100  105   88   94   87   92   91   93   86   93   82
~~~

从 A 的上行搜索失败；从 B 搜到下降 B→E，再搜到上行 E→H，故从 B 启动。最后输出 B→E soft、E→H forming。B1=A→B 保留但不归入输出段。**这是参考入口真实运行结果，不是用严格三笔门槛推测的右移。** 已建立链以后的相接不能套用此处的起点跳过。

主例只给到 G 时，也有 A→D 的局部候选，但没有后续候选对，尚不能启动；给到 L 后可以找到 A→D 与 D→I，进入第三步。

#### 第三步：只有 N0，先看它能否延长，再登记 N1

> [core] **不要把仍在延长的原段过早截断，也不要把一次越过起点直接当成新段。**

例如 N0=A→D。先从 B4 搜索反向候选。若找到 D→I，就把“检查原方向新极值”的范围截止于该候选末笔 B8；若没找到，范围一直到本次输入末尾。

只在这段范围内按时间检查与 N0 同方向的笔。上行找**第一根 high>D 的上升笔**；下降镜像找第一根 low 小于 N0 终点价的下降笔。相等不延长。找到后，检查 N0 起点至这个新终点的端点极值，按次序执行：

1. **有新极值，端点检查通过：**更新 N0 终笔和终点关键价，起点不变；回到第三步，从更新后末笔的下一笔重找反向候选。没有冻结，也不沿用旧特征元素。
2. **否则，反向候选为空、有新极值、端点检查返回 start：**代码仍延长 N0，来源改为 `pen_break_absorb`。在延伸范围里记录越过原起点最深的原始笔：上行找最低 low，下降找最高 high，并列取最早。然后仍回第三步。这是代码的吸收例外，不是“起点极值检查通过”。
3. **上两项都未执行，而且反向候选为空：**停止主循环，去第六步保留 N0 和尾部显示。
4. **其余情况，反向候选存在：**把它放入 N1，N0 不改，进入第四步。

主例找到 D→I 后，在 B4～B8 里没有超过 D=115 的上升笔，所以登记 **N0=A→D、N1=D→I**。成员分别为 B1～B3、B4～B8，还没有任何冻结段。

#### 第四步：已有 N0/N1，决定延长、保留还是撤销

> [core] **先让后一个候选充分发展，再决定前一个能否冻结；不能把“跌破某个价格”单独当作整段结论。**

固定本轮的 N0/N1。先从 N1 末笔的下一笔寻找 N2，方向与 N0 一样。主例是从 B9 找上行 I→L。然后严格按以下顺序，第一次得到决定就去第五步，不执行后面的判断。

**先检查 N1 自身能否延长。** 搜索范围从 N1 后第一笔开始，有 N2 就到 N2 末笔，没有 N2 就到输入末尾。找第一根与 N1 同向、严格越过 N1 终点极值的笔，并检查 N1 起点至新终点的端点极值；全部通过，给出 `extend_n1`。未找到或端点检查失败，才继续。

**再取得两份比较依据。** 二者都从 N1 后第一笔搜索到输入末尾，各自取第一项：

- `brk` 是**首次越过 N1 起点**的笔编号。N1 下行时看 high 是否大于其起点价，N1 上行时看 low 是否小于其起点价；此搜索不筛笔方向。
- `rev` 是**首次沿 N1 方向越过其终点**的同向笔及新价。只看与 N1 同向的笔；下行找更低 low，上行找更高 high。
- 主例若 N1=D→I，下行起点115、终点101：brk 查高价>115，rev 查下降笔低价<101。没找到的各自记为空；同价不算越过。

这两项不是“前低与当前低”的含混比较：一个检查起点被越过，另一个检查回到该候选方向后是否出现新极值。

**然后依次裁决：**

1. **N2 存在：**给出 `confirm(N2)`。代码不另要求 brk 为空，也不比较 N2 与 brk 谁先出现；下一步检查 N0 能否冻结，不是此处立即冻结 N1。
2. **N2 不存在，brk 与 rev 都存在：**在 N0 原末笔至 rev 所在笔的闭区间中，选 N0 方向的最大 high（上行）或最小 low（下降），作为拟议延长终点；并列取最早。若没有同向笔，代码退回比较该区间全部笔。拟议范围通过端点极值检查，给出 `break`；任一端点检查失败，给出 `rollover`。代码在这项没有检查 brk/rev 的先后编号，不能写成“按谁先到达裁决”。
3. **上项未返回，且 N1 来源为 gap：**进入下面的第二序列补充检查。有合格证据，而且 brk 为空或证据编号<=brk，给出 `gap_revert`；否则给出 `none`。
4. **N1 不是 gap，且前面都未返回：**给出 `none`。

**缺口补充到底从哪里看。** 从 N1 末笔之后的第二根笔开始，取与 N1 同方向的笔，使用相反候选方向的识别器。例如 4.4 的独立例中，N1 是上行 E→H、末笔 B7，就从 B9 开始取上升笔，用“下降方向＋GAP_REVERT”找底；主例的 N1 是下降 D→I、末笔 B8，就从 B10 开始取下降笔，用“上升方向＋GAP_REVERT”找顶。它检查的是**当前 N1 的终点**，不能仍固定研究最初的 D。

元素形成、包含、右移和转折公式沿用 4.2，但突破使用合成中间元素、没有前看。取第一个转折，返回“证据笔编号、下一候选可用的峰值末笔编号”；不因这个第二序列自己有缺口再要求第三序列。起始笔不存在、方向与应取方向不符，或扫到末尾没有转折，都返回空，依前面的裁决给出 none。

这一项只查第二序列转折，**不再替下一候选执行至少三笔与端点极值检查**；如何登记下一候选由第五步规定。

#### 第五步：执行决定，需要冻结时先过条件检查

> [core] **判断和修改分开：第四步只交出决定，本步才更新成员范围或冻结记录。** 冻结前的检查失败，不等于删除输入或改查下一个起点。

冻结条件 `_gate_ok()` 为：至少三笔、笔数为奇数、首尾笔方向等于候选方向、前三笔公共区间非空，即 `max(三低)<=min(三高)`；通常还须通过 4.2 的端点极值检查。`pen_break_absorb` 仍查前四项，但豁免端点极值检查。

按收到的决定执行：

- **extend_n1：**只更新 N1 末笔和终点价；N0、冻结列表不改。回第四步，按新的 N1 终点重新找 N2。
- **confirm(N2)：**先检查 N0。失败则停止主循环、去第六步；通过则把 N0 加入 frozen，旧 N1 升为新 N0，N2 成为新 N1，回第四步。此处没有再对 N1、N2 执行冻结条件检查。
- **break：**删除工作位置 N1，按给出的拟议末笔和终点价延长 N0；原始笔不删除，冻结列表不改，回第三步。不是从 brk 的下一笔重找，而是从**更新后的 N0 末笔下一笔**开始。
- **rollover：**先检查 N0，失败则去第六步；通过则冻结 N0，把旧 N1 升为新 N0，并清空 N1，回第三步。没有强行把反向范围塞回旧 N0。
- **gap_revert：**分别检查 N0、N1，另要求两者反向且成员相接。任一失败，去第六步且不冻结这两段；全部通过，按原几何同时冻结 N0、N1，清空两个位置。两段的依赖编号与确认时间改记本次第二序列证据，`frozen_by=gap_revert`。
- **none：**不改任何候选，停止主循环，去第六步。它不表示所有可能未来都已失败。

gap_revert 冻结以后，还会尝试立即登记下一候选：起点取旧 N1 末笔下一笔，方向取旧 N1 反向，末笔取第二序列返回的峰值末笔。若范围至少三笔、首尾方向都对，直接放为新 N0，来源 feature_seq、依赖记到这个峰值末笔，回第三步。**这次登记没有再次执行完整端点极值或前三笔重叠检查。** 不满足登记条件就保持两位置为空，去第六步。

普通延长和普通 confirm 并不把 dep 自动改成“本次处理到哪里”。因此，不能只读旧 dep 就认定那是冻结首次可知时刻。gap_revert 单独写入证据时间，不代表每一种冻结路径都这样写。

第三至第五步共享一个主循环计数：一轮或者执行第三步，或者执行第四、第五步这一组，不是每个文字步骤各计一轮。每轮加1，最多执行4n轮，n 为本次笔数；达到上限就去第六步输出已有状态。代码没有为此单独返回“达到上限”的状态，不能把这种退出解释成已经完整算完。

#### 第六步：输出结果，并区分候选与尾部显示

> [core] **图上可以有未完成的一段，但不能因此把它当成已经通过全部条件的线段。**

先按顺序输出 frozen，再输出现有 N0（soft）。尾部只采用以下第一条适用规则：

1. **有 N1：**从其起笔到输入末尾，找与 N1 同向的极值笔。上行取最大 high，下降取最小 low，并列取最早；最终显示末笔取“候选末笔与所找到末笔编号”的较大者。来源对外改成 forming，状态仍 pending_n1，保留原 dep。这里改的是输出，不是回去改变主循环中的候选。
2. **没有 N1，但 N0 后还有输入：**从 N0 末笔下一笔开始，按反向的同向极值画一条 forming，依赖记到本次末笔。
3. **N0/N1 都为空，但最后 frozen 后还有输入：**从最后 frozen 的末笔下一笔开始，用同样规则画反向 forming。
4. **完全没有输出：**按第一根输入笔方向，从头画一条 forming。第一步已保证此时至少三笔，不适用于空输入。
5. **没有可补尾部：**只输出已有段。极值不在最后一笔时，其后输入可以尚未被覆盖，不强行把终点拉到最后时间。

无同向笔时 `_forming_end()` 防御性返回起笔编号；本章有效交替输入通常不会走到这个退化出口。

最后 `_finish()` 把每个工作范围转成 Xianduan：起点取第一成员笔起点，终点取最后成员笔终点；high/low 从**全部成员笔**取最大/最小，而不是只从两端点取值。还聚合原始/合并数据范围，写入规则、状态及追溯信息，然后返回整个列表，调用结束。

### 4.4 把同一个主例完整走一遍

> [example] **D 的几何位置可以一直不变，程序对 A→D 的把握却逐步变化。** 下列每行都重新调用公开入口，只提供当行截止点以内的数据，不把上一行的内部状态带入。

~~~text
点       A    B    C    D    E    F    G    H    I    J    K    L    M    N    O
价格    100  110  105  115  108  112  103  107  101  110  106  114  108  112  102

输入截止       返回的几何与状态
A～C          空列表，笔数不足3
D～K          A→D forming/pending_n1
L～N          A→D soft_n0；D→I forming/pending_n1
O             A→D frozen；D→I soft_n0；I→L forming/pending_n1
~~~

**到 G，取得 A→D 的结构候选。** 下降区间 B2=`[105,110]`、B4=`[108,115]`、B6=`[103,112]` 通过转折与无缺口检查，候选末笔 B3、依赖 B6。可是公开入口还没有相接的反向候选，因此只能画出 forming，不能称为 frozen。

**到 L，取得 D→I。** 4.2 已算出 B7/B9 合成 `[101,107]`，随后 B11 使底转折成立，返回有缺口的 D→I。第二步终于找到 A→D＋D→I 这一对，第三步登记 N1。第四步此时既没有 I 后的完整 N2，也没有足够的缺口补充证据，返回 none。

**到 O，取得 I→L，然后冻结的是 A→D。** I 后的下降笔为 B10=`[106,110]`、B12=`[108,114]`、B14=`[102,112]`，构成无缺口顶转折；候选 I→L 的成员 B9～B11、依赖 B14。N1=D→I 没有合格延长，第四步走 confirm，N0=A→D 通过冻结条件，于是：

~~~text
变更前：frozen=[]；N0=A→D；N1=D→I；本轮找到 N2=I→L
变更后：frozen=[A→D]；N0=D→I；N1=I→L
下一轮：找 L 后的下降候选，没有得到后续决定 → 第六步输出
~~~

D→I 虽然带 gap，本次仍优先使用已经找到的 N2；不是强行改走缺口补充分支。本例逐个检查了从0到14笔的全部前缀，因此可以说**在这份固定输入的前缀实验中，O 是 A→D 首次 frozen 的位置**。这不是任意未来扩展或上游回改下的稳定性证明。

**缺口补充真正执行的独立例。** 下面另换一份明确标注的输入；它不是主例的后续：

~~~text
点       A    B    C    D    E    F    G    H    I    J    K    L    M    N    O    P    Q
价格    100  104   76   84   75   78   77   88   75   85   79   84   78   81   79   85   76
~~~

公开入口从 B 启动，得到 N0=B→E、N1=E→H（gap）。第四步没有得到可优先使用的 N2，才对 N1 的高点 H 做第二序列检查；返回证据 B15/P、下一候选末笔 B12/M。冻结条件通过后，同时冻结 B→E 与 E→H，再登记 H→M 为新 N0。最终输出：

~~~text
B→E frozen；E→H frozen；H→M soft_n0；M→P forming/pending_n1
~~~

**这里第二序列确认的是当前 N1=E→H，并连同其前驱一起冻结。** 不能把第 1 章“最初 D 的第二组”固定套在整个候选链上。Q 仍属于输入；显示尾段结束于 P，不表示 Q 被删掉。

[example] 本例独立于上面的主例和缺口例，固定 `A100→B110→C90→D100`，仅在其后补充演示数据；不是对未来行情的预测。

1. **到 D：搜索已经推进，尚未选定起点。** A/B/C 的起笔依次尝试均无候选，首段搜索耗尽，内部 N0/N1 为空。输出分支按首笔向上方向寻找最高的同向笔终点：B110 高于 D100，暂画 A→B，状态 `pending_n1`。C、D 仍在输入中。
2. **到 H：B→E 候选可识别，但尚未启动。** 寻找下降段时比较上升笔 C→D=`[90,100]`、E→F=`[80,95]`、G→H=`[85,105]`。低边满足90>80、85≥80，高边105>95，且严格突破105>95，无缺口；端点满足 B110 为最高、E80 为最低。候选 B→E 的终点在 E，证据到 H 才齐。其后尚无接续上升候选，首段搜索仍未选定 B；公开输出仍是临时 A→B。
3. **到 K：B 被选为首段起点。** E→H 的上升候选由 F→G=`[85,95]`、H→I=`[92,105]`、J→K=`[88,102]` 给出：95<105、102≤105、88<92，严格下破且无缺口，E80/H105 也是该候选的低/高极值。B→E 与 E→H 都存在，首段启动；输出 B→E `soft_n0`、E→H `pending_n1`。A→B 保留为未归属前缀，临时线被替换。
4. **到 P：出现 H→M 的下降候选，先冻结 B→E。** 4.2 的顺序搜索中，I→J=`[92,102]`、K→L=`[88,98]`、M→N=`[82,94]` 仍依次降低，不能给出中间底；搜索右移后，用于底转折的三个元素为 `[88,98]、[82,94]、[86,104]`，低边88>82、86≥82，高边104>94，且严格突破。它们分别是 K→L、M→N、O→P 的原始区间，没有发生包含合并；I→J 不再属于当前三元素窗口，但仍保留在输入中。H105/M82 满足端点极值，候选无缺口。冻结检查通过后，B→E 变 frozen，原 N1=E→H 升为 soft N0，H→M 成为 pending N1。不是 N2 一出现就冻结原 N1。

class XianduanFreezeState(StrEnum):
    """线段冻结状态 (方案 A 显示口径)。"""

    FROZEN = "frozen"  # 已冻结 confirmed (实线; 不被普通后续改写)
    SOFT_N0 = "soft_n0"  # 准完成 N0 (软实线; 有候选终点未冻结, 可尾部延伸)
    PENDING_N1 = "pending_n1"  # 待确认 N1 (虚线 provisional; 可被击破作废)


@dataclass(slots=True)
class _XianduanCand:
    """线段候选 (特征序列内核产生 → 进 N0/N1/N2 状态机)。

    ``start_key`` = 起点关键价位 (上涨段 = 起点 low / 下跌段 = 起点 high), N1 击破判据。
    ``end_key`` = 候选终点极值 (上涨段 = 终点 high / 下跌段 = 终点 low)。延伸时随 end 更新。
    """

    start_bi: int
    end_bi: int
    direction: BiDir
    start_key: float
    end_key: float
    rule: str = "feature_seq"  # 候选来源 (feature_seq / gap / pen_break_absorb); 随候选传到输出
    dep: int = 0  # 依赖水位 (最大查阅笔下标); 随候选传到输出 (状态机不读)
    pen_break_at: int | None = None  # 笔破坏失败吸收段的内部越点笔下标 (T7; 其它段 None)
    confirmation_ts: int | None = None  # 缺口段第二序列反向分型证据笔 end_ts (§16 v10; 冻结带出)
    frozen_by: str = ""  # 冻结事件来源 ("gap_revert" = 缺口第二种反向确认; 随候选/冻结传出)


@dataclass(slots=True)
class _FrozenXianduan:
    """已冻结 confirmed 线段 (不可变语义; 不被普通后续走势改写)。"""

    start_bi: int
    end_bi: int
    direction: BiDir
    rule: str = "feature_seq"
    dep: int = 0
    pen_break_at: int | None = None  # 笔破坏失败吸收段的内部越点笔下标 (T7; 其它段 None)
    confirmation_ts: int | None = None  # 反向确认证据笔 end_ts (gap_revert §16 v10; 与几何终点分离)
    frozen_by: str = ""  # 冻结事件 ("gap_revert" = 由后继缺口反向确认原子冻结; 其它 "")


class _XianduanFreezeMachine:
    """N0/N1/N2 动态冻结状态机 (严格标准)。

    维护: frozen 冻结历史 + soft N0(准完成) + pending N1(待确认)。N0/N1 反向交替。
    5 个转移 (decision-0028 §3-quater)：
      T1 准完成 ``promote_to_n0``      : 候选 → soft N0 (无 N0 时)。
      T2 待确认 ``set_pending_n1``     : 反向候选 → pending N1 (有 N0 无 N1 时)。
      T3 确认   ``confirm_on_n2``      : N2 出现且 N1 未被击破 → 冻结 N0、N1→新 N0、N2→新 N1。
      T4 作废 + T5 延伸 ``invalidate_n1_extend_n0`` : N1 起点被严格击破 → 作废 N1、N0 延伸吞击破区。
    回算水位 = 最后 frozen 段 end+1 (``rebuild_floor``); 冻结历史不回改。
    """

    def __init__(self) -> None:
        self.frozen: list[_FrozenXianduan] = []
        self.n0: _XianduanCand | None = None
        self.n1: _XianduanCand | None = None

    # ── 查询 ──────────────────────────────────────────────────────────────────
    def rebuild_floor(self) -> int:
        """最早可重算笔下标 = 最后 frozen 段 end+1 (冻结区不回改; -1 = 无 frozen 可从 0 起)。"""
        return self.frozen[-1].end_bi + 1 if self.frozen else 0

    def is_n1_broken(self, price: float) -> bool:
        """N1 起点是否被**严格**击破 (触平不算破; 与相等值口径一致)。

        上涨 N1: 后续价 ``< 起点 low`` → 破; 下跌 N1: 后续价 ``> 起点 high`` → 破。
        """
        if self.n1 is None:
            return False
        if self.n1.direction is BiDir.UP:
            return price < self.n1.start_key
        return price > self.n1.start_key

    # ── 5 个转移 ──────────────────────────────────────────────────────────────
    def promote_to_n0(self, cand: _XianduanCand) -> None:
        """T1 准完成: 候选 → soft N0 (仅在无 N0 无 N1 时, 如首段或冻结级联后)。"""
        if self.n0 is not None or self.n1 is not None:
            raise AssertionError("promote_to_n0 须在无 N0/N1 时")
        self.n0 = cand

    def set_pending_n1(self, cand: _XianduanCand) -> None:
        """T2 待确认: 反向候选 → pending N1 (有 N0 无 N1; 方向须与 N0 反向)。"""
        if self.n0 is None or self.n1 is not None:
            raise AssertionError("set_pending_n1 须在有 N0 无 N1 时")
        if cand.direction is not _opposite(self.n0.direction):
            raise AssertionError("N1 方向须与 N0 反向")
        self.n1 = cand

    def confirm_on_n2(self, n2: _XianduanCand) -> None:
        """T3 确认: N2 出现且 N1 未被击破 → 冻结 N0、N1 升为新 N0、N2 成新 N1。

        N2 方向 = N0 方向 (= N1 的反向)。冻结后滚动窗口左移一格。
        """
        if self.n0 is None or self.n1 is None:
            raise AssertionError("confirm_on_n2 须在 N0、N1 都在时")
        if n2.direction is not self.n0.direction:
            raise AssertionError("N2 方向须与 N0 同向 (N1 反向)")
        self.frozen.append(
            _FrozenXianduan(self.n0.start_bi, self.n0.end_bi, self.n0.direction,
                      rule=self.n0.rule, dep=self.n0.dep, pen_break_at=self.n0.pen_break_at,
                      confirmation_ts=self.n0.confirmation_ts, frozen_by=self.n0.frozen_by)
        )
        self.n0 = self.n1  # N1 → 新 soft N0 (缺口段带 confirmation_ts, 下轮冻结时带出)
        self.n1 = n2  # N2 → 新 pending N1

    def invalidate_n1_extend_n0(self, new_end_bi: int, new_end_key: float) -> None:
        """T4 作废 + T5 延伸: N1 起点被严格击破 → 作废 N1; N0 延伸吞掉假反弹+击破区到新极值。

        ``new_end_bi/new_end_key`` = N0 延伸后的新终点 (由特征序列内核重算给出, S2 接入)。
        延伸后 N1 置空, 等新反向候选重新成 N1 (从击破笔后第一根反向笔起)。
        """
        if self.n0 is None or self.n1 is None:
            raise AssertionError("invalidate_n1_extend_n0 须在 N0、N1 都在时")
        self.n1 = None  # T4 作废
        self.n0.end_bi = new_end_bi  # T5 延伸
        self.n0.end_key = new_end_key

    def rollover_n1_to_n0(self) -> None:
        """T6 转接: N1 (反向候选) **跌破/突破了 N0 起点** → N1 是真强反向, N0 已完结 →
        冻结 N0、N1 升为新 soft N0、N1 置空 (下一轮从 N1 之后重找新反向)。

        与 T3(confirm) 区别: T3 靠 N2 出现确认; T6 靠 N1 自身越过 N0 起点 (强反向) 确认。
        修「N0 反向延伸吞掉越过起点的反向段 → 造 B5 反画 → 冻结硬闸断链」。
        """
        if self.n0 is None or self.n1 is None:
            raise AssertionError("rollover_n1_to_n0 须在 N0、N1 都在时")
        self.frozen.append(
            _FrozenXianduan(self.n0.start_bi, self.n0.end_bi, self.n0.direction,
                      rule=self.n0.rule, dep=self.n0.dep, pen_break_at=self.n0.pen_break_at,
                      confirmation_ts=self.n0.confirmation_ts, frozen_by=self.n0.frozen_by)
        )
        self.n0 = self.n1  # N1 → 新 soft N0
        self.n1 = None  # 下一轮重找反向 N1

    def confirm_gap_revert(self, evidence_bi: int, confirmation_ts: int) -> None:
        """T8 gap_revert_confirmed 原子转移 (§16 v10): N1 = 缺口候选、第二特征序列出反向分型 →
        **原子冻结 N0(直接前驱) + N1(缺口段)**, 两段冻结依赖水位/confirmation_ts 均反映
        ``evidence_bi`` (第二特征序列分型证据笔; 不暗示 N0 更早已 frozen); N0、N1 均置空 (调用方
        随后从 N1.end+1 重建新 N0)。

        约束 (调用方 driver 先校验, 见 run()): 当前须 soft N0 + pending 缺口 N1; N0/N1 方向相反且
        连续; 各过 ``_gate_ok``; ``evidence_bi`` 归属当前 N1。任一不满足则不调用本转移。
        **N0 保留原 rule 与自身 source_range (start/end 不变), 只标 frozen_by=gap_revert** (不塞 N1
        几何)。N1 几何终点不变, rule 保持 (gap)。
        """
        if self.n0 is None or self.n1 is None:
            raise AssertionError("confirm_gap_revert 须在 N0、N1 都在时")
        # 冻结 N0 (直接前驱): 保留原候选来源 rule 与几何; 依赖水位/confirmation_ts = evidence_bi。
        self.frozen.append(_FrozenXianduan(
            self.n0.start_bi, self.n0.end_bi, self.n0.direction, rule=self.n0.rule,
            dep=evidence_bi, pen_break_at=self.n0.pen_break_at,
            confirmation_ts=confirmation_ts, frozen_by="gap_revert"))
        # 冻结 N1 (缺口段): 几何终点不变; dep/confirmation_ts = evidence_bi (证据水位 ≠ 几何终点)。
        self.frozen.append(_FrozenXianduan(
            self.n1.start_bi, self.n1.end_bi, self.n1.direction, rule=self.n1.rule,
            dep=evidence_bi, pen_break_at=self.n1.pen_break_at,
            confirmation_ts=confirmation_ts, frozen_by="gap_revert"))
        self.n0 = None
        self.n1 = None


def build_xianduans(
    bis: list[Bi],
    cfg: ChanConfig,
    *,
    profile_id: str,
    config_hash: str,
) -> list[Xianduan]:
    """从笔序列派生线段序列（纯函数，特征序列法；签名对齐 ``build_bis``）。

    Args:
        bis: 引擎已派生的笔序列 (默认主线 = bi_5k 老笔; xianduan-v1 §5)。
        cfg: 缠论口径配置 (PR-6B: 线段默认口径固定 feature_sequence; 暂无可配置变体)。
        profile_id / config_hash: 口径身份 (供 Xianduan trace 回溯 §1.7)。

    Returns:
        线段序列 (上下交替, 带稳定 id + 轻量 trace; confirmed/provisional 由 dep 水位判)。
    """
    if len(bis) < 3:
        return []
    cfg = cfg.normalize()
    builder = _XianduanBuilder(
        bis,
        nonstandard=cfg.xianduan_nonstandard_policy is XianduanNonstandardPolicy.REPAIR,
        oscillation=cfg.xianduan_oscillation_policy is XianduanOscillationPolicy.THREE_BI,
        strong_bi=cfg.xianduan_break_policy is XianduanBreakPolicy.STRONG_BI,
    )
    work = builder.run()
    return _finish(bis, work, profile_id=profile_id, config_hash=config_hash)

@dataclass(slots=True)
class _Eigen:
    """特征元素 = 连续 (经包含合并的) 反向笔当 K 线 (第65/67课标准特征序列)。

    把每个反向笔当 K 线: high=笔区间高、low=笔区间低。``idxs`` 记所含笔下标; ``gap`` 与前一
    元素是否有缺口。包含处理 (``test_combine``) **区分两种包含方向** (用户 2026-06-20 口径 §1):
    旧元素包含新笔→恒合并; 新笔包含旧元素→exclude 模式不合并 (保转折分界, 第四/七种情况)。
    合并取值按线段方向 (上升高高、下降低低)。
    """

    xianduan_dir: BiDir
    idxs: list[int]
    high: float
    low: float
    gap: bool = False

    @classmethod
    def of(cls, xianduan_dir: BiDir, idx: int, bi: Bi) -> _Eigen:
        return cls(xianduan_dir=xianduan_dir, idxs=[idx], high=bi.high, low=bi.low)

    def test_combine(
        self, bi: Bi, *, exclude_included: bool, allow_top_equal: int | None
    ) -> str:
        """包含判定 (第65/67课包含处理) → ``combine`` / ``included`` / ``up`` / ``down``。

        - **旧元素包含新笔** (self 全包 bi) → ``combine`` (恒合并)。
        - **新笔包含旧元素** (bi 全包 self) → exclude 模式 ``included`` (不合并、成新元素, 第四/
          七种情况保转折分界); 否则 ``combine``。相等顶/底由 ``allow_top_equal`` 放行成方向
          (1=顶相等不合并 / -1=底相等不合并, 第七种情况, 见 xianduan-v1 §6 相等值口径)。
        - 无包含 → ``up`` (新笔更高) / ``down`` (新笔更低)。
        """
        if self.high >= bi.high and self.low <= bi.low:  # 旧元素包含新笔
            return "combine"
        if self.high <= bi.high and self.low >= bi.low:  # 新笔包含旧元素
            if allow_top_equal == 1 and self.high == bi.high and self.low > bi.low:
                return "down"
            if allow_top_equal == -1 and self.low == bi.low and self.high < bi.high:
                return "up"
            return "included" if exclude_included else "combine"
        if self.high > bi.high and self.low > bi.low:
            return "down"
        return "up"

    def merge(self, idx: int, bi: Bi) -> None:
        """按线段方向合并新笔 (上升取高高、下降取低低; 第65课包含处理)。"""
        if self.xianduan_dir is BiDir.UP:
            self.high = max(self.high, bi.high)
            self.low = max(self.low, bi.low)
        else:
            self.high = min(self.high, bi.high)
            self.low = min(self.low, bi.low)
        self.idxs.append(idx)


class _SeqRole(StrEnum):
    """特征序列角色 (§16 v10; 决定 ``_actual_break`` 突破判定规则)。

    - ``PRIMARY``    第一特征序列: 末原始笔 ``bis[e1.idxs[-1]]`` + k+2 前看 (第八种情况; 现状不动)。
    - ``GAP_REVERT`` 第二特征序列 (缺口第二种反向确认): 用**合并后** ``_Eigen.high/low`` 严格判、
                     **无前看** (第七/78课严格包含处理)。
    """

    PRIMARY = "primary"
    GAP_REVERT = "gap_revert"


class _EigenFX:
    """特征序列分型识别器 (候选线段方向 ``xianduan_dir``; 只接反向笔)。

    三特征元素 e0/e1/e2: 上升线段看顶分型、下降看底分型 (第67课)。**包含处理两层**: 第二元素
    用 exclude (新笔包含旧元素不合并, 保转折分界, 第四种情况); 第三元素允许合并 (第六/八种情况)。
    顶/底分型**同时校验高低点** (第二种情况防假分型); 实际突破规则随 ``sequence_role`` (§16 v10):
    PRIMARY 带前看 (第八种情况), GAP_REVERT 用合并值严格判 (第七/78课, 无前看)。
    """

    __slots__ = ("xianduan_dir", "bis", "ele", "lst", "last_evidence", "sequence_role")

    def __init__(
        self, xianduan_dir: BiDir, bis: list[Bi], *, sequence_role: _SeqRole = _SeqRole.PRIMARY
    ) -> None:
        self.xianduan_dir = xianduan_dir
        self.bis = bis
        self.ele: list[_Eigen | None] = [None, None, None]
        self.lst: list[int] = []  # 已喂入的反向笔下标
        self.last_evidence: int | None = None  # 成分型实际查阅的最大笔下标 (dep 水位)
        self.sequence_role = sequence_role

    def _is_up(self) -> bool:
        return self.xianduan_dir is BiDir.UP

    def _top_equal(self) -> int:
        # 第三元素相等边界口径 (第七种情况): 上升线段(降特征笔)=1 顶相等不合并; 下降=-1 底相等。
        return 1 if self._is_up() else -1

    def add(self, idx: int) -> bool:
        """喂入一根反向笔, 返回是否出现特征序列分型。"""
        bi = self.bis[idx]
        self.lst.append(idx)
        if self.ele[0] is None:
            self.ele[0] = _Eigen.of(self.xianduan_dir, idx, bi)
            return False
        if self.ele[1] is None:
            return self._treat_second(idx, bi)
        if self.ele[2] is None:
            return self._treat_third(idx, bi)
        # 三元素已满还没处理 → 内部不变量错误 (调用方应在出分型时停止喂入)。
        raise AssertionError("eigen sequence overflow: 3 elements already filled")

    def _treat_second(self, idx: int, bi: Bi) -> bool:
        """第二元素: exclude 包含处理 (新笔包含旧元素不合并, 保转折分界, 第四种情况)。"""
        e0 = self.ele[0]
        assert e0 is not None
        cd = e0.test_combine(bi, exclude_included=True, allow_top_equal=None)
        if cd == "combine":
            e0.merge(idx, bi)
            return False
        e1 = _Eigen.of(self.xianduan_dir, idx, bi)
        self.ele[1] = e1
        # 前两元素方向不对 (上升线段 e1 不高于 e0 / 下降线段 e1 不低于 e0) → 不可能成分型, 滑窗。
        if (self._is_up() and e1.high < e0.high) or (
            not self._is_up() and e1.low > e0.low
        ):
            return self._reset()
        return False

    def _treat_third(self, idx: int, bi: Bi) -> bool:
        """第三元素: 允许合并 (exclude 关, 第六/八种情况); 相等边界用 allow_top_equal。"""
        e1 = self.ele[1]
        assert e1 is not None
        self.last_evidence = idx
        cd = e1.test_combine(
            bi, exclude_included=False, allow_top_equal=self._top_equal()
        )
        if cd == "combine":
            e1.merge(idx, bi)
            return False
        self.ele[2] = _Eigen.of(self.xianduan_dir, idx, bi)
        if not self._actual_break():
            return self._reset()
        if self._is_fx():
            self._mark_gap()
            return True
        return self._reset()

    def _actual_break(self) -> bool:
        """e2 实际突破判定 (随 ``sequence_role``; §16 v10)。

        - ``GAP_REVERT`` (第二特征序列, 第七/78课): e2 须严格突破**合并后** ``e1.low/e1.high``,
          **无前看** —— 合并元素不退回末原始笔 (避免触平漏判; 详 §16 v10)。
        - ``PRIMARY`` (第一特征序列, 第八种情况): e2 须突破 e1 **末原始笔**; 表面未破则**前看后一笔
          第二笔** (现状不变)。
        """
        e1, e2 = self.ele[1], self.ele[2]
        assert e1 is not None and e2 is not None
        if self.sequence_role is _SeqRole.GAP_REVERT:  # 第二特征序列: 合并值严格判, 无前看
            return e2.low < e1.low if self._is_up() else e2.high > e1.high
        last_e1 = self.bis[e1.idxs[-1]]  # e1 末构成笔 (合并后用末笔极值, 非合并值)
        if self._is_up():
            if e2.low < last_e1.low:
                return True
        elif e2.high > last_e1.high:
            return True
        # 前看: e2 因表面包含未直接突破, 但其笔后第二笔已形成实际突破 (第八种情况)。
        k = e2.idxs[0]
        if k + 2 < len(self.bis):
            e2_bi, ahead = self.bis[k], self.bis[k + 2]
            if self._is_up() and e2_bi.direction is BiDir.DOWN and ahead.low < e2_bi.low:
                self.last_evidence = k + 2  # 前看突破: 依赖到 k+2 笔
                return True
            if (
                not self._is_up()
                and e2_bi.direction is BiDir.UP
                and ahead.high > e2_bi.high
            ):
                self.last_evidence = k + 2
                return True
        return False

    def _is_fx(self) -> bool:
        """顶/底分型 (第67课; **同时校验高低点**防假分型, 第二种情况)。

        顶分型 (上升线段): e0.high < e1.high 且 e2.high ≤ e1.high 且 e2.low < e1.low。
        底分型 (下降线段): e2.high > e1.high 且 e0.low > e1.low 且 e2.low ≥ e1.low。
        """
        e0, e1, e2 = self.ele[0], self.ele[1], self.ele[2]
        assert e0 is not None and e1 is not None and e2 is not None
        if self._is_up():
            return e0.high < e1.high and e2.high <= e1.high and e2.low < e1.low
        return e2.high > e1.high and e0.low > e1.low and e2.low >= e1.low

    def _mark_gap(self) -> None:
        """标记 e1 与 e0 间是否有特征序列缺口 (第67课第一种 vs 第二种情况)。"""
        e0, e1 = self.ele[0], self.ele[1]
        assert e0 is not None and e1 is not None
        if self._is_up():
            e1.gap = e0.high < e1.low  # 上升: e0 顶 低于 e1 底 → 缺口
        else:
            e1.gap = e0.low > e1.high  # 下降: e0 底 高于 e1 顶 → 缺口

    def _reset(self) -> bool:
        """非分型 → 从第二根特征笔起重排滑窗 (再喂入)。"""
        rest = self.lst[1:]
        self.ele = [None, None, None]
        self.lst = []
        for j in rest:
            if self.add(j):
                return True
        return False

    def has_gap(self) -> bool:
        e1 = self.ele[1]
        return bool(e1 and e1.gap)

    def peak_end_bi_idx(self) -> int:
        """线段端点笔下标 = 峰值特征笔的前一笔 (第67课, GetPeakBiIdx 思路)。

        上升线段: e1 内 high 最高的特征笔 (下降笔) 的前一笔 (上升笔) 终点 = 顶 = 线段终点。
        """
        e1 = self.ele[1]
        assert e1 is not None
        if self._is_up():
            p = max(e1.idxs, key=lambda i: self.bis[i].high)
        else:
            p = min(e1.idxs, key=lambda i: self.bis[i].low)
        return p - 1

@dataclass(slots=True)
class _WorkXianduan:
    """构建期线段 + 冻结状态。rule_kind = 候选来源 (feature_seq/gap/forming);
    freeze_state ∈ FROZEN(已冻结实线) / SOFT_N0(准完成软实线) / PENDING_N1(待确认虚线)。"""

    start_bi: int
    end_bi: int
    direction: BiDir
    rule_kind: str
    dep_index: int
    freeze_state: XianduanFreezeState
    pen_break_at: int | None = None  # 笔破坏失败吸收段的内部越点笔下标 (T7; 其它段 None)
    confirmation_ts: int | None = None  # gap_revert 反向确认证据 end_ts (§16 v10)
    frozen_by: str = ""  # 冻结事件来源 ("gap_revert" / "")


class _XianduanBuilder:
    """单次派生的内部状态机 (不跨调用持久)。"""

    def __init__(
        self, bis: list[Bi], *, nonstandard: bool = False, oscillation: bool = False,
        strong_bi: bool = False,
    ) -> None:
        self.bis = bis
        self.xianduans: list[_WorkXianduan] = []
        # 实战变体开关 (严格标准均 False; xianduan-v1 §5 / xianduan-practical-v1 §16)。
        self.nonstandard = nonstandard  # 非标准连续拆分补齐
        self.oscillation = oscillation  # 横向震荡三笔成段 (TODO: 后续实现)
        self.strong_bi = strong_bi  # 强势笔破坏两阶段确认 (单笔破坏 N0 + 反向标准段 N2 确认)
        # 诊断记录 (供图上验收/调试)。
        self.orphan_debug: list[tuple[int, int, str]] = []
        # tail 区间记录 (末端无法成合法 provisional 段的原因)。
        self.tail_debug: list[tuple[int, int, str]] = []

    def run(self) -> list[_WorkXianduan]:
        """N0/N1/N2 动态冻结 pipeline (decision-0028 §3-quater / xianduan-v1 §16 v8):

        ① 定首段方向/起点 (暖机头 B5 锁定) → ② 特征序列内核逐段产生**候选** (不立即冻结) →
        ③ 候选进 N0/N1/N2 状态机: N2 出现且 N1 未被击破 → 冻结 N0; N1 起点被严格击破 → 作废 N1、
        N0 延伸吞击破区、新 N1 从击破笔后第一根反向笔重找 → ④ 输出 frozen(实线)/soft N0(软实线)/
        pending N1(虚线) + 末尾兜底。**confirmed 冻结历史不回改** (回算水位)。

        "候选成立 ≠ confirmed 冻结": 原文(第一/二种)判候选, 状态机判冻结时机。"""
        n = len(self.bis)
        if n < 3:
            return self.xianduans
        first = self._first_xianduan()
        if first is None:
            return self._emit(_XianduanFreezeMachine())  # 无法定向 → 整窗兜底 forming
        begin, d = first
        c0 = self._candidate(begin, d)
        if c0 is None:
            return self._emit(_XianduanFreezeMachine())
        sm = _XianduanFreezeMachine()
        sm.promote_to_n0(c0)  # T1 准完成
        guard = 0
        while guard < 4 * n:  # 防御性上界 (每次推进至少前移一笔)
            guard += 1
            if sm.n1 is None:
                assert sm.n0 is not None
                rev = self._candidate(sm.n0.end_bi + 1, _opposite(sm.n0.direction))
                # N0 方向若在反向候选区内 (或其后) 创新极值 → 先延伸 N0 过子顶/子底 (第五/八种);
                # 否则反向候选 = 真反向段 → pending N1。
                begin = sm.n0.end_bi + 1
                limit = rev.end_bi if rev is not None else len(self.bis) - 1
                ext = self._first_new_extreme(sm.n0, begin, limit)
                ep = (self._extreme_problem(sm.n0.start_bi, ext[0], sm.n0.direction)
                      if ext is not None else None)
                # strong_bi 单笔段**恒不延伸/不吸收** (几何 = 破坏单笔本身, 用户 2026-07-10 Q2);
                # 跳过 N0 延伸与 T7, 直接进反向候选/strong 拆分, 保持单笔不变。
                strong_n0 = sm.n0.rule == "strong_bi"
                # ① 干净延伸 (起点仍是极值) → 延伸 N0 过子顶/子底 (第五/八种)。
                if not strong_n0 and ext is not None and ep is None:
                    sm.n0.end_bi, sm.n0.end_key = ext
                    continue
                # ② T7 笔破坏失败吸收 (decision-0028 §3-quinquies): 反向**未成合法线段**
                #    (rev is None) + 原方向创新极值 (ext) + 延伸区**越过 N0 起点** (ep == "start",
                #    = 失败笔破坏越点) → 把该失败笔破坏吸收进 N0, 延伸到新极值, 标 pen_break_absorb
                #    (允许内部越点, B5 豁免)。**不 break**, driver 继续。
                if not strong_n0 and rev is None and ext is not None and ep == "start":
                    sm.n0.end_bi, sm.n0.end_key = ext
                    sm.n0.rule = "pen_break_absorb"
                    sm.n0.pen_break_at = self._pen_break_bi(sm.n0, begin, ext[0])
                    continue
                if rev is None:
                    break  # 无反向也无延伸 → N0 是末段 (soft), 反向边交兜底
                # ③ strong_bi 两阶段确认 (实战变体; xianduan-practical-v1 §16, 用户 2026-07-10):
                #    N0 之后**首根反向单笔**严格破坏 N0 起点关键极值 (start_key), 且其**紧接**又形成
                #    一条对该单笔的反向标准线段 (N2 = _candidate(single+1, N0向)) → 该单笔登记为
                #    strong_bi 单笔 N1 (不立即冻结); 由标准 N2 裁决 (confirm_on_n2) 两滞后冻结。
                #    N2 未成形 → 不登记 → 回退标准 rev (含 T7 pen_break_absorb 吸收)。
                if self.strong_bi:
                    strong = self._try_strong_bi_break(sm.n0)
                    if strong is not None:
                        sm.set_pending_n1(strong)
                        continue
                sm.set_pending_n1(rev)  # T2 待确认
                continue
            # 有 N0+N1: ① N1 延伸 → ② N2 成功冻结 → ③ N2 失败作废延伸 → ④ 未决 (见 _advance_n0n1)。
            assert sm.n0 is not None
            verdict = self._advance_n0n1(sm)
            if verdict[0] == "break":
                # strong_bi 单笔 N0 **不可延伸** (用户 2026-07-10 Q2): 本会 T4+T5 作废 N1、延伸
                # N0 的情形, 单笔段改走 T6 转接 (冻结单笔 N0、N1 升 soft N0)——单笔既已被反向标准段
                # 确认, 后续再破坏它起点只是走势延续, 不回头改写单笔几何。
                if sm.n0.rule == "strong_bi":
                    if not self._gate_ok(sm.n0):
                        break
                    sm.rollover_n1_to_n0()
                else:
                    sm.invalidate_n1_extend_n0(verdict[1], verdict[2])  # T4+T5 作废+延伸
            elif verdict[0] == "rollover":
                # T6 转接: N1 越过 N0 起点 (真强反向) → 冻结 N0、N1 升 N0。N0 须过冻结硬闸。
                if not self._gate_ok(sm.n0):
                    break
                sm.rollover_n1_to_n0()
            elif verdict[0] == "extend_n1":
                sm.n1.end_bi, sm.n1.end_key = verdict[1], verdict[2]  # N1 延伸 (子顶/子底)
            elif verdict[0] == "confirm":
                if not self._gate_ok(sm.n0):  # 冻结硬闸 (absorb 段豁免 B5, 见 _gate_ok)
                    break
                sm.confirm_on_n2(verdict[1])  # T3 冻结 N0、N1→N0、N2→N1
            elif verdict[0] == "gap_revert":
                # T8 缺口第二种反向确认 (§16 v10): 缺口 N1 经第二特征序列反向分型确认 → 原子冻结
                # N0(前驱)+N1(缺口段)。原子前提: 两段各过硬闸 + 方向相反且连续; 任一不满足则不触发
                # (退回 break, N1 保持 pending)。冻结后 **G-a 链式 seed**: 用同一反向分型 e1 peak 作
                # 下一段(反向)候选终点 → 新 soft N0 (不由同一证据 frozen), 再由标准 pipeline 裁决。
                assert sm.n1 is not None
                evidence_bi, peak_bi = verdict[1], verdict[2]
                if not (self._gate_ok(sm.n0) and self._gate_ok(sm.n1)
                        and sm.n1.direction is _opposite(sm.n0.direction)
                        and sm.n1.start_bi == sm.n0.end_bi + 1):
                    break
                next_begin = sm.n1.end_bi + 1
                next_dir = _opposite(sm.n1.direction)
                sm.confirm_gap_revert(evidence_bi, self.bis[evidence_bi].end_ts)
                # 链式 seed 下一 soft N0 = [next_begin, peak_bi] (peak_bi = 反向分型 e1 极值端点)。
                if (peak_bi - next_begin >= 2 and self.bis[next_begin].direction is next_dir
                        and self.bis[peak_bi].direction is next_dir):
                    sm.promote_to_n0(_XianduanCand(
                        start_bi=next_begin, end_bi=peak_bi, direction=next_dir,
                        start_key=self._start_key(next_begin, next_dir),
                        end_key=self._end_key(peak_bi, next_dir), rule="feature_seq", dep=peak_bi,
                    ))
                    continue
                # seed 端点退化 (不足3笔/端点方向不符) → 无法 seed → 交兜底 forming。
                break
            else:  # "none": 扫到尾未决 → N1 仍 pending (末段)
                break
        return self._emit(sm)

    # ── 候选生成 (特征序列内核; 不做冻结判定) ─────────────────────────────────────

    def _candidate(self, begin: int, xianduan_dir: BiDir) -> _XianduanCand | None:
        """从 begin 起、方向 xianduan_dir, 喂反向笔成特征序列, **首个分型 → 一个候选** (不冻结)。

        候选 = 原文第一种(无缺口)/第二种(有缺口)产生的线段候选; 冻结时机交 N0/N1/N2 状态机。
        返回 _XianduanCand (含 start_key/end_key 供击破判定 + rule/dep 供输出), 无分型 → None。
        """
        n = len(self.bis)
        feat_dir = _opposite(xianduan_dir)
        fx = _EigenFX(xianduan_dir, self.bis)
        i = begin
        while i < n:
            if self.bis[i].direction is feat_dir and fx.add(i):
                end_bi = fx.peak_end_bi_idx()
                # 候选须 ≥3 笔且**端点为段内真极值** (B5 自洽); 否则是子顶/子底 → 重起特征序列
                # 从该分型后继续扫更深分型 (第八种"段内更极值", 直到端点是真极值)。
                if (
                    end_bi - begin >= 2
                    and self._extreme_problem(begin, end_bi, xianduan_dir) is None
                ):
                    dep = fx.last_evidence if fx.last_evidence is not None else end_bi
                    rule = "gap" if fx.has_gap() else "feature_seq"
                    return _XianduanCand(
                        start_bi=begin, end_bi=end_bi, direction=xianduan_dir,
                        start_key=self._start_key(begin, xianduan_dir),
                        end_key=self._end_key(end_bi, xianduan_dir),
                        rule=rule, dep=dep,
                    )
                fx = _EigenFX(xianduan_dir, self.bis)  # 子顶/子底 → 延伸, 从 end_bi+1 重扫
                i = end_bi
            i += 1
        return None

    def _first_new_extreme(
        self, n0: _XianduanCand, begin: int, limit: int
    ) -> tuple[int, float] | None:
        """[begin, limit] 内**首个严格超过 N0 端点极值**的本段方向笔 (上涨首个新高/下跌首个新低)。

        增量延伸: 延伸到首个新极值后由主循环重新找反向; 仅在 N0 方向真创新极值时触发 (合法反向段
        的 highs/lows 不会越过 N0 端点, 故不会误延伸过真反向段)。
        """
        hi = min(limit, len(self.bis) - 1)
        for i in range(begin, hi + 1):
            b = self.bis[i]
            if b.direction is not n0.direction:
                continue
            if n0.direction is BiDir.UP and b.high > n0.end_key:
                return i, b.high
            if n0.direction is BiDir.DOWN and b.low < n0.end_key:
                return i, b.low
        return None

    def _start_key(self, bi: int, d: BiDir) -> float:
        """起点关键价位 (N1 击破判据): 上涨段 = 起点 low / 下跌段 = 起点 high。"""
        return self.bis[bi].low if d is BiDir.UP else self.bis[bi].high

    def _end_key(self, bi: int, d: BiDir) -> float:
        """终点极值: 上涨段 = 终点 high / 下跌段 = 终点 low。"""
        return self.bis[bi].high if d is BiDir.UP else self.bis[bi].low

    def _breaks_start_key(self, n0: _XianduanCand, bi_idx: int) -> bool:
        """单笔 ``bi_idx`` 是否**严格**破坏 N0 起点关键极值 (触平不算; 对齐 ``is_n1_broken``)。

        上涨 N0 (start_key=起点 low): 反向下降笔 ``low < start_key`` → 破;
        下降 N0 (start_key=起点 high): 反向上升笔 ``high > start_key`` → 破。
        """
        b = self.bis[bi_idx]
        if n0.direction is BiDir.UP:
            return b.low < n0.start_key
        return b.high > n0.start_key

    def _try_strong_bi_break(self, prev_seg: _XianduanCand) -> _XianduanCand | None:
        """strong_bi 两阶段确认: 试把 ``prev_seg`` 之后首根反向单笔拆成 strong_bi 单笔段候选。

        ``prev_seg`` = 被破坏的前一段 (在 ``sm.n1 is None`` 处 = 当前 soft N0; 在 ``_advance_n0n1``
        生成 N2 处 = 当前 pending N1)。条件 (全满足才产出, 否则 None → 回退标准候选):
        - 首根反向笔 ``s = prev_seg.end_bi + 1`` 方向与 ``prev_seg`` 反向 (反向单笔);
        - ``s`` **严格破坏** ``prev_seg`` 起点关键极值 (``_breaks_start_key``; 强势破坏, 触平不算);
        - **阶段2 前置**: 紧接 ``s`` 之后形成一条对该单笔的**反向标准线段** =
          ``_candidate(s+1, prev_seg.direction)`` 且其起点 == ``s+1`` (连续)。该反向标准段是标准
          确认证据; 单笔本身由状态机 ``confirm_on_n2`` 两滞后冻结, **不立即确认**; 反向标准段
          不成形则返回 None (回退 → 单笔不自成段, 走 T7 吸收 / 标准流程)。

        返回 strong_bi 单笔候选 (start==end==s, 方向 = prev_seg 反向, rule="strong_bi"); dep 取反向
        标准段依赖水位。cutoff 安全: 反向标准段未到齐时 ``_candidate`` 返回 None → 不产出。
        """
        s = prev_seg.end_bi + 1
        if s >= len(self.bis):
            return None
        d = _opposite(prev_seg.direction)
        if self.bis[s].direction is not d:  # 首根须是反向单笔
            return None
        if not self._breaks_start_key(prev_seg, s):  # 须强势破坏 prev_seg 起点关键极值
            return None
        rev_std = self._candidate(s + 1, prev_seg.direction)  # 阶段2 前置: 紧接反向标准线段
        if rev_std is None or rev_std.start_bi != s + 1:
            return None
        return _XianduanCand(
            start_bi=s, end_bi=s, direction=d,
            start_key=self._start_key(s, d), end_key=self._end_key(s, d),
            rule="strong_bi", dep=rev_std.dep,
        )

    def _revert_confirm(self, seg_dir: BiDir, peak_end_bi: int) -> tuple[int, int] | None:
        """缺口第二种反向确认 (第67课第二种 / §16 v10)。

        从 ``peak_end_bi+2`` 起, 在**反向方向**建第二特征序列 (``_SeqRole.GAP_REVERT``, 合并值判
        分型、无前看); **首个**反向分型 → 返回 ``(evidence_bi, peak_bi)``:
        - ``evidence_bi`` = 反向分型 ``last_evidence`` 笔下标 (证据水位);
        - ``peak_bi`` = 反向序列 ``peak_end_bi_idx()`` = 第二特征序列**中间元素 e1 极值端点** → 用作
          gap_revert **链式 seed 的下一段 (反向 seg_dir) 候选终点** (G-a; 用户 2026-07-09)。
        扫到尾无分型 → None。**不递归**: 第二特征序列自身即使有缺口, 只要形成分型即确认 (原文第67课:
        第二个序列的分型不分第一/二种情况)。方向: 反向序列方向 = ``peak_end_bi+2`` 笔方向的反向
        (镜像 chan ``find_revert_fx``: ``revert_bi_dir(bi_list[begin].dir)``)。
        """
        begin = peak_end_bi + 2
        n = len(self.bis)
        if begin >= n:
            return None
        rev_dir = _opposite(seg_dir)  # 反向序列线段方向 = 被确认段(seg_dir)的反向 = 下一段方向
        if self.bis[begin].direction is not seg_dir:
            return None  # 守护: peak+2 笔方向应与被确认段同向 (镜像 chan); 否则数据退化
        fx = _EigenFX(rev_dir, self.bis, sequence_role=_SeqRole.GAP_REVERT)
        i = begin
        while i < n:
            if self.bis[i].direction is seg_dir and fx.add(i):  # 只喂 seg_dir 笔 (rev 序列的反向笔)
                ev = fx.last_evidence if fx.last_evidence is not None else i
                return ev, fx.peak_end_bi_idx()  # 证据笔 + e1 peak (下一段候选终点)
            i += 1
        return None

    def _second_sequence_elements(self, seg_dir: BiDir, peak_end_bi: int) -> list[_Eigen]:
        """只读显示辅助 (xianduan-v1 §16 v10 显示层「第二特征序列」, 用户 2026-07-10 Commit C)。

        复现 ``_revert_confirm`` 同一驱动 (同一 ``_EigenFX`` 类 + ``GAP_REVERT`` 规则 + 同一喂入
        循环), 返回其累积的特征元素 —— **与算法确认逻辑同源, 不重新实现合并规则**（根因：显示层
        此前用另一套简化规则模拟"第二序列", 与算法真实判分型逻辑语义不一致, 曾致 bi416-424 排查
        反复误判, 详模块 banner「三类显示单元」）。

        分型形成后即停 (定格 e0/e1/e2, 与 ``_revert_confirm`` 返回时刻一致); 扫到尾未形成分型时
        返回当前累积的部分元素 (调试可见"正在生长")。独立 ``_EigenFX`` 实例, 不与 ``_revert_
        confirm`` 共享可变状态、不影响其行为。
        """
        begin = peak_end_bi + 2
        n = len(self.bis)
        if begin >= n or self.bis[begin].direction is not seg_dir:
            return []
        rev_dir = _opposite(seg_dir)
        fx = _EigenFX(rev_dir, self.bis, sequence_role=_SeqRole.GAP_REVERT)
        i = begin
        while i < n:
            if self.bis[i].direction is seg_dir and fx.add(i):
                break
            i += 1
        return [e for e in fx.ele if e is not None]

    # ── N2 出现 vs N1 击破 (先到先判) ─────────────────────────────────────────────

    def _advance_n0n1(self, sm: _XianduanFreezeMachine) -> tuple:
        """有 N0+N1 时推进一步, 返回 verdict (顺序: N1 延伸 → N2 成败裁决 → 未决):

        核心裁决 (用户 2026-06-26): **「N1 起点被击破」≠「N1 立即失败」**。击破笔本就是 N2 的起点
        (N2 与 N0 同向、与 N1 反向, 天然越过 N1 起点)。故击破后**先给 N2 成长机会**:
        - N2 = `_candidate(N1.end+1, N0向)` **非 None** (起点即段内极值且 B5 自洽) → **N2 成功**:
          N1 成立, N0 冻结 (`confirm`)。`_candidate` 起点极值自检 = 「N2 连续成长」判据, 不会远跳。
        - N2 **为 None** (起点被反向越过, 价格反转回 N1 向) 且 N1 起点确被严格击破 → **N2 失败**
          (第五种假反向): 作废 N1, N0 延伸到击破后同向真实极值 (`break`)。
        - N2 为 None 且无明确击破 → 未决 (`none`): 保持 N0 soft + N1 pending, **不提前冻结**。

        verdict: ('extend_n1',end,key) / ('confirm',n2) / ('break',end,key) / ('none',)。
        """
        assert sm.n0 is not None and sm.n1 is not None
        n0dir = sm.n0.direction
        n1 = sm.n1
        n = len(self.bis)
        begin = n1.end_bi + 1
        n2 = self._candidate(begin, n0dir)
        # ① N1 子顶/子底延伸 (B5 守护): N1 创新极值且 [起点,新极值] 仍 B5 自洽 (起点未被破) → 延伸
        #    (第八种段内更极值)。先于裁决, 让 N1 长到真极值再判确认。
        #    strong_bi 单笔段**恒不延伸** (单笔段几何 = 破坏单笔本身, 用户 2026-07-10 Q2)。
        limit = n2.end_bi if n2 is not None else n - 1
        if n1.rule != "strong_bi":
            ext = self._first_new_extreme(n1, begin, limit)
            if ext is not None and self._extreme_problem(n1.start_bi, ext[0], n1.direction) is None:
                return ("extend_n1", ext[0], ext[1])
        # 击破/反转证据 (两类 N1 共用; 供确认 vs 失效的 evidence index 先后裁决)。
        brk = self._first_break(n1, begin, n - 1)
        rev = self._first_new_extreme(n1, begin, n - 1)  # 反向回 N1 向的极值 = 失效证据
        # ② 确认裁决 (用户 2026-07-09 最终口径, 见 §16 v10):
        #    缺口第二种情况本质 = **缺口段不得在无反向结构证据时确认**。反向结构证据分两级:
        #      · **完整反向线段 N2** (更强证据, 内含反向特征序列分型背书);
        #      · **裸反向特征序列分型 gap_revert** (末端/cutoff N2 未形成、但反向分型已完成的卡住)。
        #    中段历史数据: 后续已形成完整 N2 → 仍按 N2/两滞后状态机确认缺口段, **保持现有稳定分段**;
        #    **不因裸分型更早出现就强行改用 atomic gap_revert** (atomic 在触平边界与两滞后发散、噪声
        #    数据会崩塌)。末端无 N2 但裸分型已完成 → 落 ④ gap_revert 补全。
        #    "N2 确认非绕过第二种": N2 ⊃ 裸反向分型 (完整反向段必含反向分型背书); 全 frozen 缺口段有
        #    第二序列背书由 test_all_frozen_gap_segments_have_second_sequence_backing 硬证。
        #    strong_bi 变体 (xianduan-practical-v1 §16, 用户 2026-07-10): 即将确认 N1 时, 若 N1
        #    之后首根笔是**强势破坏 N1 起点的反向单笔**且其后紧接反向标准段 → 用 strong_bi 单笔段作
        #    N2 (把 N1 之后本会长成的标准反向段细化为「单笔 strong 段 + 反向标准段」; 单笔破坏可级联
        #    ——单笔成不了标准段, 故**不要求** standard n2 存在, 只需反向标准段前置)。仅 strong_bi
        #    开; 严格 standard 不触发 → golden 零回归。单笔由后续 confirm_on_n2 两滞后冻结。
        if self.strong_bi:
            strong = self._try_strong_bi_break(n1)
            if strong is not None:
                return ("confirm", strong)
        if n2 is not None:
            return ("confirm", n2)
        # ③ 确认未成 + **双证据**击破 (实时生长防误判, 用户 2026-06-26): ① N1 起点被严格击破 +
        #    ② 后续已反向走回 N1 方向 (创越 N1 终点极值)。仅有击破不够 (刚击破时确认序列仍在生长)。
        if brk is not None and rev is not None:
            new_end, new_key = self._extend_extreme(sm.n0, rev[0])  # N0 延伸到反转点前真实极值
            # 守护: 延伸后 N0 仍须 B5 自洽。若 N1 已**越过 N0 起点** (上涨 N0 段内现更低 low / 下跌
            # 现更高 high) → 延伸会造 B5 反画。此时 N1 是真强反向、N0 已完结 → T6 转接 (冻结 N0,
            # N1 升 N0), 不作废 N1。否则 N1 是假反向 (第五种) → T4+T5 作废+延伸。
            if self._extreme_problem(sm.n0.start_bi, new_end, sm.n0.direction) is not None:
                return ("rollover",)
            return ("break", new_end, new_key)
        # ④ 缺口第二种反向确认 (§16 v10, **末端卡住缺口段兜底**): N2 未成形 + 无 break/rollover 时,
        #    缺口候选从 peak+2 起第二特征序列 (GAP_REVERT 合并值) 出反向分型 → gap_revert 原子冻结
        #    N0+N1 + G-a 链式 seed。仅救 N2 不成形而卡 pending 的末端缺口段 (锚点 bi416-424)。
        if n1.rule == "gap":
            rc = self._revert_confirm(n1.direction, n1.end_bi)
            if rc is not None and (brk is None or rc[0] <= brk):
                return ("gap_revert", rc[0], rc[1])
        # ⑤ 未决 (确认序列仍在生长 / 无击破): N0 soft + N1 pending, 等后续数据生长。
        return ("none",)

    def _first_break(self, n1: _XianduanCand, begin: int, limit: int) -> int | None:
        """[begin, limit] 内**严格击破** N1 起点关键价位的首笔下标 (触平不算; None=未破)。

        上涨 N1: 后续笔 low < 起点 low → 破; 下跌 N1: 后续笔 high > 起点 high → 破。
        """
        up = n1.direction is BiDir.UP
        for i in range(begin, min(limit, len(self.bis) - 1) + 1):
            b = self.bis[i]
            if (up and b.low < n1.start_key) or (not up and b.high > n1.start_key):
                return i
        return None

    def _extend_extreme(self, n0: _XianduanCand, limit: int) -> tuple[int, float]:
        """N0 延伸目标 = [N0.end, limit] 内本段方向真极值笔 (下跌取最低 low / 上涨取最高 high)。

        N1 作废后 N0 吞掉假反弹+击破区到新极值; 终点取本段方向笔, 保证延伸后端点仍为方向极值。
        """
        lo, hi = n0.end_bi, min(limit, len(self.bis) - 1)
        rng = [i for i in range(lo, hi + 1) if self.bis[i].direction is n0.direction]
        if not rng:
            rng = list(range(lo, hi + 1))
        if n0.direction is BiDir.DOWN:
            e = min(rng, key=lambda i: self.bis[i].low)
            return e, self.bis[e].low
        e = max(rng, key=lambda i: self.bis[i].high)
        return e, self.bis[e].high

    def _gate_ok(self, n0: _XianduanCand) -> bool:
        """冻结硬闸: 标准段须过 `_basic_valid` (≥3笔/奇数/首尾同向/首三笔重合) **且** B5 端点极值;
        `pen_break_absorb` 段 (T7 笔破坏失败吸收) **豁免 B5**, 只查 `_basic_valid`。"""
        if n0.rule == "strong_bi":
            # 单笔 strong_bi 段 (实战变体, 用户确认非原文≥3; xianduan-practical-v1 §16): 豁免
            # B1/B3 (≥3/单数) 与 B2 (首三重合) 与 B5 —— 只需是那根反向破坏单笔 (start==end, 方向
            # 正确)。破坏 N0 起点 + 反向 N2 前置已在 _try_strong_bi_n1 校验。
            return (n0.start_bi == n0.end_bi
                    and self.bis[n0.start_bi].direction is n0.direction)
        if not self._basic_valid(n0.start_bi, n0.end_bi, n0.direction):
            return False
        if n0.rule == "pen_break_absorb":  # 吸收段允许内部越点, B5 不作硬闸
            return True
        return self._extreme_problem(n0.start_bi, n0.end_bi, n0.direction) is None

    def _pen_break_bi(self, n0: _XianduanCand, begin: int, end: int) -> int:
        """吸收段内部**越过 N0 起点**最极端的笔下标 (失败笔破坏点; 上取最低/下取最高)。"""
        up = n0.direction is BiDir.UP
        best_i, best_v = begin, None
        for i in range(begin, end + 1):
            b = self.bis[i]
            v = b.low if up else b.high
            broke = (v < n0.start_key) if up else (v > n0.start_key)
            if broke and (best_v is None or (v < best_v if up else v > best_v)):
                best_i, best_v = i, v
        return best_i

    # ── 首段定向 (暖机头 B5 锁定; 候选制) ────────────────────────────────────────

    def _first_xianduan(self) -> tuple[int, BiDir] | None:
        """首段起点+方向: 跳过暖机头, 取**首个能成 (合法候选 + 合法反向候选) 对**的起点。

        暖机头常有单笔强势/方向不定 (第五种"中间地带"), 无法成稳定链 → 右移起点直到一个段及其
        反向段都成合法候选 (链能继续生长)。其前的暖机笔留空 (用户允许)。返回 (begin, dir) 或 None。
        """
        n = len(self.bis)
        for begin in range(n):
            d = self.bis[begin].direction
            c = self._candidate(begin, d)
            if c is None:
                continue
            rev = self._candidate(c.end_bi + 1, _opposite(d))
            if rev is not None:
                return begin, d
        return None

    def _basic_valid(self, start: int, end: int, xianduan_dir: BiDir) -> bool:
        """基础硬约束 (第77课): ≥3 笔 (B1) + 含笔数单数 (B3) + 首尾同向 + 首三笔重合 (B2)。"""
        cnt = end - start + 1
        if cnt < 3 or cnt % 2 == 0:
            return False
        if (
            self.bis[start].direction is not xianduan_dir
            or self.bis[end].direction is not xianduan_dir
        ):
            return False
        three = self.bis[start : start + 3]
        return max(b.low for b in three) <= min(b.high for b in three)

    def _extreme_problem(self, start: int, end: int, xianduan_dir: BiDir) -> str | None:
        """端点极值校验 (第77课 B5 / 第八种情况): 上升线段段内不得有低于起点的 low、终点须为
        段内最高; 下降线段段内不得有高于起点的 high、终点须为段内最低。

        返回 ``"start"`` (起点不是段内极值) / ``"end"`` (终点不是段内极值) / ``None`` (合法)。
        """
        xianduan = self.bis[start : end + 1]
        if xianduan_dir is BiDir.UP:
            if any(b.low < self.bis[start].low for b in xianduan):
                return "start"  # 段内有更低 low → 起点不是真底
            if any(b.high > self.bis[end].high for b in xianduan):
                return "end"  # 段内有更高 high → 终点不是真顶
        else:
            if any(b.high > self.bis[start].high for b in xianduan):
                return "start"
            if any(b.low < self.bis[end].low for b in xianduan):
                return "end"
        return None

    # ── 输出: frozen(实线) / soft N0(软实线) / pending N1(虚线) + 末尾兜底 (方案 A) ──

    def _emit(self, sm: _XianduanFreezeMachine) -> list[_WorkXianduan]:
        """状态机 → _WorkXianduan 列表 (方案 A 显示口径)。

        frozen → FROZEN(实线 confirmed); soft N0 → SOFT_N0(软实线, 未冻结); pending N1 →
        PENDING_N1(虚线)。无 N1 时 N0 之后的反向边出一条 forming 虚线 (终点取该向极值笔)。
        连续性: 各段起点恒 = 上段 end+1, 无内部 gap; 左侧暖机头允许留空。
        """
        n = len(self.bis)
        out: list[_WorkXianduan] = []
        for fz in sm.frozen:
            out.append(_WorkXianduan(fz.start_bi, fz.end_bi, fz.direction, fz.rule, fz.dep,
                                XianduanFreezeState.FROZEN, pen_break_at=fz.pen_break_at,
                                confirmation_ts=fz.confirmation_ts, frozen_by=fz.frozen_by))
        if sm.n0 is not None:
            out.append(_WorkXianduan(
                sm.n0.start_bi, sm.n0.end_bi, sm.n0.direction, sm.n0.rule,
                sm.n0.dep, XianduanFreezeState.SOFT_N0, pen_break_at=sm.n0.pen_break_at,
            ))
        if sm.n1 is not None:
            # pending N1 (唯一右缘 forming): 终点延伸到该向**最新极值** (覆盖到右缘附近, driver 在
            # 震荡区提前停时不留大段空白; 仍是单条 forming 虚线, 满足"最右最多一条 forming")。
            fe = self._forming_end(sm.n1.start_bi, sm.n1.direction)
            n1_end = max(sm.n1.end_bi, fe)
            out.append(_WorkXianduan(
                sm.n1.start_bi, n1_end, sm.n1.direction, "forming",
                sm.n1.dep, XianduanFreezeState.PENDING_N1,
            ))
        elif sm.n0 is not None and sm.n0.end_bi + 1 < n:  # 无 N1 → N0 之后反向边一条 forming 虚线
            start = sm.n0.end_bi + 1  # N0 收在末笔时无尾段可画 (start < n 守护)
            d = _opposite(sm.n0.direction)
            end = self._forming_end(start, d)
            if end >= start:
                out.append(_WorkXianduan(
                    start, end, d, "forming", n - 1, XianduanFreezeState.PENDING_N1
                ))
        elif sm.n0 is None and sm.n1 is None and sm.frozen and sm.frozen[-1].end_bi + 1 < n:
            # gap_revert 后无新 N0 候选 (末段反向段尚未成候选) → 从最后 frozen 段后画一条 forming
            # (反向方向), 保证连续覆盖到末笔、右缘不留空档。
            start = sm.frozen[-1].end_bi + 1
            d = _opposite(sm.frozen[-1].direction)
            end = self._forming_end(start, d)
            if end >= start:
                out.append(_WorkXianduan(
                    start, end, d, "forming", n - 1, XianduanFreezeState.PENDING_N1
                ))
        if not out and n >= 1:  # 完全无法定向 → 整窗一条 forming
            d = self.bis[0].direction
            end = self._forming_end(0, d)
            out.append(_WorkXianduan(0, end, d, "forming", n - 1, XianduanFreezeState.PENDING_N1))
        return out

    def _forming_end(self, start: int, xianduan_dir: BiDir) -> int:
        """forming 末段终点笔 = 暂定极值的**同向笔** (上涨段取最高 high 的上涨笔 / 下跌段取最低
        low 的下跌笔)。保证 forming 终点落在本段方向的极值上 (用户 2026-06-21), 而非末笔。"""
        same = [i for i in range(start, len(self.bis)) if self.bis[i].direction is xianduan_dir]
        if not same:
            return start  # 无同向笔 (退化) → 起点自身
        if xianduan_dir is BiDir.UP:
            return max(same, key=lambda i: self.bis[i].high)
        return min(same, key=lambda i: self.bis[i].low)


# ── _WorkXianduan → Xianduan (含轻量 trace, source/merged_range 从构成笔聚合) ──────────────

_RULE_FSEQ = {BiDir.UP: RULE_XIANDUAN_UP_FSEQ, BiDir.DOWN: RULE_XIANDUAN_DOWN_FSEQ}
_RULE_GAP = {BiDir.UP: RULE_XIANDUAN_UP_GAP, BiDir.DOWN: RULE_XIANDUAN_DOWN_GAP}
_RULE_TAIL = {BiDir.UP: RULE_XIANDUAN_UP_TAIL, BiDir.DOWN: RULE_XIANDUAN_DOWN_TAIL}
_RULE_EXTREME_SPLIT = {
    BiDir.UP: RULE_XIANDUAN_UP_EXTREME_SPLIT, BiDir.DOWN: RULE_XIANDUAN_DOWN_EXTREME_SPLIT
}
_RULE_NONSTANDARD_REPAIR = {
    BiDir.UP: RULE_XIANDUAN_UP_NONSTANDARD_REPAIR, BiDir.DOWN: RULE_XIANDUAN_DOWN_NONSTANDARD_REPAIR

_RULE_MAP = {
    "gap": _RULE_GAP,
    "tail": _RULE_TAIL,
    "extreme_split": _RULE_EXTREME_SPLIT,

    },

        BiDir.UP: RULE_XIANDUAN_UP_STRONG_BI_BREAK, BiDir.DOWN: RULE_XIANDUAN_DOWN_STRONG_BI_BREAK
    },
}


def _rule_for(direction: BiDir, rule_kind: str) -> str:
    return _RULE_MAP.get(rule_kind, _RULE_FSEQ)[direction]


def _finish(
    bis: list[Bi], work: list[_WorkXianduan], *, profile_id: str, config_hash: str
) -> list[Xianduan]:
    out: list[Xianduan] = []
    for w in work:
        first, last = bis[w.start_bi], bis[w.end_bi]
        members = bis[w.start_bi : w.end_bi + 1]
        high = max(b.high for b in members)
        low = min(b.low for b in members)
        # source/merged_range 从构成笔 trace 聚合 (§1.7); 端点笔无 trace 时回退端点 ts。
        src_from = _src_from(first)
        src_to = _src_to(last)
        merged_from = first.trace.merged_from_index if first.trace else None
        merged_to = last.trace.merged_to_index if last.trace else None
        trace = StructTrace(
            algo_card_id=_ALGO_CARD_ID,
            rule_id=_rule_for(w.direction, w.rule_kind),
            profile_id=profile_id,
            config_hash=config_hash,
            source_from_ts=src_from,
            source_to_ts=src_to,
            merged_from_index=merged_from,
            merged_to_index=merged_to,
            dep_to_index=w.dep_index,
            freeze_state=w.freeze_state.value,
            pen_break_at=w.pen_break_at,
            confirmation_ts=w.confirmation_ts,
            frozen_by=w.frozen_by,
        )
        out.append(
            Xianduan(
                period=first.period,
                direction=w.direction,
                start_ts=first.start_ts,
                end_ts=last.end_ts,
                start_price=first.start_price,
                end_price=last.end_price,
                high=high,
                low=low,
                trace=trace,
            )
        )
    return out


def _src_from(bi: Bi) -> int:
    if bi.trace and bi.trace.source_from_ts is not None:
        return bi.trace.source_from_ts
    return bi.start_ts


def _src_to(bi: Bi) -> int:
    if bi.trace and bi.trace.source_to_ts is not None:
        return bi.trace.source_to_ts
    return bi.end_ts

# 特征序列显示层 (只读调试; 纯显示, 不进算法口径 / config_hash / 信号 / 回测)
# ──────────────────────────────────────────────────────────────────────────────
# UI「显示特征序列」用: 复用线段特征序列内核 (_Eigen / _XianduanBuilder) 只读产出每个线段的特征
# 元素, 供前端画矩形框。**不改 build_xianduans 输出语义 / 不改 get_xianduans 结构结果** —— 只重跑
# 同一 _XianduanBuilder 拿各段笔下标区间, 再对每段按第65课包含处理把反向笔合并成特征元素。
#
# 语义 (第65/67课, xianduan-v1 §6): 特征序列 = 线段的**反向笔**当特征 K 线 —— 上涨线段看**下降**
# 特征序列、下降线段看**上涨**特征序列 (feature_direction = 线段方向的反向)。这是「特征序列」原
# 定义, **不是新线段口径**; UI 名仍叫「特征序列」, 不引入新 profile / 不动 chan JSON。
#
# **三类显示单元 (xianduan-v1 §16 v10 显示层根因修复, 用户 2026-07-10 Commit C)**: 早期把「第二
# 特征序列」与「tail 同向临时探测」都叫 ttz、语义混用, 曾导致排查时把 tail 滑动编号误读为"有效
# 反向分型"。现彻底分名、三类互不复用前缀:
# - ``PRIMARY``    tz{n}: 每段(含当下未完成段)的**反向笔**特征序列 (第65/67课标准定义), 编号跨
#                  完整序列连续稳定。
# - ``SECOND``     ttz{n}: **缺口第二种反向确认用的第二特征序列**, 与算法 `_revert_confirm` 同源
#                  (复用同一 `_EigenFX(GAP_REVERT)` 驱动, 非重新实现合并规则) —— 只对 frozen 且
#                  `rule_kind=="gap"` 的段产出 (即 `test_all_frozen_gap_segments_have_second_
#                  sequence_backing` 保证非空的段)。编号**每个缺口事件局部从 0 起**(ttz0=e0/
#                  ttz1=e1/ttz2=e2), 多个缺口事件的 ttz0/1/2 会重复出现——用 id (ts 派生) 区分,
#                  不靠编号唯一 (对齐 tz/tp 的"id 稳定、编号仅显示便利"惯例)。
# - ``TAIL_PROBE`` tp{n}: 右缘尚未画出线段虚线的**同向笔**临时探测 (归属假想的下一段), 仅调试、
#                  不参与任何确认判定; 画出虚线后本轮作废重算 (不稳定)。**不再叫 ttz**, 与第二
#                  特征序列彻底分开、避免重蹈两者语义混用的根因。
# ══════════════════════════════════════════════════════════════════════════════


class FeatureSeqKind(StrEnum):
    """特征序列显示单元类别 (纯显示, 不进算法/hash; 见上方模块banner「三类显示单元」)。"""

    PRIMARY = "primary"        # tz: 每段标准反向特征序列
    SECOND = "second"          # ttz: 缺口第二种第二特征序列 (与 _revert_confirm 同源)
    TAIL_PROBE = "tail_probe"  # tp: 右缘同向笔临时探测 (原误称 ttz, 已分名)


@dataclass(frozen=True, slots=True)
class FeatureSeqUnit:
    """单个特征元素 (经包含合并) 的只读显示单元 —— 一个矩形框。

    ``direction``          所属线段方向 (上涨段 / 下降段)。
    ``feature_direction``  特征元素的笔方向 (= 线段方向的反向; 上涨段看下降特征、下降段看上涨特征)。
    ``start_bi_index/end_bi_index``  该特征元素合并所含的首/末笔下标 (完整笔序列中的位置)。
    ``start_ts/end_ts``    首笔起点 ts / 末笔终点 ts (矩形横跨, 绘图点)。
    ``source_from_ts/source_to_ts``  构成笔实际依据的原始 K 线 ts 跨度 (从构成笔 trace 聚合, 同
                           线段/笔): 供 D4-A valid 整体落入判定 (来源跨左缘暖机区的框不画, 不能用
                           绘图点保守回退 —— 特征序列是笔/线段派生的结构化项, 非合并 K 线原始框)。
    ``high/low``           特征元素 (合并后) 的高/低 (矩形纵跨)。
    ``global_index``       序内生成顺序编号: ``PRIMARY`` 跨完整序列连续稳定 → tz{n}; ``SECOND``
                           每个缺口事件局部从 0 起 → ttz{n} (id 才是跨事件唯一锚); ``TAIL_PROBE``
                           自成一套局部计数 → tp{n} (不稳定, 后续可作废重排)。
    ``kind``               三类之一, 见 ``FeatureSeqKind`` (模块 banner「三类显示单元」)。
    """

    direction: BiDir
    feature_direction: BiDir
    start_bi_index: int
    end_bi_index: int
    start_ts: int
    end_ts: int
    high: float
    low: float
    source_from_ts: int
    source_to_ts: int
    global_index: int
    kind: FeatureSeqKind = FeatureSeqKind.PRIMARY


def _feature_elements(
    bis: list[Bi], start_bi: int, end_bi: int, seg_dir: BiDir, feat_dir: BiDir
) -> list[_Eigen]:
    """段内特征序列的特征元素 (标准包含处理, 复用 ``_Eigen``; 只读, 不参与冻结判定)。

    只取段内**反向笔** (``feat_dir``) 当特征 K 线, 按第65课包含处理顺序合并: 相互包含即合并
    (``combine``), 非包含处成新元素分界。合并取值随**线段方向** (上升取高高 / 下降取低低, 与
    ``_EigenFX`` 一致)。相比 ``_EigenFX`` 只保留标准三元素分型窗口的差别: 这里为展示遍历整段所有
    反向笔, 不做 exclude / 前看 / 分型判定 —— 显示的是「特征序列」本身, 非线段确认逻辑。
    """
    elements: list[_Eigen] = []
    cur: _Eigen | None = None
    for i in range(start_bi, end_bi + 1):
        if bis[i].direction is not feat_dir:
            continue
        if cur is None:
            cur = _Eigen.of(seg_dir, i, bis[i])
            continue
        if cur.test_combine(bis[i], exclude_included=False, allow_top_equal=None) == "combine":
            cur.merge(i, bis[i])
        else:
            elements.append(cur)
            cur = _Eigen.of(seg_dir, i, bis[i])
    if cur is not None:
        elements.append(cur)
    return elements


def build_feature_sequence_overlays(bis: list[Bi], cfg: ChanConfig) -> list[FeatureSeqUnit]:
    """只读调试: 每条线段(含当下未完成段)+右缘未画段区的特征序列元素 (供前端画框); 稳定全局编号。

    与 ``build_xianduans`` 共用同一 ``_XianduanBuilder`` (同 cfg → 同分段), 故特征序列与图上显示
    的线段严格对应。覆盖三类区域 (用户 2026-07-08), 产三种单元 (``FeatureSeqKind``, 模块 banner
    「三类显示单元」):
    - ``PRIMARY`` (tz): 已完成 (frozen) 线段内 + 当下未完成线段 (soft_n0/pending_n1/forming) 的
      段内反向笔特征序列; 最后一个 work item 延伸到 ``len(bis)-1`` 覆盖右缘 tail。
    - ``SECOND`` (ttz): frozen 且 ``rule_kind=="gap"`` 的段, 与 ``_revert_confirm`` 同源产出的
      第二特征序列 (每缺口事件局部编号 0 起)。
    - ``TAIL_PROBE`` (tp): 没有画线段虚线的当下 (最后一个 work item 之后到最新笔) 的**同向笔**
      临时探测。左侧暖机头(首个 work item 之前)无段, 不显示(非"当下")。

    ``global_index``: ``PRIMARY`` 按 (线段顺序, 段内特征元素顺序) 基于**完整** engine 笔序列连续
    赋值, 调用方随后窗口裁剪只影响返回哪些框、不重排编号 (对齐 ``attach_bi_labels`` 纪律);
    ``SECOND``/``TAIL_PROBE`` 各自局部计数 (见 ``FeatureSeqUnit.global_index`` 字段说明)。

    cutoff / 回放下天然安全: ``bis`` 只含 ``<= cutoff_ts`` 的 K 线派生结果, 不偷看未来。
    """
    if len(bis) < 3:
        return []
    cfg = cfg.normalize()
    builder = _XianduanBuilder(
        bis,
        nonstandard=cfg.xianduan_nonstandard_policy is XianduanNonstandardPolicy.REPAIR,
        oscillation=cfg.xianduan_oscillation_policy is XianduanOscillationPolicy.THREE_BI,
    )
    work = builder.run()
    n = len(bis)
    out: list[FeatureSeqUnit] = []
    gi = 0
    last_wi = len(work) - 1
    for wi, w in enumerate(work):
        feat_dir = _opposite(w.direction)
        # 最后一段延伸到最新笔: 覆盖当下未画线段虚线的 tail (正在生长的反向特征序列 tz)。
        span_end = n - 1 if wi == last_wi else w.end_bi
        for e in _feature_elements(bis, w.start_bi, span_end, w.direction, feat_dir):
            first_bi, last_bi = bis[e.idxs[0]], bis[e.idxs[-1]]
            out.append(
                FeatureSeqUnit(
                    direction=w.direction,
                    feature_direction=feat_dir,
                    start_bi_index=e.idxs[0],
                    end_bi_index=e.idxs[-1],
                    start_ts=first_bi.start_ts,
                    end_ts=last_bi.end_ts,
                    source_from_ts=_src_from(first_bi),
                    source_to_ts=_src_to(last_bi),
                    high=e.high,
                    low=e.low,
                    global_index=gi,
                    kind=FeatureSeqKind.PRIMARY,
                )
            )
            gi += 1
        # 第二特征序列 ttz (§16 v10, 用户 2026-07-10): 只对 frozen 且 rule_kind=="gap" 的段产出
        # (test_all_frozen_gap_segments_have_second_sequence_backing 保证非空), 与 _revert_confirm
        # 同一 _EigenFX(GAP_REVERT) 驱动同源。每缺口事件局部编号 0 起 (跨事件用 id 区分, 不靠编号)。
        if w.freeze_state is XianduanFreezeState.FROZEN and w.rule_kind == "gap":
            for si, e in enumerate(builder._second_sequence_elements(w.direction, w.end_bi)):
                first_bi, last_bi = bis[e.idxs[0]], bis[e.idxs[-1]]
                out.append(
                    FeatureSeqUnit(
                        direction=_opposite(w.direction),  # 第二序列方向 = 下一段方向 (反向)
                        feature_direction=w.direction,  # 特征元素笔方向 = 被确认段方向 (seg_dir)
                        start_bi_index=e.idxs[0],
                        end_bi_index=e.idxs[-1],
                        start_ts=first_bi.start_ts,
                        end_ts=last_bi.end_ts,
                        source_from_ts=_src_from(first_bi),
                        source_to_ts=_src_to(last_bi),
                        high=e.high,
                        low=e.low,
                        global_index=si,
                        kind=FeatureSeqKind.SECOND,
                    )
                )
    # tail-probe (原误称 ttz, 已按 §16 v10 分名, 用户 2026-07-08/2026-07-10): 未画线段虚线的
    # tail —— 从当前 (末) 段虚线终点的下一笔起, 额外画**同向笔**临时序列 (归属假想的下一段)。
    # 仅调试、不参与任何确认判定; 自成一套 tp{n} 计数, 一旦后续画出虚线定型即作废重算 (不保稳定)。
    if work:
        last = work[-1]
        tail_start = last.end_bi + 1
        if tail_start <= n - 1:
            d = last.direction  # 同向 d (反向 tz 用 opposite(d))
            ti = 0
            for e in _feature_elements(bis, tail_start, n - 1, _opposite(d), d):
                first_bi, last_bi = bis[e.idxs[0]], bis[e.idxs[-1]]
                out.append(
                    FeatureSeqUnit(
                        direction=_opposite(d),  # 假想下一段方向
                        feature_direction=d,  # 特征元素笔方向 = 同向 d → 取 d 的 K 线涨跌色
                        start_bi_index=e.idxs[0],
                        end_bi_index=e.idxs[-1],
                        start_ts=first_bi.start_ts,
                        end_ts=last_bi.end_ts,
                        source_from_ts=_src_from(first_bi),
                        source_to_ts=_src_to(last_bi),
                        high=e.high,
                        low=e.low,
                        global_index=ti,
                        kind=FeatureSeqKind.TAIL_PROBE,
                    )
                )
                ti += 1
    return out
